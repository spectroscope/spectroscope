Chapter 12The tool belt

Thirty-nine built-in tools in a session of the app without MCP servers and skills (the table “Who gets which tools” below), plus one dynamic adapter per connected MCP tool. Every tool obeys one iron contract: it never throws — failures come back as a string starting ERROR:, which the model reads and self-corrects from. Every model-supplied path passes the sandbox. Every mutation passes the gate.

The shared rules

The path sandbox

Every file tool resolves paths relative to the working directory and refuses anything that leaves it (ERROR: path is outside the working directory). The check compares real paths, so a symlink sitting inside the working directory cannot be read or written through to a file outside it — a link that stays inside still works, because the rule is about leaving and not about links. Tree-walking tools apply the same test to every hit and never enter .git, build, node_modules, target. The one exception is the extended permission mode (chapter 13): there view_file, read_file, list_dir, write_file, edit_file, glob and grep also accept a path outside the working directory, still resolved through its real path. view_image stays fenced. In extended the launch file refusal is wider than in the other modes: write_file and edit_file refuse .spectro/launch.json and .claude/launch.json in any folder, subfolders of the working directory included, where the other modes refuse only the working directory's own.

The caps

Files: a whole read may take 25 % of the run’s context window, estimated at 3 bytes per token; no file over the 2 MiB fuse is read, edited or searched. Output: 10 000 chars shared clamp (surrogate-safe truncation). Glob: 200 results. Shell: 900 s timeout, pipe drained on a background thread — a timeout means “genuinely hung”, never “output too large”. Web: 512 kB streamed body cap before the text clip.

Files & search

read_filefreeinput: { path, offset?, limit? }

Reads a UTF-8 text file relative to the working directory. The file comes back whole when its estimated size (3 bytes per token) fits a quarter of the context window the run has and it is under the 2 MiB fuse. The window is the one compaction is derived from; when the backend states none, the compaction threshold stands in for it. A larger file is refused with its size, its estimated tokens, the window and the share, and can be read in pages with offset (1-based line) and limit (line count); a page is counted in bytes against the same bound. read_skill_file, which reads the files that ship beside a skill, follows the same rule. Try: “Read build.gradle.kts and tell me the dependencies.”

list_dirfreeinput: { path }

Lists a directory, sorted, directories marked with a trailing slash; an empty directory answers (empty).

globfreeinput: { pattern, path? }

Finds files by glob pattern (**/*.java) under a directory — pure Java, pruned walk, symlink-guarded, results sorted and capped at 200. Also granted to explore subagents. Try: “Find every *.test.ts file under spectro-web.”

grepfreeinput: { pattern, path?, glob? }

Searches file contents by Java regex, returning path:line:text hits — no shell involved, so it works even where run_command is denied. Skips binary files and files over the 2 MiB fuse, and names each file it skipped for its size at the end of the answer; invalid regex answers ERROR: invalid regex: …. Try: “Search for TODO across the Java sources.”

code_graphfreeinput: { action, question?, dfs?, budget?, from?, to?, name?, depth?, top? }

Asks the code graph of the session folder, the graphify-out/graph.json that Build code graph or graphify update wrote. Five actions run graphify's read-only subcommands: query asks a question in words, path finds the shortest path between two nodes, explain describes one node, affected lists what depends on a node and god_nodes lists the most connected nodes. The model sees the tool only when graphify is on the PATH and the folder has a graph, and a graph that links out of the folder is refused. graphify runs without a shell, stops after 30 s, and the answer is cut at 16,000 characters. A name or question that starts with a dash is refused. Explore subagents get it too. Try: “Use the code graph: what is affected if CodeGraphJobs changes?”

Mutation & shell

write_filegated · remembers pathinput: { path, content }

Writes a text file, creating parent directories. Success: Wrote: <path> (<n> bytes). An “always allow” remembers the full path, never a blanket approval.

edit_filegated · remembers pathinput: { path, old_string, new_string, replace_all? }

Surgical exact-string replacement. old_string must be unique (ERROR: old_string is not unique (n matches) otherwise) unless replace_all; zero matches and empty old_string error readably. A denied edit writes nothing. Try: “In README.md, change the title X to Y.”

run_commandgated · remembers first tokeninput: { command }

Runs a shell command in the working directory via /bin/sh -c: stderr merged, output drained concurrently and capped, killed on abort. The timeout is the commandTimeoutSeconds setting, 900 s as shipped, and the tool tells the model the number it was built with. Non-zero exit returns ERROR: exit code <n> plus the output — exit-code feedback is what lets the model fix its own mistakes. An “always allow” remembers only the first token (run_command:git*).

web_fetchgated · remembers URLinput: { url }

Fetches an http/https page and returns readable text (scripts/styles dropped, tags stripped, entities decoded, whitespace collapsed, 10 k-char clip). Network egress on model-chosen input is a side effect — hence the gate. Streaming fetch with finite 15 s timeouts and a 512 kB body cap; non-2xx answers ERROR: web_fetch got HTTP <status>. Main agent only.

Metadata & delegation

update_planfree · main onlyinput: { steps: [{text, status}] }

Publishes the agent's step list to the Plan panel (chapter 6) as the additive plan event. Latest wins — each call replaces the whole plan. The status enum (pending / in_progress / completed) is enforced: a model improvising "done" gets an error instead of polluting the wire. Deliberately not given to subagents — a worker's plan would clobber the display.

use_skillfreeinput: { name }

Returns the full instructions of a named skill (chapter 15). Registered only when skills are installed; children get it too, so dev-tool workers can load their role skill.

generate_imagegatedinput: { prompt }

Generates an image via the configured image provider (chapter 17). Gated because it is a paid cloud call. The image lands content-addressed under ~/.spectro/images/; the model sees only a short confirmation, and the user sees the picture in the Images panel.

spawn_agent / spawn_agentsfree · parent onlyinput: { type, task } / { agents: […] }

Starts one subagent (or up to four in parallel) and waits for the result — chapter 14. Free of a gate because the child's tools ask for permission individually; delegation is not an escape hatch.

With background: true (card 505) spawn_agents returns at once with the children's names. They take the chat's slots as a blocking batch does. Their status lines and results reach the parent as messages at its next step. The parent asks one of them how far it is with send_message and collects the results with wait_agents. The field is offered only where the parent has an inbox and agent messaging is on. At the end of a turn the run waits for its children and hands each result to the model as a message block from that child. At the turn cap, on a stop or on an error it cancels them and waits up to 30 seconds for them to end.

build_plan · write_spec · develop · testfree · parent onlyinput: { task }

The four development role tools — thin wrappers over a worker spawn, each pointing its child at a skill (chapter 14).

report_statusfree · children onlyinput: { message }

The child's side of the A2A protocol: one short progress sentence per milestone, surfacing live in the parent's UI. Telling the parent what you do is never dangerous.

send_messagefree · main and childreninput: { to, message, summary?, notify_when_idle? }

Sends one message to another agent (card 503). to is a name from list_agents: a session on this machine, parent, or a child of the run; the ref in brackets only when two rows share a name. A child agent reaches only its parent. A child that names another child or a session is refused, and the refusal tells it to send to parent instead. The parent decides what to pass on, and you see every message in the chat. An agent of the run wins over a session of the same name, and a name that reached one session earlier in the run and now names another one is refused. The result names the summary, the recipient and the msg_id; a later [Delivery notice] says when the other session held, declined or refused it. notify_when_idle asks a session for one notice when it next finishes a turn; only the main agent may ask, at most 32 at a time, and a notice that does not come within 12 hours expires. The message reaches the other model inside an attribution block that says another agent wrote it and that it grants nothing. In auto and extended a gated call is refused (peer-relay in the gate audit) when a message the run took in says something was denied, declined or not authorised and names that call: the command line, a command it chains with &&, ; or | or wraps in sh -c, its first two words, or a path. The rule reads words. A different command with the same effect, such as find build -delete for rm -rf build, or a message that names no command, still passes.

list_agentsfree · main and childreninput: { }

Lists whom send_message reaches, without a model call: the caller's own name first, then the sessions on this machine with their face, status, folder and status line, then the children of the run with their role and last status line. A child sees its parent only. Another session or a child writes the folder, face, status and status line, so each is printed on one line with control characters, brackets, guillemets and quotes turned into spaces. A folder longer than 120 characters keeps its last 119 behind an ellipsis, so the folder's own name stays; a name and the other fields stop at 100. A listing with rows ends with one line saying these fields were written by those sessions and agents and are information, not instructions. Both tools leave the request when agentMessaging is off (chapter 30) or the messaging group is unchecked.

wait_agentsfree · parent onlyinput: { ids?, timeoutSeconds? }

The join of a background fan-out (card 505). It waits for the named children, or for every background child of the run, and returns each result once, with the last status line of each child still running. It waits without polling. timeoutSeconds runs from 0, which returns at once, to 3,600; left out, it waits until the children have ended. A result the parent already took in as a message is reported as such and not repeated. Its description names the children of the run. No child holds this tool, so a background child cannot join anything and the depth stays one. It belongs to the messaging group and leaves the request with the two tools above.

schedule_wakeupgated · write · in a loopinput: { delaySeconds, reason, prompt, stop? }

Paces a loop the operator started with /loop (card 504). The delay is held between 60 and 3,600 seconds and the wakeup lands on the whole minute at or after it; the result names the time and says when the delay was moved. delaySeconds, reason and prompt are required unless stop is true, which ends the loop. The prompt <<loop>> fires the loop's own instructions: in full at the first wakeup, after a compaction, after /clear and after the session was opened again, as a short reminder otherwise. In a loop with an interval it fires the loop's own task. Any other prompt fires behind a line saying the model wrote it and when, in the chat and for the model, so it never reads as the operator's own words. A reason longer than 500 characters is cut; a prompt the model wrote that is longer than 500 characters is refused. A new wakeup replaces the pending one. The result asks the model to write its update for the tick before the call, and a stop asks for the closing summary before it, because the turn ends when the call returns: the run ends after the round of tool calls that held it, unless the call was refused. A goal's check does not run on that ending. The agent offers the tool only while the session runs a loop, so a session without one sends the tools it sent before. Tier write: in ask mode you see the call, and the auto modes check it against relayed denials as they check every gated call (chapter 10).

mcp__<server>__<tool>gated · dynamicschema from the server

Every tool a connected MCP server advertises, wrapped as a first-class spectroscope tool (chapter 18). Always gated: its inputs are model output and its effects are external.

Tool groups

Every request to the model carries the schema of every tool the session holds, whether the task uses the tool or not. In a session without MCP servers or skills, that block is 18,101 characters, about 4,500 tokens; the context ring's own reader measured it on 2026-10-09. The gear under the message box lists eight tool groups (browser, launch, images, web, agents, roles, mcp and, since card 503, messaging) with the tools each group holds in this session. The messaging group holds send_message and list_agents, which added 1,073 characters to an Anthropic request when they came (measured on the posted body on 2026-10-11), and wait_agents since card 505. When you uncheck a group, the next run leaves its tools out of the request, and so do the subagents that run spawns. With every group unchecked the block dropped to 4,125 characters on 2026-10-09, when the gear had seven groups, and the model sees the standard file tools except view_image, which belongs to images, plus run_command, update_plan and ask_user_question. code_graph, offered where the folder holds a code graph, and schedule_wakeup, offered while a loop runs, belong to no group either. Switching a group off does not change a permission: a tool that is still on asks exactly as before. If the session has a pinned folder, the gear saves your choice in that folder's local settings file under toolGroupsOff (chapter 30), and the next session starts with it. Without a pinned folder the gear says that the choice holds for this session only and is not saved. The switch applies to sessions in the app window; the REPL and spectro run send every tool.
