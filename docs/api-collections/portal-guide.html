use the api

the whole surface, importable

Everything the cockpit does over REST, you can do over REST — the web UI has no private wire. All 48 endpoints of spectro-server ship as ready-made collections, foldered by area (sessions, fleet, settings, leveling, …), every request carrying its own description and fence semantics. Host and port are collection variables with localhost defaults: change them once and every request re-targets.

which client, which file

Postman imports the v2.1 file. Bruno opens the folder natively (and imports the Postman file too). Insomnia and Hoppscotch both import the Postman v2.1 file directly — that one file serves all four clients.

No client at hand? The API answers curl just the same. One worked example — the starter-bundle catalog, from a fresh install (output abridged):

About the fences. The surface is origin-gated — the hardening that keeps a malicious web page from driving your local server. One filter checks every /api request for a loopback peer and a localhost Host; GET /api/health is the only path left open, and the individual endpoints add stricter checks on top. A desktop REST client sends no browser Origin header, and the server treats an absent Origin as safe: from the same machine, targeting localhost, every request in the collection passes. The fences bite in exactly two cases — a foreign Origin header added by hand, or a URL that names anything other than localhost (a LAN IP, a rebound DNS name). Refusals are blank 404s, never 403, so a refused caller learns nothing. Measured against a live server built from this tree:

the collections are generated from one endpoint table, and the generator diffs that table against the server's controller annotations on every run — an endpoint added to the code fails the regeneration until the table learns it. two endpoints deserve respect: DELETE /api/sessions/{id} really deletes, and POST /api/fleet/nodes answers 404 until the server runs with SPECTRO_ALLOW_SPAWN and a hub. /ws and /ws/shell are WebSocket, not REST.
