# Files Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A session tab `files` that shows, second by second, which file each tool call read, created or changed, with edits as a diff, a shell heuristic for commands, and an optional model reading on a model the person picks.

**Architecture:** Pure folds in `spectro-web/src/files/` turn the session's event list into a ledger of file calls and touches (`shell.ts` reads shell commands, `fold.ts` reads every tool call, `modelReading.ts` merges a model's answer). `files/FilesView.tsx` draws the four views from that ledger in its own lazy chunk. A new server endpoint `/api/files/analyze` streams a model's reading of a digest, on the provider and model named in the request.

**Tech Stack:** React 18 + TypeScript, vitest (`renderToStaticMarkup`, `testkit/driveComponent.tsx`), Spring Boot controller in Java 21, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-11-09-files-tab-design.md` (this branch). Mockup with the layout and behaviour to match: the clickable `index.html` of card 604, kept with the card's evidence in the private product home outside this repo (open it in a browser).

## Calls in this plan beyond the design document

These came up while reading the code for this plan. Each is the plan's call, marked here so the owner can check it.

- C9. Leveling: P2 said the tab has no rung and is open from the start. The ladder in `spectro-core/src/main/resources/leveling/levels.json` already lists a surface `files` at level 1 (`first-light`), and `isSurfaceOpen` (`state/leveling.ts:130`) gates any tab by its id. So in ladder mode the tab opens at level 1, which the ladder reaches when the first run completes. A session without a run has no files to show, so `levels.json` stays as it is. Off and the other leveling modes open it from the start.
- C10. Guide: the tab chapter is `docs/guide-assets/parts/05-web-tabs.html`, not `04-web-chat.html` as C8 said. The new section goes between Trace and Text, with the id `ch-tabs-files-tab` (`ch-tabs-files` is already the right panel's Files section).
- C11. Failure: a call counts as failed when its `tool_result.isError` is true. Measured on 2026-11-09 by a script over the 78 files in `~/.spectro/sessions`, results paired to calls by agent and call id, for `read_file`, `write_file` and `edit_file`: all 36 error results carry `isError: true` and start with `ERROR`, none of the 571 others does. Output text is not inspected.
- C12. Time: `t` is `number | null`, in seconds: `elapsedAt` in `state/stepper.ts` returns milliseconds, so the fold divides by 1000. `elapsedAt` returns null when the recording has no readable stamp; a stampless import gets no invented seconds. When the whole ledger has no clock, the timeline and the operations table count calls instead of seconds and say so.
- C13. Paths: a touch keeps the string the tool wrote (`written`) and a resolved key (`path`). The workspace is the first `run_start.workspace`; for an import, the latest `ground_info.cwd` before the call (the importer already puts these frames in the stream, `import/claudeCode.ts:1349`, so the importer needs no change). Display uses `shortenPath` from `lab/fileTree.ts`.
- C14. Model merge: model entries apply to shell calls only. A file tool's call already says exactly which file it touched; entries naming any other call are dropped. A touch carries `sources: Source[]` instead of one `source`, so a merged touch shows `probable · model`.
- C15. Vocabulary: the fold reads tool calls through `describeTool` in `components/toolViews.ts` (C4, so VS Code and Claude Code names come for free) and handles `MultiEdit` and `NotebookEdit` itself, since `describeTool` has no case for them. The lab keeps its own name sets in `lab/labScene.ts`, split into read and write (P6), and a drift test holds the two classifications together. `view_image` stays out of the lab's read set although P6 listed it: `describeTool` classifies it as `image`, the lab's tool belt has no chip for that kind (`lab/flowmap/belt.ts:129`), and `beltCoverage.test.tsx` would fail on it. The fold still reads it as a read. `Monitor` is not folded: `describeTool` gives it the `command` kind (`toolViews.ts:1559`), but its command is a wait loop, not work on files.
- C17. Start position: App's `focusEvent` is cleared by the trace (`onFocusHandled`, `App.tsx:3176`), and the trace may be mounted hidden beside the tab. So the tab gets its own state in App, `filesFocus`, set wherever a route sets `focusEvent` (`App.tsx:1322` and the `seek` case at `:2098`), passed as `startAt` and cleared by the tab through `onStartHandled`.
- C18. An `edit_file` whose result reports `fileChange: "unchanged"` gets no touch and the note `no change`, like an unchanged write.
- C16. Execution: subagent-driven, per the owner's standing rule in `~/.claude/rules/modelle-und-agenten.md` (a fresh subagent per task, review between tasks, builders on `opus`).

```ts
export type TouchKind = "read" | "create" | "change" | "overwrite" | "write" | "append" | "delete" | "unknown";
export interface ShellTouch {
  written: string;          // the path as the command spells it
  path: string;             // resolvePath(written, base at that point of the line)
  folder: boolean;
  kind: TouchKind;
  reason: string;           // rule name plus the matched fragment, e.g. "redirect > out.txt"
  replaced?: { old: string; new: string }[];
  content?: string;
  appended?: string;
}
export interface ShellReading { touches: ShellTouch[]; script: string | null; inline: boolean }
export function shellTouches(command: string, cwd: string | null): ShellReading;
```

**Files:**

**Interfaces:**

- Produces:

```ts
export type Source = "recorded" | "probable" | "model";
export interface FileTouch extends ShellTouch {
  sources: Source[];        // non-empty; "recorded" never shares with another
  callIndex: number;        // index of the tool_call in the event list
  agentId: string;
  t: number | null;         // seconds from the first event (C12)
}
export interface FileCall {
  callIndex: number; agentId: string; t: number | null; tool: string;
  line: string;             // path or full command, one line
  status: "ok" | "failed" | "pending";
  shell: boolean;
  output: string | null;    // shell calls only, for the digest
  base: string | null;      // the folder relative paths of this call resolve against (C13)
  script: string | null;
  inline: boolean;
  note: string | null;      // "no change" for an unchanged write, "no file named" for a shell call without touches
  touches: FileTouch[];
}
export interface PromptMark { eventIndex: number; t: number | null; n: number; text: string }
export interface FileLedger { calls: FileCall[]; prompts: PromptMark[]; workspace: string | null; timed: boolean }
export interface FileRow {
  path: string; label: string;               // label = shortenPath(path, workspace)
  group: "changed" | "read";
  letter: "A" | "M" | "D" | "?" | "R";
  sources: Source[];                          // union over the row's touches
  firstT: number | null; firstCall: number;
  touches: FileTouch[];
}
export interface FilesSummary { recordedChanged: number; probableChanged: number; onlyRead: number; shellCalls: number; unknownScripts: number }
export function foldFiles(events: readonly RunEvent[]): FileLedger;
export function fileRows(ledger: FileLedger, agents: ReadonlySet<string> | null): FileRow[];
export function summarize(ledger: FileLedger, rows: readonly FileRow[]): FilesSummary;
```

Rules the fold applies (from spec section 1, plus C11 to C18): a `tool_result` pairs with the latest unpaired `tool_call` of the same `agentId` and `callId`. `status` is `failed` when the result's `isError` is true (failed calls list but carry no touches), `pending` when no result came. Per `describeTool` kind: `file` and `image` give `read`; `listing` and `matches` give a folder read; `write` gives `create`, `overwrite`, `write` (reason `existence not recorded`) or no touch for `unchanged` (the call still lists, `note: "no change"`); a shell call without touches gets `note: "no file named"`; `edit` gives `change` with one `replaced` pair, or no touch and `note: "no change"` when the result reports `unchanged` (C18); `command` goes through `shellTouches` with that call's `base`, except for `Monitor`, which is not folded (C15). `summarize`: `recordedChanged` counts rows of letter `A`, `M` or `D` with a `recorded` change-like touch; `probableChanged` counts rows of letter `A`, `M` or `D` without one; `?` rows count in neither (they stand behind `unknownScripts`, the number of shell calls with a `script` or `inline`); `onlyRead` counts `R` rows; `shellCalls` counts shell calls. `MultiEdit` gives `change` with one pair per entry of `input.edits`; `NotebookEdit` gives `change` on `input.notebook_path`. Prompts are root `run_start` events (no `parentId`, agent not `TITLE_AGENT_ID`) and `user_message` events, numbered from 1. `letter`: `D` when the row's last change-like touch is a delete, `A` when its first change-like touch is a create, `M` for any other change-like touch, `?` when its only non-read touches are `unknown`, `R` when it only reads. `group` is `read` exactly for `R`.
