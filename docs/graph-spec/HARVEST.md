## L1 `.graph.jsonl` + L2 `.state.jsonl` wire format — the graph-view artifact contract (Python reference implementation at `spectroscope/graph/observe.py`, reference reader `graphview.html`)

Two sibling JSONL files share a stem and join by `(runId, node, superstep)`. `<stem>.graph.jsonl` (L1) carries seven lifecycle record types — the topology drawing plus the light that walks it — and is the file that must stay safe to attach to a bug report, so it never contains a caller's values. `<stem>.state.jsonl` (L2) carries exactly two types, `state_policy` and `state_payload`, and is the only file that may hold state values; each sink hard-refuses the other's vocabulary and counts the refusal, so miswiring cannot move the corpus into the wrong file. Recording is off by default; when it is on, a per-channel policy (four modes: off/summary/sample/full) decides what is recorded, and every ceiling that fires replaces the value with a self-describing marker object rather than a shorter value, so a truncated value can never be mistaken for a complete one. Three facts are deliberately kept distinguishable and a port must preserve all three: what a node **wrote** (`node_end.updateKeys` / `updateBytes`), what was **recorded** (`state_payload.channels`), and **why they differ** (`state_policy`). The artifacts examined are a real `summary`-mode run (11 supersteps, one CRAG rewrite cycle) and they exercise both absence reasons in one file: `docs` is written and absent because it is not on the allow list, `principal` is written and absent because it is denied.

### Rules

- **One record per line: compact JSON with separators `(",", ":")` (no spaces anywhere), UTF-8, LF line ends, non-ASCII emitted RAW (`ensure_ascii=False`, i.e. `ü` not `ü`).**
  - why: One viewer reads this file and the RunEvent wire; a second dialect in the same viewer is the actual cost. `head -1 file.jsonl` showing a human a whole record is the property the whole design rests on (it is why compression was refused).
  - test: Write a record containing `"Wartungsfenster — Freigabe"` and assert the raw line bytes contain the UTF-8 for `ü` and `—`, contain no `\u` escape, and contain no `", "` or `": "` sequence.
- **`type` is ALWAYS the first key of a record and `ts` is ALWAYS the last; every other declared field sits between them in builder order. This is enforced at the sink (`_ordered`), not only at the builder, so a hand-rolled record gets ordered too.**
  - why: A viewer and a diff both rely on it; the runtime is allowed to build a record by hand, so the guarantee has to belong to the writer of the line.
  - test: `assert list(record)[0] == "type" and list(record)[-1] == "ts"` for every record type, including one passed to the sink as a hand-built dict with keys in the wrong order.
- **`ts` is an integer of epoch MILLISECONDS. It is stamped by the writer only when the caller omits it; a caller-supplied `ts` is preserved verbatim.**
  - why: The two files (and the session file) interleave by `ts`; a re-stamped timestamp would reorder a replay.
  - test: Build a record with `ts=7` and assert the emitted line ends `,"ts":7}`; build one with `ts=None` and assert the value is within a second of `now*1000` and is an int, not a float.
- **A field whose value is `None` is omitted from the record ENTIRELY (the Jackson `NON_NULL` rule) — but only at the top level of the record. Nulls nested inside `channels` are preserved.**
  - why: An absent key means 'not applicable'; a null inside a channel means 'the node wrote null'. Collapsing the second into the first would destroy the distinction between not-recorded and recorded-as-empty.
  - test: `edge_taken(..., branch=None)` produces a line with no `branch` key at all; `state_payload("n", 1, {"x": None}, sample_policy)` produces `"channels":{"x":null}`.
- **Reading is tolerant and silent: blank lines, unparseable lines and lines whose JSON is not an object are dropped without a word or an exception. A MISSING file, by contrast, raises.**
  - why: The common cause of a torn line is a crash mid-write, and the reader's job is to show what survived. But a file that was never written is a different problem from an empty one and must not be silently reported as 'no records'.
  - test: Append `{"type":"node_e` (torn) to a valid artifact and assert the loader returns all prior records with no error; call the loader on a nonexistent path and assert it raises.
- **Field names are camelCase (`durationMs`, `updateKeys`, `updateBytes`, `recordCap`, `runId`, `threadId`) with EXACTLY ONE exception: `graph_topology.schema_version` is snake_case. Record `type` values are snake_case throughout.**
  - why: The topology is built by another module which owns its own keys; the artifact owns only the envelope (`type` first, `ts` last) and reinterprets nothing. A port that camelCases the envelope's contents breaks the reader.
  - test: Assert the topology line contains `"schema_version":1` and does NOT contain `schemaVersion`; assert `node_end` contains `durationMs` and not `duration_ms`.
- **`.graph.jsonl` has exactly seven record types: `graph_topology`, `graph_start`, `node_start`, `node_end`, `node_error`, `edge_taken`, `graph_end`. Its writer MUST refuse any record whose type is `state_policy` or `state_payload`, drop it, and increment a `refused` counter.**
  - why: The promise that this file is safe to attach to a bug report is enforced where it cannot be forgotten, rather than at a call site. It makes it impossible to get the corpus into the wrong file by wiring a sink wrong.
  - test: Hand a `state_payload` record to the graph writer; assert the file is unchanged byte-for-byte and `writer.refused == 1`.
- **`.state.jsonl` has exactly two record types, `state_policy` and `state_payload`. Its writer MUST refuse everything else (including `graph_topology`) and count it. It NEVER clips — the record it receives is already clipped.**
  - why: Clipping in the sink would leave every other sink in a fan-out holding the raw corpus. The clip belongs to the record builder; the sink only writes.
  - test: Hand a `node_end` record to the state writer and assert `refused == 1`; build a `MultiSink(ListSink(), StateArtifact(...))` around a run with a 38 KB corpus and assert the `ListSink`'s captured records contain no document text.
- **`graph_topology` shape: `{"type":"graph_topology","schema_version":<int, currently 1>,"entry":<node id or omitted>,"nodes":[{"id","label"}],"edges":[{"from","to","kind":"direct"|"conditional","branch":<name, conditional only>}],"branches":[{"name","source","targets":[…]}],"ts":…}`. It carries NO `runId`. START and END are ordinary nodes with ids `__start__` and `__end__`, emitted first and last respectively, END exactly once.**
  - why: A renderer that has to special-case two sentinels will get one of them wrong. Order is declaration order throughout so the same graph yields the same bytes and artifacts stay comparable across runs.
  - test: Compile the same graph twice and assert byte-identical topology lines; assert `nodes[0].id == "__start__"`, `nodes[-1].id == "__end__"`, and that `__end__` appears exactly once even when it is both key and value in a path_map.
- **The FIRST `graph_topology` line in the file is the drawing. A later one (a re-ingest appended to the same file) stays in the ordinary record stream and must not silently replace the drawing.**
  - why: The file is opened in append mode and holds many runs. A viewer that took the last topology would silently draw the wrong shape for the earlier runs in the same file.
  - test: Append a second run with a changed graph; assert the loader's returned topology is the first one and that the second `graph_topology` is present in the records list.
- **`graph_start`: `runId` (required, non-empty), `threadId` (present only when a checkpointer is configured, omitted otherwise). `graph_end`: `runId`, `steps` (int, the superstep count the recursion limit is measured against), `durationMs` (optional).**
  - why: `runId` on every record is what lets a reader tell a retry from a second turn in an append-mode file. `steps` is the number a recursion limit is measured against.
  - test: Run without a checkpointer and assert no `threadId` key exists on the `graph_start` line; in the reference artifact `graph_end` reads `"steps":11` for supersteps 0…10 plus the edge into `__end__` at superstep 11.
- **`node_end` ALWAYS carries `updateKeys` (array) and `updateBytes` (int), even when the node wrote nothing — as `[]` and `0`, never omitted. `updateKeys` is in the node's OWN write order and is never sorted.**
  - why: `[]` is not null, so the NON_NULL rule does not remove it — and it must not, because `updateKeys: []` is the record that says 'this node finished and wrote no channel', which is a different fact from a missing payload line. Reordering the keys would be a small lie about what the node did.
  - test: `node_end("noop", 1, 0, None)` emits `"updateKeys":[],"updateBytes":0`; `node_end("n",1,0,{"zebra":1,"alpha":2})` emits `["zebra","alpha"]`.
- **`updateBytes` is the TRUE full serialized size of the node's whole update in bytes, and it stays true even when the payload record holds a clipped view of the same update. It is measured as the UTF-8 byte length of the compact, non-ASCII-escaped JSON of the update dict, best-effort (`default=str`, then `repr`, then 0) and it may NEVER raise.**
  - why: The two files cross-check each other: a reader sees that `retrieve` wrote 38,321 bytes and that only some were recorded. A size hint that took the run down would be an observation changing the observed.
  - test: `node_end("retrieve",2,41,{"docs":[1,2],"trace":["x"]})` gives `updateBytes == 28` (`len(b'{"docs":[1,2],"trace":["x"]}')`); a value whose `__str__` raises still yields an int and no exception.
- **`node_error`: `error` is the exception CLASS name only (or the literal `"Error"` when the caller passed a plain string) and `message` is the text, separate fields — never one `"Type: message"` string. `message` longer than 1000 characters is cut to 1000 and gets a single `…` (U+2026) appended. `durationMs` is optional.**
  - why: A viewer groups by error class; a fused string forces it to parse. The message cap exists because a message built by interpolating a document is payload wearing a diagnostic's coat.
  - test: `node_error("grade",3,ValueError("empty corpus"))` gives `error == "ValueError"`, `message == "empty corpus"`; a 5000-char message yields `len(message) == 1001` ending in `…`.
- **A cancelled node is recorded as a `node_error` and then re-raised; it must never leave a `node_start` with no ending.**
  - why: An SSE consumer walking away mid-stream is the ordinary case, and a node with no ending is indistinguishable from a viewer that lost a line.
  - test: Cancel a run mid-node and assert the artifact holds a `node_error` for the in-flight node with the same `(runId, node, superstep)` as its `node_start`.
- **`edge_taken`: the wire key is `from` (plus `to`), `branch` is present ONLY for conditional edges and names the SOURCE NODE (disambiguated `source#2` for a second branch out of the same node), never the path function. `superstep` is the superstep the edge leads INTO, not the one it leaves.**
  - why: A path function is routinely a lambda, so its `__name__` means nothing. The into-semantics let a reader walk the file and see arrows into a frontier and then that frontier's nodes lighting up.
  - test: In the reference artifact, `router → retrieve` carries `"superstep":1` while the `node_start` for `router` carries `"superstep":0`; the final `verify → __end__` carries `"superstep":11` and no node record exists at 11.
- **A reader MUST be able to draw an `edge_taken` naming an arrow that is not in the topology, rather than dropping it or throwing.**
  - why: A conditional branch declared without a `path_map` is legal and its targets are unknowable at compile time, so the topology carries the branch with no arrows while the run still walks somewhere.
  - test: Feed a reader a topology with a branch that has zero conditional edges plus an `edge_taken` for that branch; assert the arrow renders and no exception is raised.
- **`superstep` is 0-based and numbers the frontiers of ONE run. It is NOT the checkpointer's step: for a single run `snapshot.step == superstep + 1`, and a checkpointer's step continues across turns on the same thread while `superstep` restarts at 0.**
  - why: Two similarly named counters measuring different quantities; a viewer that conflates them is off by one, and under LangGraph the equivalent number does not restart per run at all.
  - test: Run twice on one thread and assert both runs' first `node_start` carries `"superstep":0` while the saver's step values continue upward.
- **`state_policy` is emitted exactly once PER RUN, immediately after `graph_start` and before any `state_payload` of that run. The policy is read once at run start and carried to every node of the run; it can never change mid-run.**
  - why: The file is append-mode and holds several runs, so a reader meeting a payload must find the policy of THAT run above it. A run that announced `summary` and then recorded something else would make its own policy record a lie — which is why a mid-run UI toggle was refused.
  - test: Two runs against one file produce two `state_policy` lines, each directly after its own `graph_start`, each carrying its run's `runId`; no payload line precedes its run's policy line.
- **`state_policy` fields: `runId`, `mode` (exactly one of `off`|`summary`|`sample`|`full`), `allowed` (array, omitted when empty), `caps` (object, omitted when empty), `recordCap` (int, omitted when null), `denied` (array, omitted when empty), `redaction` (STRING: `"patterns"` when recording, `"off"` at off — NEVER a boolean).**
  - why: `"redaction":true` would imply a completeness the measurement disproves: six of six credential shapes caught, six of six confidential-prose cases missed. A RAG corpus is made of prose.
  - test: `state_policy_record(StatePolicy.full(acknowledged=True))` has no `caps` and no `recordCap` keys at all; `StatePolicy.off()` yields exactly `{type, runId, mode:"off", redaction:"off", ts}`; assert `redaction` is never `true`/`false` in any mode.
- **A cap reaches the wire as an INT, or as a three-element ARRAY `["sample", keep, bytes]` — never a tuple, object or string. A channel denied by a `None` cap is dropped from `caps` entirely and appears in `denied`.**
  - why: A tuple would still dump as an array from Python, but a second sink in a fan-out receives the record object and must not be handed a Python-only type. A denied channel shown with a cap would read as recordable.
  - test: `json.loads` the policy line and assert `isinstance(caps["docs"], list)` and `caps["docs"] == ["sample", 3, 512]`; construct with `caps={"secret": None}` and assert `"secret" not in caps` and `"secret" in denied`.
- **The policy gate is one function asked once per channel, with this precedence: a channel named in `allowed` is recorded even if it is on the deny list; otherwise a channel in `denied` is never recorded; otherwise it is recorded only in `sample` and `full`. Under `summary` a channel that is neither allowed nor denied is NOT recorded.**
  - why: One gate, so the answer cannot differ between the record and the policy line that explains the record. `summary` is a named-channels tier on purpose: a caller whose state uses different words gets nothing until it says which words — the safe way round for a mode whose promise is 'no documents'.
  - test: With `summary()`, a channel `notes` that is not in `allowed` produces no entry in `channels`; with `full(allow={"principal"})`, `principal` IS recorded; with `full(acknowledged=True)` and no allow, `principal` is not.
- **`state_payload` fields: `runId`, `node`, `superstep`, `channels` (object), `truncated` (array of channel names, OMITTED when nothing was truncated — never present as `[]`). `channels` key order is the node's own write order.**
  - why: `truncated` lets a viewer badge a row without walking the tree; `[]` would violate the NON_NULL rule the dialect keeps everywhere else.
  - test: A payload where nothing was clipped has no `truncated` key; a payload where only `docs` was sampled has `"truncated":["docs"]`; `{"zebra":1,"alpha":2}` yields `list(channels) == ["zebra","alpha"]`.
- **The join key is `(runId, node, superstep)` — all three. A later line for the same key overwrites an earlier one.**
  - why: A node enters twice in one run (the reference artifact has `router`, `retrieve`, `rerank` and `grade` each at two supersteps), so joining on the node name alone would show the second attempt's values under the first. A node runs at most once per superstep, so the triple is unique even under fan-out.
  - test: Load the reference `crag-payload.state.jsonl` and assert the map has 11 distinct entries, including both `(run,"retrieve",1)` and `(run,"retrieve",6)`.
- **When nothing is recordable, NO line is written — never a line with an empty `channels` object. Likewise the runtime skips the builder entirely when the node's update is empty.**
  - why: An empty `channels` would read as 'the node wrote nothing', which is a different fact and is already told by `node_end.updateKeys`.
  - test: A node writing only `{"principal": …}` under `sample()` produces zero `state_payload` lines while its `node_end` still carries `"updateKeys":["principal"]`.
- **A truncated value is NEVER a shorter value of the same type — it is a marker object. Five marker shapes, each naming which ceiling fired via `omitted`: clipped string `{"kind":"str","bytes":<true UTF-8 bytes>,"chars":<true code points>,"omitted":"cap","head":<prefix>}`; sampled list `{"kind":"list","len":<true length>,"bytes":<true serialized bytes of the WHOLE list>,"omitted":"cap","sampled":<kept>,"items":[…]}`; redaction `{"kind":"redacted","rule":<rule name>,"bytes":<bucket STRING>}`; unserializable `{"kind":"unserializable","type":<type name>,"omitted":"error"}`; record-cap collapse `{"kind":"channel","bytes":<true size of the original channel value>,"omitted":"recordCap"}`.**
  - why: This is the house rule 'a field we cannot fill truthfully is not added', applied to values. A shortened string that looks like a whole string is the one failure this layer exists to prevent.
  - test: Clip `"A"*5000` at 512 and assert the channel equals `{"kind":"str","bytes":5000,"chars":5000,"omitted":"cap","head":"A"*512}` — assert it is a dict, not a str.
- **`head` is ALWAYS a byte-prefix of the real value: cut at exactly `bytes` UTF-8 bytes, with a half-written character at the cut DROPPED (decode errors ignored). No ellipsis is appended, no middle elision, no summary, never model-written.**
  - why: A generated précis in an evidence file is the exact opposite of the product. Dropping the partial character keeps `head` a prefix rather than a repair of one.
  - test: `"ü"*100` capped at 9 bytes yields `head == "üüüü"` (8 bytes), `bytes == 200`, `chars == 100`; and for any clip, `real_value.startswith(head)` and `"…" not in head`.
- **`items` in a sampled list is the LEADING slice in the node's own order — never a 'best' or 'most relevant' selection.**
  - why: A selection implies a judgement the recorder is not entitled to make, and rerank already reordered the list for its own reasons.
  - test: Sample 8 docs to 3 and assert `[i["ordinal"] for i in items] == [0,1,2]`.
- **Redaction runs BEFORE clipping, and a string in which any pattern fires is replaced WHOLE — never partially masked, never with surviving prose around the marker. `redacted.bytes` is a coarse BUCKET STRING from the fixed set `"1-8"|"9-16"|"17-32"|"33-64"|"65-128"|"129+"` measuring the whole value, never an exact length.**
  - why: Redact-then-clip is what stops a `head` ending mid-credential. The tail of a key is still a key, and prose surviving beside a marker invites the reader to believe 'the rest is fine'. The exact length is a small oracle and is a recorded open finding against the Java llm-wire; a defect already on the books is not repeated here.
  - test: A 4000-char document containing `sk-proj-AbCdEf0123456789XyZwVu` records as `{"kind":"redacted","rule":"openai-key","bytes":"129+"}` with none of the surrounding prose present; assert `bytes` is a `str`, not an `int`.
- **The `recordCap` is checked against the serialized size of the WHOLE record including its envelope. When it fires, EVERY channel of that record collapses to a `{"kind":"channel",…,"omitted":"recordCap"}` marker carrying the true size of the ORIGINAL (unclipped) channel value, `truncated` lists every channel, and the collapsed record is emitted without being re-checked against the cap.**
  - why: The last-resort ceiling. The line still exists and still names every channel with its true size, so a reader loses the values but never the fact that they were written.
  - test: An update of 40×900-char trace strings plus `confidence: 0.82` under `sample()` yields both channels collapsed, `confidence` as `{"kind":"channel","bytes":4,"omitted":"recordCap"}`, `truncated == ["trace","confidence"]`, and the whole line under 8192 bytes.
- **Building a payload record may NEVER raise and never change the run's outcome. A cycle, a nesting depth over 32, a `__str__` that raises, or a non-finite float each become an `unserializable` marker; the whole build-and-emit path sits inside an absorbing catch that increments a failure counter and warns once.**
  - why: Observation may not change the observed. A channel that disappears silently is the failure mode `node_error` was added to prevent, so a value that cannot be described says so instead of vanishing.
  - test: `{"confidence": NaN}` records as an unserializable marker and `json.loads(json.dumps(record))` succeeds under strict parsing (a bare `NaN` token would fail); a self-referencing list produces a marker and no exception.
- **The policy is applied in the record BUILDER, before the record reaches any sink — never in a sink. The caller's update dict is never mutated.**
  - why: The sink protocol is `Callable[[dict], None]` and always will be, so a fan-out carrying an OTLP exporter, a test collector or a print-to-stderr callable would otherwise be handed the raw corpus. A record that reaches a sink is already safe.
  - test: Run with `MultiSink(ListSink(), StateArtifact(...))` and a 38 KB corpus; assert no document text appears in the `ListSink` records, and assert the node's original update dict is unchanged after the emit.
- **A reader must recognise a marker by `kind` PLUS its companion field, never by `kind` alone: `str`+`head`, `list`+`items` (array), `redacted`+`rule` (string), `channel`+`omitted=="recordCap"`, `unserializable`+`kind`. Anything else is ordinary caller data.**
  - why: A caller is entitled to a state channel or a document field literally called `kind`; mistaking one for a marker would print a truncation that never happened.
  - test: Record `{"doc": {"kind": "list", "title": "x"}}` verbatim under `full()` and assert the reader renders it as a plain object, not as a sampled-list badge.
- **Four different absences mean four different things and the reader must print four different sentences: (a) channel in `node_end.updateKeys` but absent from `channels` → written, not recorded — reason read from `state_policy` (`denied` → policy: deny; `mode:"summary"` and not in `allowed` → not on the allow list; `mode:"off"` → policy: off); (b) channel PRESENT in `channels` with value `[]`, `""`, `0` or `null` → written and empty; (c) no payload line at all with `updateKeys == []` → the node finished and wrote nothing; (d) no payload line with `updateKeys` non-empty → every channel was denied; (e) no `.state.jsonl` at all → unknown, and the view must say which flag turns it on rather than printing a riddle.**
  - why: This is the whole reason `state_policy` exists. Without it a missing channel is ambiguous between 'the node did not write it', 'the policy denied it' and 'the recorder failed'.
  - test: Against the reference pair: `router` at superstep 0 has `updateKeys ["query_used","route","principal","trace"]` and `channels {query_used, route, trace}` → `principal` must render 'not recorded · policy: deny' (it is in `denied`); `retrieve` at superstep 1 has `updateKeys ["docs","trace"]` and `channels {trace}` → `docs` must render 'not recorded · not on the allow list' (mode summary, absent from `allowed`).
- **A `.state.jsonl` whose `runId` does not match the `runId` of the drawn run's `graph_start` must NOT be joined. The file stays loaded and unjoined and the view says why.**
  - why: Draping one run's values over another run's drawing is a fabricated association — the one thing an evidence view cannot afford.
  - test: Load a payload file from run B against a graph file from run A; assert zero channels render and a 'not joined' banner names both run ids.
- **Path resolution: the two files are siblings `<stem>.graph.jsonl` and `<stem>.state.jsonl`, and the suffix rule is idempotent ACROSS the family — a path already carrying one known suffix is re-pointed, not doubled, and a bare `.jsonl` loses its extension first.**
  - why: A caller hands the same path to both writers and must land in two files rather than one, so `artifacts("run.graph.jsonl")` still writes payloads to `run.state.jsonl`.
  - test: `_state_path("run.graph.jsonl")` → `run.state.jsonl`; `_artifact_path("run.graph.jsonl")` → unchanged; `_state_path("20260810-session.jsonl")` → `20260810-session.state.jsonl`.
- **Both files are opened in APPEND mode and every line is flushed immediately. The writer never closes a sink it did not open; a closed sink under a running graph is just a sink that raises, and the emit path absorbs it.**
  - why: A process that dies mid-run loses its last line and never its history — the file a viewer is tailing is complete up to the moment of the crash, which is exactly when somebody wants to read it.
  - test: Write three records without closing and assert the file already contains three complete lines; close the sink under a running graph and assert the run completes with `sink_failures` incremented.
- **Default is `off`, and at `off` NOTHING is built: the clipper is never called, no `state_policy` record is emitted by the runtime, and the `.state.jsonl` file is never opened. `full` must be unreachable without an explicit acknowledgement argument.**
  - why: A library upgrade that silently begins writing a user's document corpus to disk is a data incident, not a feature. Recording is a line in the caller's own source or it does not happen. `full` measures over 100 % of the state it observes, so a caller who reaches it by tab-completing a mode name has not made the decision the mode represents.
  - test: Run with no state argument and assert no `.state.jsonl` exists on disk (not a zero-byte file); assert `StatePolicy.full()` without the acknowledgement raises; assert the runtime emits zero `state_policy` lines when the mode is off.

### Traps

- `graph_topology.schema_version` is the ONE snake_case key in an otherwise camelCase dialect. A port that camelCases the envelope's contents (or a Jackson `SNAKE_CASE`/`LOWER_CAMEL` naming strategy applied blanket) breaks the reader on the very first line.
- `updateBytes`, the sampled-list `bytes` and the clipped-string `bytes` are all UTF-8 byte lengths of COMPACT, NON-escaped JSON. Jackson escapes non-ASCII by default and JS `JSON.stringify` does not add spaces but `TextEncoder` is needed for the byte count — a German or emoji-bearing corpus will produce different numbers in every port that does not pin both settings.
- `chars` on a clipped-string marker counts Unicode CODE POINTS (Python `len`), not UTF-16 code units. Java `String.length()` and JS `.length` both count UTF-16 units, so any astral character (emoji, some CJK ext) silently doubles the number. The existing test uses `ü`, which is BMP and therefore does not catch it.
- `bytes` is a NUMBER on the `str`, `list` and `channel` markers, and a STRING bucket (`"33-64"`) on the `redacted` marker. Same key name, two JSON types — a typed reader modelling `bytes: number` will throw on the first redaction, and a Java `long bytes` field will fail to deserialize.
- `truncated` must be OMITTED when empty, never `[]`. Java's Jackson `NON_NULL` does not suppress an empty list (that needs `NON_EMPTY`), so a naive port emits `"truncated":[]` on every clean record and the reader badges rows that were never truncated.
- The mirror-image trap: `updateKeys` MUST be emitted as `[]` and `updateBytes` as `0` for a node that wrote nothing. A blanket `NON_EMPTY`/`NON_DEFAULT` strategy suppresses both, and the reader then cannot tell 'wrote nothing' from 'has not finished yet'.
- `caps` in a `state_policy` record lists channels that are NEVER recorded under that mode. The reference artifact is `summary` and its `caps` contains `"docs":["sample",3,512]` while `allowed` excludes `docs`. Cap presence does not imply recordability; only `allowed`/`denied`/`mode` decide.
- A `("sample", keep, bytes)` cap applies at EVERY depth of that channel, to every nested list and every nested string — not only the top-level list. `docs` with `("sample",3,512)` also cuts a 10-element tag list inside a kept document down to 3 and clips every inner string at 512 bytes. A port that applies the cap only at the first level records far more than the policy promised.
- DICTS are never sampled — only lists and tuples. A 500-key object is recorded whole (subject only to `recordCap`), and a tuple serializes as a JSON array. A port that samples map entries diverges; one that serializes tuples as objects breaks the wire.
- At `off` the runtime resolves the policy to `None` and emits NO `state_policy` record and opens no file — even though the builder can produce a valid `mode:"off"` record. So in practice a `mode:"off"` line only ever appears if a caller emits one by hand. A reader must still handle it (it is the only way to say 'written deliberately, recorded nothing'), but must not expect it, and must not treat a missing `.state.jsonl` as proof that recording was off.
- `edge_taken.superstep` is the superstep the edge leads INTO. Assuming it is the superstep it leaves puts every arrow one frontier early, and the final edge into `__end__` carries a superstep for which no node record exists (11 in the reference artifact, where nodes run at 0…10).
- The `state_payload` line is written AFTER the `node_end` for the same node and superstep, and the `state_policy` line lands in a DIFFERENT file from the `graph_start` it follows. A streaming reader that assumes payload-before-lifecycle, or that waits for the policy on the graph stream, deadlocks or drops the first payloads.
- `_record` strips `None` only at the TOP level. Nulls nested inside `channels` survive and are load-bearing (`"x":null` = the node wrote null). A port that runs a recursive null-stripping serializer erases the distinction between 'written as null' and 'not recorded'.
- Python checks `bool` before `int` (bools are ints there). In Java/TS this is naturally distinct, but the reverse trap applies: `abstained: false` and `confidence: 0.0` must serialize as `false`/`0`, not be dropped by a NON_DEFAULT rule — the reference artifact's `verify` node carries exactly these two.
- Non-finite floats must never reach the JSON. Python's default dumper writes bare `NaN`/`Infinity` tokens which strict readers reject; the clipper converts them to `unserializable` markers first. Jackson has the same default and needs `QUOTE_NON_NUMERIC_NUMBERS` off plus the same pre-conversion.
- A caller may legitimately have a state channel or document field named `kind`. Marker detection must require `kind` PLUS its companion field (`head`, `items` as array, `rule` as string, `omitted == "recordCap"`), or the reader will print a truncation badge on ordinary data.
- `branch` on an `edge_taken` and in the topology names the SOURCE NODE, disambiguated as `source#2` for a second branch out of the same node — it is not the path function's name (path functions are routinely lambdas). A port that names branches after the function produces names that never join.
- A branch declared without a `path_map` puts zero conditional edges in the topology while the run still emits `edge_taken` for it. The reader must draw an arrow the drawing never had; dropping it hides a real path and throwing takes the view down.
- `updateBytes` is best-effort (`default=str`, then `repr`, then 0) and is NOT the sum of the per-channel `bytes` values in the payload record — it measures the whole update dict including its own JSON punctuation. Cross-checking them for exact equality in a test will fail.
- The collapsed `recordCap` record is emitted WITHOUT being re-checked against the cap. With very many channels the collapsed line can itself exceed `recordCap`; that is deliberate (the line must still name every channel) and a port that loops until it fits will drop channel names.

## spectroscope.graph — the LangGraph-compatible graph runtime, as pinned in /Users/christopher.ezell/Spectroscope/spectroscope-harness-python/spectro/docs/GRAPH-CONTRACT.md (cross-checked against the built code in spectro/spectroscope/graph/{state,graph,runtime,checkpoint,observe}.py)

A deliberate, dependency-free subset of LangGraph: a Pregel-style state machine whose topology is fixed and serializable at compile() time, so a run can be drawn first and lit up afterwards from a JSONL artifact. Five parts: state.py (the START/END sentinels, reducer resolution from Annotated metadata, the non-mutating state merge), graph.py (StateGraph builder, 15 eager/deferred validation refusals, the frozen GraphSpec, build_topology), runtime.py (CompiledGraph: the superstep loop, routing phases, stream modes, the stream-writer contextvar, recursion limit, sync-node thread pool), checkpoint.py (StateSnapshot, the BaseCheckpointSaver seam, InMemorySaver with deep-copy detachment), observe.py (the record vocabulary and the .graph.jsonl / .state.jsonl sinks). Explicitly and permanently out of scope: Send, Command, interrupt() and human-in-the-loop resume, Store, subgraphs, retry policies, node caching, message reducers (add_messages/MessagesState), astream_events, stream_mode "messages"/"debug", update_state and time-travel replay, LangChain Runnable conformance, persistent checkpointers, langgraph.prebuilt. Absent surface must fail loudly at import/compile, never as a quiet wrong answer at run time. Three statements in the document were measured false against real LangGraph 1.2.9 and are corrected in place: the reducer is the LAST Annotated metadata entry (not the first callable), config injection is by parameter NAME (not by arity), and the default recursion limit is 10007 (not 25). The whole point of the package is determinism and observability, so anything that would make two runs of the same graph differ — set iteration, shared mutable state, a sink that can abort a run — is a contract violation, not a style question.

### Rules

- **START is the literal string "__start__" and END is the literal string "__end__". They are plain strings, not enum/sentinel objects.**
  - why: They appear as path_map keys, as values in the serialized topology, and as entries in the JSONL artifact. Anything richer needs special-casing in all three places.
  - test: Assert the exact string values; assert a topology JSON round-trip carries them as strings.
- **The graph state is a plain mutable map at runtime (Map<String,Object>). The schema type is a declaration only — it is never used as a gate on which keys may be written.**
  - why: Nodes return partial updates, never a full state; a run that died because a node stashed a diagnostic field would be a worse failure than an untyped channel.
  - test: A node returning a key the schema never declared is merged, not rejected.
- **resolve_reducers reads the LAST metadata entry of a channel's Annotated type, and uses it only if it is callable. A non-callable last entry leaves the channel last-write-wins, even when an earlier entry IS a reducer.**
  - why: Measured false the other way in the original pin. Annotated[list, operator.add, "a note"] gives ['y'] on LangGraph 1.2.9 (no reducer) but ['x','y'] under a first-callable rule. Neither engine raises, so the only symptom is a different final state — exactly what a drop-in must not have. Ledger row F4.
  - test: Two nodes in sequence each returning {"c":[…]} on schema Annotated[list, operator.add, "doc"] → final c == ['y']; with the reducer last → ['x','y'].
- **A resolved reducer must accept exactly two POSITIONAL parameters. Keyword-only extras with defaults are fine (def join(a, b, *, sep=",")); varargs do not count as positional; a callable whose signature cannot be read is refused. Violation raises InvalidReducerError (a ValueError subclass) with the message prefix "Invalid reducer signature. Expected (a, b) -> c." naming the channel and the callable.**
  - why: A reducer is only exercised on the SECOND write to its channel, so an unusable one survives a smoke test and takes down a superstep in production with a TypeError naming neither the channel nor the callable. LangGraph raises the same wording at StateGraph(schema); we raise at compile() — both are build time, no node has run either way.
  - test: Annotated[list, len] and Annotated[list, operator.add, len] both fail at compile with that message; Annotated[list, join_with_sep] compiles.
- **A schema carrying no annotations at all returns an empty reducer map rather than raising.**
  - why: A graph without reducers is a legitimate graph — one where every channel overwrites.
  - test: compile() a graph over a bare class/stub schema and run it.
- **apply_update(state, update, reducers) returns a NEW map and never mutates either argument. update == null returns a copy (not an alias); update == {} returns a copy.**
  - why: The runtime keeps the pre-superstep state alive to hand to every node in the frontier, and the checkpointer keeps older snapshots alive to serve history — one in-place write corrupts both. An alias would let a caller share a map with the engine.
  - test: Mutate the returned map and assert the input state is unchanged; assert identity inequality for the null-update case.
- **An update that is not a map is an error: raise InvalidUpdateError (message "Expected dict, got <type>: <repr>"). The TYPE is what is checked, never truthiness — empty list, empty tuple, empty string, 0 and false are all refused exactly as ['x'] is. Only null and an empty map mean "no channels written".**
  - why: LangGraph 1.2.9 refuses all of them; a silent pass hides the node's mistake until some later run makes the value non-empty.
  - test: Parametrized: [], (), "", 0, false, ['x'] all raise; null and {} do not.
- **Per channel in the update: if there is no reducer, OR the channel is absent from the state, OR the current value is null, the update value is SET (seeds the channel). Only otherwise is reducer(current, value) called.**
  - why: A reducer needs a left operand. Absent-channel seeding is the normal case on the first superstep of a total=False schema; folding into nothing would throw or produce garbage.
  - test: First write to an operator.add channel on an empty state yields the value itself, not an exception.
- **Updates are folded in the update's own key iteration order, and concurrent updates from one superstep are folded by calling apply_update once per update, in FRONTIER order.**
  - why: That gives the reducer its seed from the first writer and folds the rest; two nodes writing the same plain channel must resolve deterministically in frontier order.
  - test: Two-node frontier both writing the same plain channel → the second-in-frontier value wins, reproducibly.
- **add_node refuses: a name that is not a non-empty string; a name equal to START or END; a duplicate name; a non-callable action. All four are eager (at the add_node call), not deferred to compile().**
  - why: None of them can be repaired by a later call, and an error at the offending line beats an error at the bottom of the builder function. Node names are the identity a run is traced by, so they must be unique.
  - test: Four refusal tests, each asserting GraphValidationError at the add_node call site.
- **add_node does NOT inspect the action's signature. Whether the callable is usable is the runtime's business.**
  - why: The measured caller binds dependencies with a hand-named one-argument closure precisely because LangGraph inspects the signature; validating at build time would reject legal shapes.
  - test: add_node with a zero-arg callable succeeds at build and fails at run.
- **add_edge refuses start == END ("nothing leaves END") and end == START ("nothing enters START"), eagerly. Whether the two ends exist is checked at compile(), not here.**
  - why: Edges are routinely declared before the nodes they point at, so endpoint existence must be deferred; but no later add_node could make START-as-target or END-as-source valid.
  - test: add_edge(END,'x') and add_edge('x',START) raise immediately; add_edge('a','b') before add_node('b') is accepted and validated at compile.
- **An identical (start, end) edge declared twice is recorded exactly once.**
  - why: Semantically a no-op, but a duplicate would draw a second arrow in the topology.
  - test: Declare the same edge twice; topology has one edge.
- **add_conditional_edges refuses a non-callable path and source == END, eagerly. path_map may be a dict, a list of strings, or null; a list is normalised to an identity mapping at declaration time; a list entry that is not a string, and any other path_map type, raise GraphValidationError.**
  - why: Reducing the three accepted forms to dict-or-null at the seam means the runtime and the topology only ever see one shape.
  - test: list path_map ['a','b'] produces branch.targets ('a','b'); path_map=42 raises; path_map=['a',7] raises.
- **branch.targets is the deduplicated tuple of path_map VALUES for a dict, the entries themselves for a list, and empty for a null path_map — with declaration/insertion order preserved.**
  - why: The topology draws one edge per target; order stability is what makes two artifacts of the same graph byte-comparable.
  - test: A dict path_map with two keys mapping to the same node yields one target.

- **compile() takes a keyword-only sink= (any callable taking a record map) and a keyword-only state= (a StatePolicy); CompiledGraph's constructor is (spec, checkpointer=null, topology=null, sink=null, state=null) with topology third positional and sink/state keyword-only.**
  - why: Without a sink seam nothing could write the artifact through the public path — the whole reason for the package. Keyword-only so nothing positional can drift into it; named sink rather than on_record because observe.py already owns that word.
  - test: Positional misuse is rejected; sink receives the topology record.
- **The topology record is written to the sink in the CONSTRUCTOR — at compile() time, before a node has run — and the topology is computed once and never recomputed.**
  - why: A viewer tailing the artifact has the drawing before the first node runs. A topology that could change between runs would make the view a guess.
  - test: compile() with a list sink; assert the first record is graph_topology before any run.
- **Every record of one run carries the same runId (12 hex chars from a uuid4). One call to the engine is one run.**
  - why: The artifact is opened in append mode and a compiled graph is normally run many times; without it a reader cannot tell a retry from a second turn.
  - test: Two runs on one compiled graph produce two distinct runIds and no record without one.
- **The record vocabulary is exactly: graph_topology (first line of the file), graph_start {runId, threadId?}, node_start {runId, node, superstep}, node_end {runId, node, superstep, durationMs, updateKeys[], updateBytes}, node_error {runId, node, superstep, durationMs, error, message}, edge_taken {runId, from, to, branch?, superstep}, graph_end {runId, steps, durationMs}. threadId is absent for a graph without a checkpointer; branch is absent for a static edge.**
  - why: Declared in one place so the runtime and any reader cannot drift. The camelCase is the RunEvent wire's.
  - test: Golden-file test of a full CRAG run's artifact.
- **Record key order is fixed: "type" first, "ts" last, declared fields in between, and any null field is OMITTED entirely rather than serialized as null. JSON is compact (no spaces) and does not escape non-ASCII.**
  - why: Identical to the RunEvent wire, so a viewer can rely on the shape whoever wrote the line. The ordering guarantee belongs to the sink, which normalises any hand-built record.
  - test: Serialize a record with a null field and assert the key is absent and the byte layout matches.
- **node_end takes the RAW update and records only its SHAPE: updateKeys in the node's own write order (not sorted) and updateBytes = the true full serialized size. Redaction lives in the record builder, never at the call site or in the sink.**
  - why: A caller who has to remember to strip values will one day forget, and the forgetting is silent. Clipping in the sink would let a MultiSink's second sink see the raw corpus. updateBytes stays the TRUE size even when an L2 payload records a clipped view, which is what lets the two files cross-check each other.
  - test: A node writing a 39 KB corpus: the .graph.jsonl line contains the key names and 39021, and none of the content.
- **node_error carries error = the exception's simple class name ("Error" for a bare string) and message = its text, truncated at a fixed limit with an ellipsis. error and message are separate fields, never one "Type: message" string.**
  - why: A viewer groups by class; a single string forces every reader to re-parse it.
  - test: Raise with a 100 KB message; assert truncation and the two fields.
- **An edge_taken is emitted for EVERY edge actually walked, including edges into END, and its superstep is the one the edge leads INTO.**
  - why: The topology can only say where a branch might go; the record of where it went is the entire difference between a drawing and a run.
  - test: Reconstruct the run's path from topology + records with no access to state and assert it equals the trace the run produced (test_graph_integration.py's last group).
- **A branch with a NULL path_map produces edge_taken records for arrows that are not in the topology. A reader/viewer MUST be able to draw an arrow the topology never had, rather than dropping it or falling over.**
  - why: Omitting path_map is legal and its targets are unknowable at compile time. This is the documented price of omitting it.
  - test: The pinned integration case: unmapped branch, assert the reader renders the arrow.
- **graph_end is emitted from a finally — always, including on a raised run, a recursion abort, and a consumer that walked away mid-stream. It carries steps (the superstep count) and durationMs.**
  - why: An artifact whose last run has no ending is indistinguishable from a viewer that lost the tail.
  - test: Three failure shapes, each assert a trailing graph_end with the right runId.
- **A cancelled node is recorded as a node_error with class CancelledError and then re-raised. For a SYNC node the message must say the run was abandoned, the node is sync, its worker thread could not be cancelled and may still be running. An async node keeps its own plain cancellation.**
  - why: A node that vanishes without a node_end looks exactly like a viewer that dropped a line — and recording a sync node's cancellation as a clean ending is a lie a reader cannot detect: the artifact would show it stopping at superstep 3 while it went on calling an API for another minute.
  - test: Abandon a stream over a sync node and over an async node; assert both messages.
- **Record building is LAZY — the emit seam takes a thunk and builds nothing when there is no sink.**
  - why: node_end measures the update it is handed, and a retrieval node's update is the whole retrieved corpus; a run with no sink must not pay for a measurement nobody reads. A thunk makes that structural instead of a rule every call site must remember.
  - test: With no sink, a node writing a huge update performs zero serialization (instrument the size hint).
- **The emit seam ABSORBS everything an emit can raise — the building of the record as much as the writing of it — and never lets it replace a running exception. Catch the ordinary-exception tier only, never the process-is-stopping tier (Exception, not BaseException / in Java: Exception, not Error or InterruptedException-as-cancellation).**
  - why: Observation may never change the outcome of the thing observed. graph_end is reported from a finally, so a node failing with Boom while the artifact's disk filled up reached the caller as the SINK's OSError with Boom demoted to __context__ — and a caller that turns an exception into an SSE error event then tells its user about a file and never about the real failure.
  - test: Node raises Boom + sink raises OSError → the caller receives Boom.
- **The FIRST sink failure warns once per compiled graph, naming the exception; every failure increments a public counter CompiledGraph.sink_failures. Never silent, never once-per-record.**
  - why: Silence makes a truncated artifact indistinguishable from a crashed process; warning on every record buries the run in noise the moment a disk fills.
  - test: Ten failing emits → one warning, sink_failures == 10.
- **A record builder returning null is a DECLINE, not a failure: nothing is written and sink_failures is not incremented.**
  - why: The state-payload clipper can find nothing worth recording when a policy denies every channel a node wrote, and a line naming no channel costs a reader a lookup to learn nothing.
  - test: Policy denying all channels → no state_payload line, sink_failures == 0.
- **The runtime NEVER opens a sink and never closes one, not after a run and not on the way out. A sink closed under a live graph is simply a sink that raises: absorbed, warned once, counted.**
  - why: A compiled graph is long-lived and runs many times, so closing after a run would be wrong and closing at the end would be closing somebody else's file. Before this, a closed artifact poisoned the graph permanently, every later run dying with "I/O operation on closed file".
  - test: Close the artifact mid-life; later runs still complete and sink_failures grows.
- **A sink is called SYNCHRONOUSLY on the event-loop thread; the protocol is Callable[[record], void] and stays sync. A slow sink stalls the loop (measured 12.6 ms over six records at 5 ms per write) and a sink that writes slowly must buffer internally.**
  - why: Making the seam async would change the contract every exporter is written against.
  - test: Document + a timing test pinning the stall so nobody 'fixes' it by making the seam async.
- **to_topology_json() returns a DEEP copy of the topology.**
  - why: The artifact and any viewer hold on to what they are given, and a shared nested list is a corruption waiting for its second reader.
  - test: Mutate the returned structure; the graph's own topology is unchanged.
- **L2 state payloads (the values a node wrote) are opt-in, default OFF, go into a SEPARATE file (<stem>.state.jsonl) with their own record types (state_policy, state_payload), and the policy is read ONCE per run and carried down to every node.**
  - why: A library update must not start writing a caller's document corpus to disk — that is a data incident, not a feature; the .graph.jsonl has to stay safe to attach to a bug report. A run that announced one tier and recorded another would make its own policy record a lie, which is why a mid-run toggle is refused.
  - test: Default compile writes no state file; changing the policy attribute mid-run does not change what that run records.
- **The state_payload carries the node's OWN update at that superstep, not the merged state, and is emitted AFTER node_end. A node that wrote no channel gets no line.**
  - why: What a reader needs is what THIS node wrote before a reducer folded a sibling's write in beside it; and the shape belongs on record before the values that fill it in.
  - test: Assert ordering node_end → state_payload and that an empty update produces no payload line.
- **An invalid state policy is refused ONCE, at compile time (a TypeError), including the case of handing the policy CLASS instead of an instance. A policy whose mode is "off" resolves to no policy at all, so the clipper is never called.**
  - why: The alternatives are a per-node failure for the length of every run, or a silent "off" — which is how a caller who asked to see their data ends up with an empty file and no reason for it. The class's field default reads as "off", so state=StatePolicy with the tier call forgotten would look like a valid request to record nothing.
  - test: state=StatePolicy (the class) raises at compile; state=StatePolicy.off() records nothing and never walks a corpus.
- **The config handed to a node is the CALLER'S OWN map, unchanged and unwrapped — no ensure_config() wrapper, no callbacks/tags/metadata/run_id, and no per-call copy.**
  - why: Known, written-down sharp edge (§9.13). A node reading config["configurable"][…] — the documented pattern and the measured caller's — sees no difference; a node reading config["callbacks"] gets a KeyError here; and because the map is not copied, a node that mutates its config mutates the caller's. Copying per node call buys nothing for any node shape in evidence.
  - test: A node mutating config is observable by the caller — pin it as the documented behaviour so nobody 'fixes' it by accident.
- **Node functions may be one-argument closures with their name assigned by hand; the signature-inspection path must accept that shape first of all, and must also handle callable objects (signature read off the invoke method), bound methods, and partially-applied functions.**
  - why: builder.py:115-126 assigns __name__ by hand and rejects functools.partial precisely because LangGraph inspects the node signature.
  - test: The four shapes each run and each get the right config-injection decision.
- **A node returns a PARTIAL update — never assume a full state — and may return null.**
  - why: nodes.py:538,711 return partial RAGState(...) which is a plain map at runtime.
  - test: A node returning {"answer": …} alone leaves every other channel intact.

### Traps

- The reducer is the LAST Annotated metadata entry, not the first callable. Taking the first callable is the natural implementation and it silently produces a different final state — no exception on either side. This exact bug was in the original pin. In Java the analogue is scanning a channel's annotation list for the first one that looks like a BinaryOperator; scan from the end and stop at the first entry, callable or not.
- Config injection by ARITY instead of by NAME. A node declared (state, deps=DEFAULT) gets its own deps on LangGraph and got our config dict here — no exception, no failing test, just a wrong answer. In Java, decide from the parameter's declared name (or an explicit marker), and only for the kinds that can take a keyword.
- HashMap/HashSet anywhere in the topology, the frontier, or the node registry. Frontier order decides plain-channel merge order, and topology byte-stability is a pinned property; any unordered iteration makes runs non-reproducible and artifacts non-comparable. Use LinkedHashMap/List throughout and preserve declaration order.
- Applying node updates as they arrive instead of at superstep end. Everything still passes on a linear graph; it only breaks — silently, as a wrong answer — on a fan-out.
- Merging a continuing thread with a plain map-merge instead of through the reducers. Explainv2 hands in trace=[] every turn; the plain merge wipes the accumulated trace, an offset computation then exceeds the list length, and every SSE done event carries an empty trace while the tests stay green.
- Making astream or aget_state_history return a future/CompletableFuture. The caller consumes them with no await; a coroutine-shaped return fails at the call site. aget_state is the opposite — it must be awaited.
- Treating stream_mode=["values"] as a single mode and yielding bare chunks. The SHAPE of the argument decides the chunk shape, not its length; the caller unpacks (mode, chunk).
- Wrapping custom chunks in an envelope, or batching them until superstep end. The consumer reads chunk["type"] directly, and batching kills token streaming while every test still passes.
- Returning null from get_stream_writer() inside a run when nobody consumes custom mode. It does not raise; it flips a caller that branches on `writer != null` onto its non-streaming path. Always return a real no-op callable.
- Forgetting to skip the first values chunk. "values" emits the INPUT state before the first superstep; ainvoke on a graph that does nothing returns the input.
- Shallow-copying checkpoint values. A node appending to a list at superstep 2 rewrites the snapshot superstep 1 already filed, and the store then holds ~nothing of its own (measured 32 KiB where it should hold 69 KiB). Deep-copy in AND out, values and metadata; never copy config.
- Conflating snapshot.step with the record's superstep. Different counters — one numbers a thread's checkpoints, the other one run's frontiers — and a viewer that conflates them is off by one from the second turn onward.
- Passing the runtime's superstep index into aput. It restarts a thread's step series at zero on every turn.
- Letting a failing sink abort a run, or letting it replace a live exception. graph_end is emitted from a finally, so the sink's IO error can arrive at the caller with the real failure demoted to a cause. Absorb everything on the emit path (build AND write), warn once, count the rest.
- Closing the sink from the runtime. A compiled graph runs many times; closing after a run is wrong and closing at teardown closes somebody else's file. Conversely, a sink closed by its owner mid-life must degrade to counted failures, not poison the graph.
- Building the record eagerly. node_end measures the update, and a retrieval node's update is the whole corpus — a run with no sink must pay nothing. Pass a supplier, not a built record.
- Dropping edge_taken records whose arrow is not in the topology. A branch without a path_map legally walks edges the drawing never had; a reader must render them.
- Naming branches after the path function. The measured caller passes lambdas; names must come from the source node, with #2/#3 suffixes for repeats, and the runtime must read them back out of the topology rather than recomputing.
- Assuming a node returns a full state. Updates are partial, may be null, and may contain keys the schema never declared.
- Rejecting a non-dict update by truthiness. [] , (), "", 0 and false must all be refused exactly as ['x'] is; a silent pass hides the node bug until the value is non-empty.
- Coercing recursion_limit from a string, or checking it after graph_start. A numeric string is a config bug that must be refused, and a refused run must leave no beginning in the artifact.
- Setting the writer binding in the parent after the node tasks exist. Contexts are copied at task creation, so it reaches nobody — and the symptom is only missing tokens.
- Letting the writer binding leak out of the run, which makes get_stream_writer() stop raising outside a run and breaks the caller's "am I being streamed" probe.
- Running sync nodes on the shared/common thread pool. An abandoned run pins its thread until the node finishes, and on the common pool those threads come out of everyone else's budget. Use one named package-level pool sized like the default one.
- Believing a sync node can be cancelled. The future is cancelled, the thread is not; the node runs to completion and its side effects happen. LangGraph has the same limit. All you can do is retire the writer, tell the truth in the artifact, and contain the blast radius.
- Bounding the custom queue. Dropping a chunk is worse than a slow stream; warn once at 10 000 unread and keep going.
- Adding a `tasks` field to StateSnapshot to look more like LangGraph. An empty tasks tuple reads "nothing is pending" on exactly the snapshots where something is; a missing member fails honestly.
- Yielding history oldest-first. The caller collects until limit then reverses, so it silently keeps the wrong end of a long conversation and never raises.
- Copying every snapshot before applying limit in alist. The copy is the expensive part; limit must bound the work. And limit arrives from a query parameter, so <= 0 must yield nothing rather than slice weirdly.
- Using an event-loop-bound lock in the saver. Uncontended it protects nothing across threads; contended it binds to one loop and fails later with a cross-loop error.
- Turning the sink protocol async to fix the loop stall. Every exporter is written against the sync seam; a slow sink must buffer instead.
- Sorting updateKeys, or reordering record keys. Key order is the node's own write order; record order is type-first/ts-last with nulls omitted entirely, compact JSON, non-ASCII unescaped — an artifact is compared byte-for-byte.
- Implementing anything from the permanent out-of-scope list (Send, Command, interrupt(), Store, subgraphs, retry policies, node caching, message reducers, astream_events, stream_mode messages/debug, update_state / time-travel, persistent checkpointers, prebuilt). Absence must fail at import/compile time, never as a quiet wrong answer at run time.

## spectroscope.graph — the LangGraph divergence register (docs/LANGGRAPH-DIVERGENCES.md) plus the pinned graph contract (docs/GRAPH-CONTRACT.md §5, §6, §9) it depends on

`spectroscope.graph` is a deliberate subset of LangGraph, sized against one measured caller (the Explainv2 agentic-RAG backend) and offered as a drop-in for the surface that caller uses. On 2026-08-10, 98 behaviours were run twice through the same import lines — once against real LangGraph 1.2.9 on Python 3.14.6, once against this engine — and 89 matched after the runtime fix round (87 before it); every assertion was written by measuring LangGraph first and then pinning that answer, so a red line on our side is a divergence and a red line on theirs would mean the suite is wrong. The divergences fall into three buckets: six kept on purpose with a written reason (D5, D6, D7, D8, F8, F13, plus lower-stakes F11 and F12), three closed and re-measured in the runtime round (D10/D11 recursion limit, F3 config injection, F7 writer in a path function), and the rest open as intent at commit `5d005db` (D1, D2, D3, D4, D9, F4, F5, F10) — several of which the current working tree has since closed in code, which is itself a trap because the doc still lists them as pending. A second class of entries are not LangGraph differences at all but engine defects found by an adversarial review and fixed (F1 the observation seam, F2 the un-cancellable sync node, F6 the synchronous sink, F9 the unbounded queue, F14 the writer swallowing late writes); those live in GRAPH-CONTRACT §9.9–§9.13 and are exactly the behaviours a port will re-introduce if it does not know they were bugs. The load-bearing invariants a Java/TS port must carry are: Pregel superstep isolation, the conditional path seeing the merged frontier state, config injection by NAME not arity, reducer = the LAST annotated entry and only if callable (arity-checked at build), `DEFAULT_RECURSION_LIMIT = 10007`, observation that can never alter the observed, a truncated value that can never look complete, and the honest admission that a sync node cannot be cancelled at all.

### Rules

- **[Supersteps] Execution is Pregel-style: one superstep runs the whole current frontier concurrently, collects every node's update, and applies them only after every node has returned. A node NEVER sees a sibling's write from its own superstep.**
  - why: If updates landed as they arrived, two runs of the same graph would not agree, and the artifact could not be replayed. This is the property the whole package exists for; it was among the 89 behaviours that already match LangGraph and must not regress.
  - test: Two nodes in one frontier both read channel X and both write it; assert each observed the pre-superstep value, and that the post-superstep state contains both writes folded.
- **[Merge order] Concurrent updates are folded by calling apply_update once per update, in FRONTIER ORDER — the first writer seeds the reducer, the rest fold into it.**
  - why: Order-independent folding would make a fan-out's final state depend on task completion timing.
  - test: Two siblings each appending to an operator.add list must always yield frontier order, over many runs, regardless of which coroutine finishes first.
- **[F8 — KEPT DIVERGENCE] A conditional path function is handed the state AFTER the superstep's updates are merged (the whole frontier's view), not the deciding node's own view. LangGraph hands it the deciding node's view.**
  - why: GRAPH-CONTRACT §5.3: the record holds one merged state per frontier, so the routing decision that follows is reproducible from the artifact. LangGraph's per-node view cannot be reconstructed from the record. Only reachable when a conditional edge leaves a node that ran alongside siblings; a router in a chain sees the same state either way.
  - test: Frontier {a,b}, both write `trace`, conditional edge out of a: LangGraph path sees [['a']], this engine sees [['a','b']]. Pin ours to the merged value.
- **[F3 — CLOSED, re-measured 2026-08-10] Config is injected BY NAME, never by arity: into a parameter literally called `config`, of kind POSITIONAL_OR_KEYWORD or KEYWORD_ONLY, passed as a KEYWORD. State always goes positionally. A positional-only `config` (def n(state, config, /)) is NOT injected and both engines raise the same TypeError.**
  - why: The old arity rule gave `def node(state, deps=DEFAULT_DEPS)` the config dict where LangGraph leaves the node's own DEPS — a silent wrong answer, no exception, and no test on either side can see it. The caller's builder.py:115-126 explicitly warns that the engine inspects the node signature.
  - test: Drive twelve shapes through both engines and require 12/12 agreement on the injection decision: (state), (state, config), (state, deps=…), (state, *, config), (*args), (state, **kwargs), (state, config, /), (state, config, extra=…), a callable object, a bound method, a functools.partial, and the async form.
- **[F3 residual] LangGraph additionally refuses injection unless the parameter is unannotated or annotated RunnableConfig (it warns and skips). This engine has no RunnableConfig to compare against and injects whatever the annotation says.**
  - why: The package has zero third-party dependencies. The difference runs in the permissive direction, so no working LangGraph graph breaks on it.
  - test: def n(state, config: MyThing) -> LangGraph does not inject and warns; this engine injects. Pin ours as permissive and document it.
- **[Node shape] A node is `async def f(state)`, `def f(state)`, or either with a `config` parameter, and returns a partial update dict or None. Decide the shape by signature introspection, never by trying the call and catching TypeError.**
  - why: Catching TypeError conflates 'the node does not want config' with 'the node raised TypeError internally'. The measured caller passes one-argument closures with __name__ assigned by hand (functools.partial was rejected precisely because LangGraph inspects signatures), so that shape must be accepted first of all.
  - test: A node whose body raises TypeError must propagate it verbatim, not be retried with a different arity.
- **[9.13 — KEPT DIVERGENCE, found while measuring] The config a node receives is the CALLER'S OWN dict, unwrapped and NOT copied. LangGraph passes an ensure_config() result carrying callbacks, tags, metadata and run_id alongside configurable.**
  - why: Callbacks are LangChain machinery this package will not grow. Consequences: config['configurable'][...] is identical (the documented and measured pattern), config['callbacks'] KeyErrors here, and a node that mutates its config mutates the caller's. The third is a real sharp edge, written down rather than fixed because copying per node call buys nothing for any node shape in evidence.
  - test: A node doing config['x']=1 leaves x in the caller's dict afterwards. A port that copies must say so, because it changes this.
- **[F4 — reducer resolution] The reducer is the LAST entry of a channel's Annotated metadata, and only when that entry is callable. A non-callable last entry leaves the channel last-write-wins even if an earlier entry is callable.**
  - why: The engine originally took the FIRST callable. Annotated[list, operator.add, 'doc'] then produced ['x','y'] here against ['y'] on LangGraph — a different final state, no error on either side, invisible to every test. Exactly the difference a drop-in must not have.
  - test: Annotated[list, operator.add, 'doc'] -> ['y'] (no reducer); Annotated[list, 'doc', operator.add] -> ['x','y']; Annotated[str, 'the question'] stays last-write-wins.
- **[F4 — arity check at BUILD time] A last metadata entry that is callable but cannot serve as (a, b) -> c is refused while the graph is being built, not mid-run.**
  - why: LangGraph raises `ValueError: Invalid reducer signature. Expected (a, b) -> c. Got (obj, /)` at build for both Annotated[list, len] and Annotated[list, operator.add, len] — which is the second, independent proof that only the LAST entry is read. ## spectroscope.graph — the Python graph engine (5 modules, 3570 lines) at /Users/christopher.ezell/Spectroscope/spectroscope-harness-python/spectro/spectroscope/graph/

A dependency-free, deliberate subset of the LangGraph surface, built so that a run can be *watched*: the topology is frozen and serializable the moment `compile()` returns, so a viewer draws the machine first and lights it up from an event stream afterwards. Five modules, one concern each — `state.py` (channels, reducers, the non-mutating merge), `graph.py` (the `StateGraph` builder, validation, the frozen `GraphSpec`, `build_topology`), `runtime.py` (`CompiledGraph`, Pregel supersteps, three stream modes, the writer contextvar, the sync-node thread pool), `checkpoint.py` (the three-method saver seam, `InMemorySaver`, `StateSnapshot`), `observe.py` (two JSONL artifacts, seven lifecycle record types plus two state-payload types, the `StatePolicy` tiers, the sink protocol). Execution is Pregel-style: a superstep runs the entire frontier against the *same* pre-superstep state, collects partial updates, and only then folds them through the reducers — determinism is the product, because a run that cannot be replayed cannot be watched. Observation is a one-method seam (`Callable[[dict], None]`) and is fail-safe by design: a sink that raises warns once, increments `sink_failures`, and never replaces an in-flight exception or aborts a run. Value recording (`.state.jsonl`) is a separate file and is OFF unless a caller names a tier, because a library that silently starts writing a user's document corpus to disk is a data incident, not a feature. Every non-obvious choice in the source was measured against LangGraph 1.2.9 and the reasoning is in the docstrings and in `docs/GRAPH-CONTRACT.md` / `docs/LANGGRAPH-DIVERGENCES.md`; treat those docstrings as the spec, they carry the bug each rule came from.

### Rules

- **A superstep runs the ENTIRE frontier against the same pre-superstep state, collects each node's partial update, and only then folds them in via apply_update once per update in frontier order. No node ever sees a sibling's write from its own superstep.**
  - why: Determinism. If updates landed as they arrived, two runs of the same graph over the same input could disagree, and a run that cannot be replayed cannot be watched — which is the entire product claim.
  - test: Two nodes in one frontier, both writing the same reducer channel and both reading it: each must read the pre-superstep value; the final state must contain both writes folded in frontier order.
- **The reducer of a channel is the LAST entry of the Annotated metadata, and only when that entry is callable. A non-callable last entry leaves the channel last-write-wins even if a callable sits earlier.**
  - why: Measured against LangGraph 1.2.9: on Annotated[list, operator.add, "a note"] LangGraph leaves ['y'] after two writes, while first-callable-wins leaves ['x','y']. Neither side raises — the only symptom is a different final state, which is exactly the difference a drop-in must not have.
  - test: Schema with Annotated[list, operator.add, "doc"]; two nodes each appending; final state must be the second write alone. With the reducer last, both survive.
- **A reducer is refused unless it has exactly 2 positional parameters (POSITIONAL_ONLY or POSITIONAL_OR_KEYWORD). Keyword-only extras with defaults are fine; *args does not count; an uninspectable callable is refused with the reason attached. The message begins with the verbatim string "Invalid reducer signature. Expected (a, b) -> c."**
  - why: A reducer is only exercised on the SECOND write to its channel, so an unusable one survives a smoke test and then takes down a superstep in production with a TypeError naming neither the channel nor the callable.
  - test: Annotated[list, len] must raise InvalidReducerError at compile()/spec-freeze, naming the channel and the callable, before any node runs.
- **apply_update never mutates its arguments and always returns a NEW dict. update=None returns a copy (not an alias). An empty dict returns a copy. Anything that is not a dict raises InvalidUpdateError — the TYPE is checked, never the truthiness, so [], (), "", 0 and False are refused exactly as ['x'] is.**
  - why: The runtime keeps the pre-superstep state alive to hand to every node in the frontier and the checkpointer keeps older snapshots alive to serve history — one in-place write corrupts both. A silent pass on [] would hide a wrong-return-type node until some later run made the value non-empty.
  - test: Assert identity: apply_update(s, None, {}) is not s. Assert each of [], (), "", 0, False raises.
- **A reducer SEEDS its channel instead of folding when the channel is absent from the state or currently holds None. Channels the schema never declared are simply set, not rejected.**
  - why: The normal case on the first superstep of a total=False schema — a reducer needs a left operand. The schema is a declaration, not a gate; a run that dies because a node stashed a diagnostic field is a worse failure than an untyped channel.
  - test: Empty state + update {"trace": ["a"]} on an operator.add channel must yield ["a"], not raise.
- **Config is injected into a node or path function by parameter NAME — a parameter literally called `config`, of kind POSITIONAL_OR_KEYWORD or KEYWORD_ONLY — and passed as a keyword. Never by counting positional parameters, and never by calling and catching TypeError. State goes positionally, config by keyword.**
  - why: LangGraph's own rule (_internal/_runnable.py:317-345). An arity rule hands `def node(state, deps=DEPS)` the config dict where LangGraph leaves the node its own dependency object — no exception, no failing test, just a different answer. Call-and-catch would run a node twice and report its own TypeError as an arity problem.
  - test: 12 shapes: (state), (state, config), (state, deps=…), (state, *, config), (*args), (state, **kwargs), (state, config, /), (state, config, extra=…), callable object, bound method, functools.partial, async form. Injection decision must agree on all 12, including the positional-only case that fails on both.
- **Custom stream chunks leave the moment a node writes them, never batched at superstep end.**
  - why: Token streaming is exactly the case where batching is invisible in a test and fatal in the product.
  - test: A node that writes 3 chunks then awaits a barrier: the consumer must receive all 3 before the superstep completes.
- **get_stream_writer() raises outside a run and returns a REAL callable inside one, even when nobody consumes the custom mode. Never null/None inside a run.**
  - why: Callers branch on `writer is not None` and take the streaming path whenever they get one; returning None inside a run would silently switch the caller to its non-streaming path with all tests still green. Raising outside a run is the documented way callers detect "no graph context".
  - test: Inside ainvoke (no custom consumer) the writer must be callable and its writes must be dropped silently; outside any run the call must raise.
- **The stream writer is also bound inside conditional-edge path functions. Routing runs as its own phase, on its own task, with the writer bound — and that phase is skipped entirely when none of the source nodes has a conditional branch.**
  - why: LangGraph serves a working writer in a path function; a router emitting "deciding…" is an ordinary pattern, and the caller idiom wraps the call in a bare except, so a broken writer shows up as tokens that quietly stop appearing. The skip is so a graph of static edges pays nothing per superstep.
  - test: A path function calling get_stream_writer()("deciding") must produce a custom chunk; a static-edge-only graph must not allocate a routing task.
- **The writer of a phase is RETIRED in the phase's finally. After retirement a write drops the payload, releases the queue, and returns None.**
  - why: A sync node cannot be cancelled, so an abandoned run leaves it writing. What it must not keep doing is reaching anything: a queue nobody drains grows without limit, a later phase's stream is corrupted by a dead one's tokens, and a closed loop answers with "RuntimeError: Event loop is closed" — the runtime's teardown delivered to somebody else's node as if it were their bug.
  - test: Break out of astream after 3 chunks from a slow sync node; the node's later writes must reach nothing and raise nothing, and no chunk of the dead phase may appear in a later run's stream.
- **stream_mode: None means "values"; a single string yields BARE chunks; a list yields (mode, chunk) tuples even when it names exactly one mode. The SHAPE of the argument decides, never its length. An unknown mode, or an empty list, raises ValueError rather than serving silence.**
  - why: The caller unpacks based on how it called. LangGraph accepts an unknown mode and streams nothing; a consumer that asked for a mode and gets silence cannot tell "the graph produced nothing" from "that mode does not exist here" — and this engine serves 3 modes where LangGraph serves 7, so silence is both likelier and harder to diagnose.
  - test: stream_mode=["values"] must yield 2-tuples; stream_mode="values" must yield bare dicts; "bogus", ["values","bogus"] and [] must each raise ValueError.
- **Per-run emission order is fixed: route from START (step 0) → persist → yield values(input state) → then per superstep: run frontier → apply updates in frontier order → yield one updates chunk per node → step += 1 → route → persist → yield values.**
  - why: A viewer replays the file in order; the values chunk before the first superstep is what makes ainvoke on a do-nothing graph return the input, matching LangGraph.
  - test: Record the (mode, chunk) sequence of a two-node chain and pin it exactly, including the leading values chunk.
- **The `superstep` on an edge_taken record is the step the edge leads INTO; the superstep on node_start/node_end/node_error is the step that node ran at. Both are 0-based and number the frontiers of ONE run.**
  - why: A reader walking the file sees the arrows into a frontier and then the nodes of that frontier lighting up. A viewer that conflates the two is off by one.
  - test: In a 3-node chain, the edge_taken from node A to node B must carry the same superstep as B's node_start, not A's.
- **Default recursion limit is 10007 supersteps, checked as `step >= limit` at the top of the loop. config["recursion_limit"]=None means the default; a non-int raises TypeError naming the type (a string that happens to parse is NOT coerced); a value below 1 raises ValueError "recursion_limit must be at least 1" before anything runs. The error names the cycle and the knob that widens it.**
  - why: 10007 is LangGraph's own number, counted not read. An earlier 25 was chosen against one caller's loop — a fine margin and the wrong contract: a graph that completes on LangGraph must complete here. Below 1, deque(maxlen=-1) used to raise from the middle of the engine, saying nothing about the caller's mistake.
  - test: A single-node cycle with no exit must run exactly 10007 iterations then raise GraphRecursionError whose message lists the cycling node names and mentions config={"recursion_limit": N}. recursion_limit="4" must raise TypeError, -1 must raise ValueError.
- **Every record of one run carries the same runId (12 hex chars). graph_start is emitted after the recursion limit is validated but before the state is loaded; graph_end is emitted from a finally, carrying the superstep count and the elapsed millis.**
  - why: The artifact is opened in append mode and a compiled graph runs many times — without runId a reader cannot tell a retry from a second turn. A run that raised, or whose consumer walked away mid-stream, still ended; an artifact whose last run has no ending is indistinguishable from a viewer that lost the tail. A run refused for an impossible limit never began and must not appear.
  - test: Abandon a stream mid-run and assert a graph_end with the same runId is in the file; pass recursion_limit=0 and assert neither graph_start nor graph_end appears.
- **Observation is fail-safe. The record is BUILT lazily (behind a thunk) and both the building and the writing are wrapped: any Exception — not BaseException — is absorbed, the FIRST failure warns once per compiled graph naming the exception, and every failure increments sink_failures. A builder that returns None is a DECLINE, not a failure, and is not counted.**
  - why: A sink that raises used to abort the run; worse, graph_end is emitted from a finally, so a node failing with Boom while the artifact's disk filled up reached the caller as the sink's OSError with Boom demoted to __context__ — and a caller turning that into an error event tells its user about a file instead of the real failure. Silence would make a truncated artifact look like a crashed process; warning per record would bury the run in noise. KeyboardInterrupt through a sink is the process being asked to stop.
  - test: A node raising Boom plus a sink raising OSError: the caller must see Boom. A sink raising on every record: exactly one warning, sink_failures equal to the record count, run completes.
- **The runtime NEVER opens and NEVER closes a sink — not after a run, not on the way out. A sink closed under a live graph is simply a sink that raises and is absorbed like any other.**
  - why: A compiled graph is long-lived and runs many times, so closing after the first run would be wrong and closing at the end would be closing somebody else's file. A closed GraphArtifact used to poison the graph permanently, every later run dying with "I/O operation on closed file".
  - test: Close the artifact between two runs; the second run must complete and only increment sink_failures.
- **A node's failure is recorded (node_error, with the duration) BEFORE the exception escapes, and a cancellation is recorded and then re-raised. On any node failure the remaining tasks in the frontier are cancelled AND awaited before the error escapes.**
  - why: A node that vanishes from the file without an ending is indistinguishable from a viewer that dropped a line, and a consumer walking away mid-stream is the ordinary case for an SSE endpoint. A broken run must never leave a task writing into a state nobody reads any more.
  - test: Kill one node of a 3-node frontier; assert one node_error and that the two siblings are settled before the exception reaches the caller.
- **A cancelled node is recorded honestly about what actually stopped: an async node keeps its own plain CancelledError; a SYNC node is recorded with the message "the run was abandoned; this node is sync, so its worker thread could not be cancelled and may still be running". The record's class stays CancelledError either way.**
  - why: asyncio cancels the future, never the thread — measured, a consumer that broke after 3 chunks left the node writing 37 more. Recording that as a clean ending is a lie a reader cannot detect: the artifact would show a node that stopped at superstep 3 while it went on calling an API for another minute.
  - test: Abandon a stream over a sync node and assert the node_error message names the thread caveat; the same over an async node must not.
- **Multi-turn continuation merges THROUGH the reducers: the incoming input is applied as an update onto the persisted values, never substituted for them and never `{**persisted, **incoming}`.**
  - why: The measured caller hands in a fully populated fresh state every turn including an empty accumulating channel. Merging appends nothing and the accumulated history survives; a plain overwrite silently resets it to [], an offset computed from its length then exceeds the list, and every downstream event carries an empty trace while the tests still pass.
  - test: Two ainvoke calls on one thread_id, each passing trace=[] on an operator.add channel: turn two must see turn one's trace intact.
- **Without a thread_id the run simply goes unrecorded — persistence is skipped, not failed. Without a checkpointer, every thread question (aget_state, aget_state_history) raises MissingCheckpointerError. An UNKNOWN thread is not an error: it yields an empty snapshot with step -1.**
  - why: A graph run from a script is legitimate; an unaddressable checkpoint is not. "No history" is the normal state of a first message, whereas a missing checkpointer means the graph was compiled without memory and every thread question is meaningless.
  - test: Run without config → no snapshot, no exception. aget_state on a graph compiled without a checkpointer → raises. aget_state on an unknown thread → StateSnapshot with values={} and step -1.
- **Checkpoint history comes back NEWEST FIRST.**
  - why: The measured caller collects turns until it has enough, then reverses. Oldest-first keeps the OPENING turns of a long conversation and drops the ones the user is looking at, without raising anything.
  - test: Three checkpoints on one thread; the first snapshot out of alist must be the third one in.
- **A saver must DETACH the values it stores from the mapping it was handed, deeply, on the way IN and on the way OUT. `config` is never copied anywhere.**
  - why: The runtime is still running on that mapping — a node that appends to state["docs"] at superstep 2 is holding the very list superstep 1 filed away. LangGraph escapes this by serializing; the store held 32 KiB for a 1.5 MiB thread because it held the running state, not a copy. Config is addressing, not state, and is where callers put callbacks and clients — the things copying most likely chokes on.
  - test: Take a checkpoint, mutate a nested list in the live state, re-read the snapshot: unchanged. Mutate the returned snapshot's values: the store is unchanged.
- **aput's step defaults to one past the thread's last step, so a second turn on a thread CONTINUES the numbering rather than restarting at zero. snapshot.step numbers a THREAD's history; the runtime's superstep numbers ONE run's frontiers, and the runtime deliberately does not pass its step to aput.**
  - why: Conflating the two makes a viewer off by one. For a single run, snapshot.step == superstep + 1.
  - test: Two turns on one thread: the second turn's first checkpoint must not have step 0.
- **alist's `limit` bounds the WORK, not just the answer: values are detached one yield at a time and the loop returns the moment it has enough. limit <= 0 returns without reading a checkpoint — but the thread id is still validated first.**

  - test: Instrument the copy; alist(limit=2) over 1000 checkpoints must perform 2 copies. alist(limit=0) on a config with no thread_id must still raise.
- **A state that cannot be copied raises a TypeError that NAMES the offending channel and says to pass live handles through config instead.**
  - why: "cannot pickle" alone helps nobody. The failure path is the only place the second walk runs, so finding the culprit costs nothing anybody waits for.
  - test: Put a threading.Lock in a channel; the error message must contain the channel's name.
- **Both artifacts speak the RunEvent wire dialect exactly: one record per line, compact JSON (',' / ':' separators, no spaces), UTF-8, LF, `type` (snake_case) always the FIRST key, `ts` (epoch millis) always the LAST, field names camelCase, a null field OMITTED entirely, non-ASCII emitted raw, flushed per line, file opened in APPEND mode.**

  - test: Byte-compare a produced line against a fixture. Assert key order via a raw-text parse, not a dict comparison.

  - test: A node returning a 40 KB corpus must produce a node_end line under ~300 bytes whose updateKeys preserve the node's dict-literal order.

  - why: That is what lets the two files cross-check each other — a reader sees that `retrieve` wrote 39,021 bytes and that 4,099 of them were recorded. A hint may be approximate; an exception raised while measuring would take the run down for the sake of a hint.
  - test: Clip a channel and assert node_end.updateBytes > the recorded payload size. Feed an object whose __repr__ raises; the run must complete.
- **node_error carries the exception CLASS name in `error` and the message separately in `message`, clipped at MESSAGE_LIMIT=1000 with a trailing ellipsis.**
  - why: A viewer groups by class, so a single "Type: message" string is the wrong shape. A message built by interpolating a document is payload wearing a diagnostic's coat and the same size argument applies.
  - test: Raise ValueError with a 5000-char message; assert error=="ValueError" and len(message)==1001.
- **The topology is complete, stable and computed once. START and END appear as ORDINARY nodes; every conditional target is its own edge tagged kind="conditional" plus the branch name; END is emitted exactly once from its own virtual slot. Order comes from declaration order throughout (START, nodes as declared, END; direct edges as declared, then conditional edges branch by branch) and NO set is ever iterated into the output.**
  - why: A renderer that has to special-case two sentinels will get one of them wrong, and a decision with no arrows reads as a dead end. Artifacts get compared across runs, and a topology that reshuffles itself makes every comparison noise. END arrives in path_map as both key and value in the measured caller, so reading nodes out of the path_maps would duplicate it.
  - test: Build the same graph twice in one process and byte-compare the two topology records.
- **A branch is named after its SOURCE node, never after its path function; a second branch out of the same source becomes "source#2". The topology and the edge_taken records use the same name, and the runtime reads the name back OUT of the topology rather than recomputing it.**
  - why: Path functions are routinely lambdas, so path.__name__ is "<lambda>" and collides the moment a graph has two. One algorithm, in the module that owns the artifact — otherwise the record and the drawing it lights up can disagree about what to call the decision.
  - test: Two conditional edges out of one node; assert the topology names them n and n#2 and that edge_taken carries the matching name.
- **Every way a graph can be undrawable is refused at build time with the offender named and the declared node list printed: an edge endpoint that is not a node, a branch source that is not a node, a path_map target that is not a node, no edge from START, and any node unreachable from START. add_node refuses a non-string/empty name, the reserved START/END names, a duplicate name and a non-callable action eagerly at the call.**
  - why: Each is a drawing with a hole in it. The three add_node refusals are eager because none can be repaired by a later call, and an error at the offending line beats an error at the bottom of the builder function.
  - test: 15 refusal cases, each asserting the offender's name appears in the message.
- **A conditional branch declared without a path_map is legal: its targets are unknowable at compile time, so the topology carries the branch with NO arrows, reachability treats it as reaching every node, and the run still records an edge_taken for wherever it actually goes. A viewer must be able to draw an arrow that is not in the topology.**
  - why: Calling a node unreachable on the strength of a guess would refuse a legal graph. This is the documented price of omitting path_map.
  - test: Compile a graph whose only route to node X is a path_map-less branch; it must compile, and the run must emit an edge_taken to X that has no counterpart in the topology's edge list.
- **A path function's return value is resolved as: dict path_map consulted first; otherwise a value that is already END or a declared node name is honoured even when the map does not mention it; anything else raises a ValueError naming the SOURCE node and listing the known keys. A list/tuple return is a fan-out.**
  - why: The forgiving reading costs nothing. Path functions are routinely lambdas, so their own name says nothing in an error message.
  - test: Return an unmapped-but-valid node name → routes. Return "nonsense" → ValueError containing the source node name and the sorted known keys.
- **The next frontier drops END, collapses duplicates while preserving order, and follows the declaration order of the edges. Conditional edges are evaluated against the state as it stands AFTER the superstep merged.**
  - why: That is the only reading that makes a router's decision reproducible from the artifact: the record holds one merged state per frontier, and the decision that follows was taken on exactly that state. LangGraph's per-node view cannot be reconstructed from the record (kept divergence F8).
  - test: Frontier {a,b} with a conditional edge out of a: the path must observe both a's and b's writes.
- **Value recording is OFF by default, is chosen per compiled graph in one visible line of the caller's own source, and lands in a SEPARATE file (<stem>.state.jsonl). At mode "off" no record is built at all — not built and discarded. The graph artifact REFUSES state_policy/state_payload records and counts the refusal; the state artifact refuses everything else and counts.**
  - why: A library upgrade that quietly starts writing a user's documents to disk is a data incident, and the person it happens to never asked for it. The promise that .graph.jsonl is safe to attach to a bug report is keepable only if the corpus lives somewhere the reporter can decline to send — and "the trace but not our documents" is then one rm, not a filter pass. At off the clipper is never called, so a retrieval node's corpus is never walked.
  - test: compile() with no state= must produce no .state.jsonl and must never invoke the clipper. Hand a state_payload to a GraphArtifact: nothing written, refused == 1.
- **Clipping and redaction happen in the RECORD BUILDER, before any sink sees the record — never in a sink.**
  - why: The sink protocol is Callable[[dict], None] and always will be, so a MultiSink carrying an OTLP exporter, a test's ListSink or a print-to-stderr debug callable would otherwise be handed the raw corpus. A record that reaches a sink is already safe.
  - test: MultiSink(StateArtifact, ListSink) with a 1 MB channel: the ListSink's record must already be clipped.
- **Caps are PER CHANNEL, not one global number, with "*" as the fallback and None denying a channel outright. An int is a byte cap for every string in that channel; a ("sample", keep, bytes) triple additionally cuts a list to its first `keep` elements. An unreadable cap is refused at policy construction, naming the channel.**
  - why: One number gets the most important channel wrong: a 1 KB global cap clips the answer — the product of the run and the value a reader most wants — while leaving the corpus generously served. A cap that quietly meant "no cap" because it was misspelled would write the corpus, silently, which is the one failure mode this layer exists to avoid.
  - test: Global-cap simulation vs table: assert `answer` survives whole at 5,353 bytes while `docs` is sampled. StatePolicy.sample(caps={"docs": "big"}) must raise naming 'docs'.
- **A truncated value NEVER looks like a complete one. A clipped string becomes an object carrying its kind, its true byte and character count, which ceiling fired, and the head; a shortened list says how long it really was and how many were kept; the kept items are the LEADING slice in the node's own order, never a "best" selection. The record also lists the truncated channel names.**
  - why: The house rule "a field we cannot fill truthfully is not added", applied to values. Choosing which items to keep would be a judgement the recorder is not entitled to make — rerank already reordered the list for its own reasons.
  - test: Clip a 10 KB string under a 512 B cap: the recorded value must be a dict with kind/bytes/chars/omitted/head, and the channel name must appear in the record's `truncated` list.
- **When a whole state_payload record exceeds RECORD_CAP (8192), every channel collapses to a marker carrying its TRUE size — the line still exists and still names every channel.**
  - why: A reader loses the values, never the fact that they were written.
  - test: Force the record cap; assert the record still lists every channel and each marker's bytes equals the real channel size.
- **Redaction replaces the WHOLE string when a pattern fires, reports a rule NAME and a coarse length BUCKET (never an exact length), and runs BEFORE clipping. The policy record says redaction:"patterns" and never true.**
  - why: The tail of a key is still a key, and a reader who sees surviving prose around a redaction reads the marker as "the rest is fine" — neither is a claim this pass can support: measured over twelve cases, six of six credential shapes were caught and six of six confidential-prose cases were missed. An exact length is already a recorded open finding against the llm wire; a defect on the books is not repeated. `true` would imply a completeness the measurement disproves. Redacting first is what keeps a head from ending mid-credential.
  - test: A string containing an API key must record only {kind:"redacted", rule:…, bytes:"33-64"}; assert no exact length appears anywhere.
- **The clipper NEVER raises: cycles and depth beyond 32 become an unserializable marker, a non-finite float becomes one, an object whose str() throws becomes one, and the whole call is additionally wrapped.**
  - why: Walking a caller's arbitrary objects means meeting a __str__ that throws, a cycle, or a lazy proxy that hits the network — and observation may never change the outcome of the thing observed. NaN and Infinity dump as bare tokens JSON has no words for, and a reader doing strict parsing would choke on the line.
  - test: Feed a self-referencing dict, float('nan'), and an object whose __str__ raises; each must produce a marker and the run must complete.
- **A state_payload is built from the node's OWN update at its own superstep — not the merged state, not a copy made by the runtime — is emitted AFTER node_end, and a node that wrote no channel gets no line at all. `None` back from the builder means nothing was recordable, and that writes no line rather than an empty one.**
  - why: What a reader needs is what THIS node wrote at THIS superstep, before a reducer folded a sibling's write in beside it. Copying an update is O(corpus) per node. An empty `channels` object would read as "the node wrote nothing", which is a different fact and is already told by node_end.updateKeys.
  - test: Two files joined on (runId, node, superstep). A node returning {} must produce a node_end and no state_payload.
- **Exactly one state_policy record is emitted per run, immediately after graph_start, and the policy is read ONCE there and carried down to every node of that run.**
  - why: Without it, a channel missing from a payload is ambiguous between "the node did not write it", "the policy denied it" and "the recorder failed". The artifact is append-mode, so a reader meeting a payload has to find the policy of THAT run above it. Carried rather than re-read because a run that announced `summary` and then recorded something else would make its own policy record a lie.
  - test: Mutate graph.state_policy mid-run; every payload of that run must still obey the announced tier.
- **Policy gating is one function asked once per channel: naming a channel in `allowed` overrides the deny list; otherwise a denied channel is refused; otherwise only sample and full record it. summary is allow-list-only. `principal` is denied by default. full() requires acknowledged=True.**
  - why: The answer cannot be allowed to differ between the record and the policy line that explains the record. summary's promise is "no documents", so a caller whose state uses different words gets nothing until it says which words — the safe way round. principal carries identity data, which is not observability data. full measures 102.64 % of the state it observes (216 KB/turn, 2.1 MB per ten-turn thread), and a caller who reaches that by tab-completing a mode name has not made the decision the mode represents.
  - test: StatePolicy.full() without acknowledged must raise. summary must record nothing for an unnamed channel. sample must skip `principal` unless it is in allow.
- **Reading is tolerant in exactly one direction: blank, torn and non-object lines are dropped without a word, but a MISSING artifact file raises. The FIRST graph_topology is the topology; a later one stays in the records.**
  - why: The common cause of a torn line is a crash and the reader's job is to show what survived; an artifact that was never written is a different problem from one that is empty. A re-ingest that rebuilt the graph must be visible as a shape change rather than silently read as the wrong drawing.
  - test: Append garbage mid-file and assert the surrounding records still parse; read a nonexistent path and assert it raises; write two topologies and assert the second appears in records.
- **The custom-chunk queue is UNBOUNDED, and crossing a depth of 10,000 unread chunks warns exactly once per writer, stating that nothing was dropped and that the queue will grow with memory.**
  - why: The alternatives are dropping a token or blocking a worker thread, and a token stream with a hole in it is worse than a slow one. Ordering and completeness are the property: 20,000 of 20,000 chunks arrive in order from both an async and a sync node. The price is that a stalled consumer lets a chatty node grow it, and that must be reported rather than invisible.
  - test: Stall the consumer and write 20,001 chunks: exactly one warning, all chunks arrive in order.
- **A sink is any callable taking a record dict — that is the entire protocol. `topology()` on a sink is sugar that builds the record and passes it through the same call path, so a sink implementing only the call still receives the topology. The topology is handed to the sink in the CONSTRUCTOR of the compiled graph, before any node has run.**
  - why: An exporter is a function until it needs to be more; no exporter should ever need the runtime to learn a second word for "sink". Handing the topology over at compile time is what puts the drawing in the file before the light — the property this package exists for.
  - test: A bare lambda as sink must receive the graph_topology record at compile() time, before ainvoke is called.

### Traps

- **`typing.Annotated` has no Java analogue and the reducer-discovery rule does not survive the port.** `resolve_reducers` reads `get_type_hints(schema, include_extras=True)` and takes the LAST metadata entry if callable. Java has no per-field metadata list with ordering semantics — an annotation is not a list you can put a lambda in. A port needs an explicit channel registry (`Channels.reducer("trace", List::concat)`) or an annotation naming a reducer class. Keep the SEMANTIC rule (which channels merge vs overwrite, seeding on absent/null, arity refused at build time); drop the metadata-position rule entirely — it exists only to match a Python library's introspection.
- **`_wants_config` decides config injection by PARAMETER NAME via `inspect.signature`.** Java does not have reliable runtime parameter names (needs `-parameters`, and it is fragile). Do NOT port this by reflection. Use type-based dispatch: two functional interfaces, `Node` (state → update) and `ConfigNode` (state, config → update), overloaded on `addNode`. That is stronger than the Python rule and removes the whole 12-shape measurement — but you then lose the permissive divergence, so document that a Java node declares its config need in its type.
- **The sync/async duality and everything built around it is Python-only.** `_is_async`, `_call`'s `run_in_executor`, `_sync_pool`, `SYNC_WORKER_LIMIT`, `SYNC_THREAD_PREFIX`, the "one pool for the package, not per compiled graph" reasoning — all of it exists because blocking the event loop stalls the frontier and the stream draining beside it. With virtual threads there is one kind of node and the pool disappears. But do NOT conclude that cancellation is solved: a virtual thread is no more killable than an OS thread, `Thread.interrupt()` is cooperative, and a node in a blocking JDBC or HTTP call ignores it. **Keep the honest artifact record** — the "this node may still be running" message is still the truth in Java. What you can drop is the separate pool (the blast-radius argument) and `_cancellation`'s async/sync branch (in Java, every node is the "sync" case unless it cooperates).
- **`contextvars.ContextVar` → `ScopedValue`, but the copy semantics differ in a load-bearing way.** contextvars copy at TASK CREATION: a value set in the parent after the tasks exist reaches nobody, which is why `_invoke_node` sets the writer INSIDE the node coroutine and why `_with_writer` runs on a freshly created task so the binding cannot leak back out (an async generator shares the context of whoever iterates it, and `get_stream_writer()` outside a run must keep raising). ScopedValue binds for a dynamic scope and is inherited by forked subtasks under structured concurrency — closer to what you want, but the "must raise outside a run" property now depends on the binding being torn down at scope exit rather than on a copy boundary. Get this wrong and `get_stream_writer()` starts returning a stale writer outside a run instead of throwing, which is the exact failure the Python code contorts itself to avoid.
- **`copy.deepcopy` for checkpoint isolation is the single hardest thing to port, and the naive Java answer is measurably wrong.** The docstring benchmarks four strategies and picks deepcopy *because it shares immutable leaves*: a 680 KiB corpus costs 371 KiB per checkpoint (the dict-and-list spine only) since every character of chunk text stays one shared object. A Jackson/serialization round-trip is the pickle row — 3x the memory (1154 KiB) — and that is the obvious Java reflex. Options: require channel values to be immutable (persistent collections, records) and copy only the spine; or use a structural-sharing map. Also note the pinned detail that the copy is taken from the mapping AS IT STANDS, not through a fresh top-level dict — rebuilding the top level first leaves a self-referential state pointing at the ORIGINAL mapping and the deep copy faithfully preserves that wrong shape.
- **Async generators, `aclosing`, and the `carrier` list are pure Python plumbing.** `astream` is a plain `def` returning an async generator specifically so callers can write `async for ... in graph.astream(...)` with no await; `_phase` uses a one-element list because an async generator cannot return a value; `aclosing` exists because a consumer breaking out of the stream closes only the outer generator and the engine underneath would otherwise wait for the GC while its half-finished superstep kept running. In Java this becomes a `Flow.Publisher` or a closeable `Iterator` on a virtual thread. **What must survive is the cleanup contract**: closing the stream must cancel the in-flight phase, await it, and retire the writer — deterministically, not at finalization.
- **The exception hierarchy's whole rationale evaporates in Java.** `GraphValidationError(ValueError)`, `GraphRecursionError(RecursionError)`, `MissingCheckpointerError(ValueError)`, `InvalidUpdateError`, `InvalidReducerError` all subclass what LangGraph raises so that an existing `except ValueError` around `compile()` keeps working. There is no Java LangGraph to be a drop-in for. Do NOT mechanically map RecursionError→StackOverflowError (wrong: it is a run-length limit, not a stack condition) or ValueError→IllegalArgumentException just to preserve the shape. Design a clean hierarchy; keep only the property that the MESSAGES name the offender.
- **Dict insertion order is load-bearing in at least six places and Java will silently lose it.** Frontier dedup uses `dict.fromkeys`; `updateKeys` is the node's own key order and explicitly NOT sorted; the topology's stability guarantee says no set is ever iterated into the output; `_record` builds keys in declared order with `type` first and `ts` last; `state_payload.channels` follows the update's order; `DEFAULT_ALLOW` is ordered because it is the reading order a panel shows. Use `LinkedHashMap`/`LinkedHashSet` everywhere and pin it with a byte-comparison test, because a `HashMap` here produces output that is correct-looking and non-reproducible.
- **`"from"` is a keyword in both languages, and the WIRE key is `from`.** Python works around it with `**{"from": from_}`; Java needs `@JsonProperty("from")`. Getting this wrong produces a valid-looking artifact no existing viewer can read.
- **Two clocks, deliberately.** `ts` is `time.time()*1000` (wall clock, epoch millis, for interleaving with the RunEvent wire) while every duration is `time.perf_counter()` (monotonic). Java: `System.currentTimeMillis()` and `System.nanoTime()`. Using one for both breaks either the file join or the durations under NTP adjustment.
- **Node inputs are a SHALLOW copy (`dict(state)`), not a deep one.** The docstring is precise about what that buys — "a node that writes into the mapping it was handed is a bug, but it must not become a sibling's wrong answer" — but nested mutation still leaks between siblings in the same superstep. Only the checkpointer deep-copies. Do not "fix" this in the port without measuring: the L2 design explicitly refuses O(corpus) copying per node, and isolating node inputs is named as the prerequisite for a future optimization (sharing untouched channels between checkpoints), not as a done deal.
- **The `updates` stream chunk yields the node's ACTUAL returned dict, unwrapped and uncopied**, while `values` chunks are shallow copies (`dict(state)`). A consumer that mutates an updates chunk reaches the node's own object. Same class of sharp edge as §9.13: the config a node receives is the caller's own dict, uncopied, so a node that mutates its config mutates the caller's. Both are written down rather than fixed; a Java port should decide deliberately rather than inherit them by accident.
- **`artifacts()` attaches `state_policy` as a dynamic attribute on the returned sink instance.** That is monkeypatching an attribute onto an object, and `_resolve_state_policy` reads it with `getattr(sink, "state_policy", None)`. Java needs a real interface (`PolicyCarryingSink`) or a compile-time parameter. The BEHAVIOUR to preserve: naming a tier at `artifacts(path, state=…)` alone is enough, because that call already opens the payload file and a runtime that then recorded nothing would leave a zero-byte `.state.jsonl` — indistinguishable from "this run recorded nothing" to every reader there is. `compile(state=…)` wins when both are given.
- **`_resolve_state_policy` refuses the CLASS `StatePolicy` with a TypeError**, because its `mode` field carries a class-level default of `"off"` — so `state=StatePolicy` with the tier call forgotten would read as a perfectly valid request to record nothing and the caller would go hunting for their missing file. A Java port with a static/singleton default policy reintroduces exactly this trap.
- **Depth and cycle detection in the clipper uses `id(value) in seen` with a frozenset of ids.** Java needs an `IdentityHashMap`-backed set; a `HashSet` calls `equals`/`hashCode` on the caller's arbitrary objects, which is precisely the code the clipper promises never to trigger (a `__str__` that throws, a lazy proxy that hits the network). The `_MAX_DEPTH = 32` ceiling and the never-raises guarantee both have to hold.
- **`_clip_value` passes the SAME `max_items` down recursively**, so a nested list inside a sampled channel is also cut to `keep`. That is a real semantic detail, not an accident of the recursion, and a port that applies the item cap only at the top level will record more than the policy promised.
- **Non-finite floats must become markers.** Python's `json.dumps` emits bare `NaN`/`Infinity` tokens; Jackson does the same by default. Strict readers choke. The clipper already handles it (`math.isfinite`), but `_bytes_of` and the artifact writers do not — configure the Java serializer explicitly rather than assuming.
- **`MemorySaver = InMemorySaver` and the whole `compat/langgraph/` shim are Python-only.** Both spellings must resolve to the SAME class (applications write `from ... import MemorySaver as InMemorySaver` in try/except fallbacks and would otherwise get two types that can drift). None of this has a Java counterpart — drop it, and drop the `compat/README.md` swap machinery with it.
- **`warnings.warn` is wrapped in a bare `except: pass`** because under `-W error` a warning becomes an exception and an exception raised while reporting a diagnostic would do exactly the damage the diagnostic exists to prevent. Java's logger will not throw the same way, but keep the principle: the reporting of a problem must never become the problem. Keep the warn-once-then-count behaviour verbatim — it is a chosen policy, not a default.
- **`threading.Lock` in `InMemorySaver` is a deliberate choice against `asyncio.Lock`, and the reasoning is void in Java** — but read it anyway, because the property it protects is not: no critical section awaits, the lock is never held across a suspension point or a yield (holding it across a yield in `alist` would deadlock any consumer that writes while it reads), and the expensive copy happens OUTSIDE the lock. Those three hold in Java too.
- **`snapshot.step` and `record["superstep"]` are different counters and a viewer that conflates them is off by one.** superstep is 0-based and numbers the frontiers of one run; step numbers a thread's history, the saver assigns it, and a second turn continues the series. For a single run, `snapshot.step == superstep + 1`. The runtime deliberately does not pass its step to `aput`.
- **`edge_taken.superstep` is the step the edge leads INTO, not the step it left from.** Off-by-one in the other direction from the previous trap, in the same file, one record type apart.
- **`StateSnapshot` is intentionally missing `tasks` and carries `interrupts=()` always.** Do not "complete" it in the port. `tasks=()` would read "nothing is pending" on exactly the snapshots where something is; an AttributeError says less but says it truthfully. `interrupts` exists only so a defensive `if snapshot.interrupts:` reads correctly. Both are out-of-scope features (human-in-the-loop, subgraphs), and adding empty fields advertises what is not there.
- **`compile()` imports `runtime` locally to break a module cycle** (runtime needs `build_topology`, graph needs `CompiledGraph`). Java has no import cycle problem at this level, so the local import vanishes — but the DEPENDENCY DIRECTION it encodes is still the design: the builder is deliberately dumb about execution and knows nothing about supersteps, reducers or stream chunks. Preserve that split when laying out packages.
- **`_sibling_path` is idempotent across the whole suffix FAMILY**, not just its own suffix: `artifacts("run.graph.jsonl")` must still write payloads to `run.state.jsonl`, not `run.graph.state.jsonl`. Easy to reimplement as a naive `endsWith` check and get subtly wrong.
- **`load_state_payloads` keys on `(runId, node, superstep)` and a repeat overwrites its earlier self.** Superstep is in the key because a node can enter twice in one run (a graph that sends `generate` back after `verify`), and a reader joining on node name alone shows the second turn's values under the first turn's node.
- **The documented, deliberately unfixed limitations are worth reading before you "improve" them:** the sink is called synchronously on the loop thread (measured 12.6 ms over six records at 5 ms per write) and making it async would change the seam every exporter is written against — a slow sink should buffer; the custom queue stays unbounded; and the node config is the caller's own uncopied dict. All three are in GRAPH-CONTRACT §9.9–§9.13 with the measurement that decided them.

## Visual structure of docs/graph-view-reference/graphview.html (the standalone deterministic graph view), for a pixel-faithful React Flow rebuild

graphview.html is a single self-contained page (2281 lines, no CDN, no build, no network) that draws a declared StateGraph topology first and then lights it up by folding an event stream over it. Its shell is a four-row CSS grid — header, transport bar with a spectral timeline ribbon, a stage split into SVG canvas plus a 306px right panel, and a footer status strip. Everything is hand-rolled SVG: a layered layout (rank = longest path from START over forward edges only) places fixed 140x66 node cards on a per-(rank, slot) grid so boxes provably cannot collide, and three distinct edge routings (straight/curved connector, cycle-return arc bowed below/right, rank-skipping arc bowed above/left) keep every path in provably empty space. dagre is deliberately absent because it breaks cycles by reversing edges, destroying the loop the view exists to show. Colour appears only on strokes and lines — node faces, panel surfaces and text are neutral; the four lifecycle states (pending/active/done/error) are carried by the box stroke, and the ribbon's per-record tick colour is the only other spectral element. The page ships an embedded CRAG fixture plus its companion state artifact and loads both through the same parser a dropped file takes. Two console guards, `__gvCheck` and `__gvStateCheck`, assert no overlaps, no off-boundary endpoints, no edges crossing foreign boxes, and that the payload file actually joined.

### Traps

- React Flow measures nodes and lets them size themselves; this layout's non-overlap guarantee comes from every node being exactly 140x66 on a fixed (rank, slot) cell. Any node type whose height varies with content silently voids the guarantee and __gvCheck().overlaps stops being empty.
- Do not reach for dagre or elk. layoutDagre returns positions only, and dagre breaks cycles by REVERSING edges — that destroys the correction loop the whole view exists to show. The hand-rolled pass is ~150 lines and is the feature, not an optimisation.
- Edge keys use U+2192 '→', not '->'. A port that normalises to ASCII will break every state.edges lookup while still rendering a plausible-looking graph with zero taken edges.
- Back-edge and skip-arc routing cannot be expressed with React Flow's built-in edge types. Both need a custom edge whose path comes from the layout pass (the 6-point gutter/lane polyline with 18px rounded corners), because the lane offset depends on the whole node field's bounding box and on a per-arc index, neither of which a per-edge renderer can know.
- The arc SIDE is semantic: below (horizontal) / right (vertical) means cycle return, above / left means rank skip. Flipping one for aesthetic balance makes the legend's last two rows lie.
- In horizontal orientation a back edge leaves the source's LEFT edge (sx = a.x) and enters the target's LEFT edge (b.x) — not the intuitive right-to-left. Getting this wrong puts the arc's first segment straight through the source box.
- paper hard-codes --gv-pending: #a39e92 instead of inheriting var(--border-strong). A port that only remaps the base ramp gets pending nodes at #c4bcad in light mode, visibly too pale.
- --ev-token / --ev-tool / --ev-gate / --ev-subagent / --ev-lifecycle / --ev-pending are declared but never consumed (0 var() references). The ribbon's record colours point at --sp-* directly. Wiring the ribbon to the --ev-* names looks like a cleanup and changes nothing today, but it re-points the page at a vocabulary whose semantics (token/tool/gate) do not match graph records.
- The ribbon's tick positions are inset by half a slider-thumb width computed from the element's MEASURED pixel width. Skipping that inset makes the playhead drift off its own record at both ends of the timeline; skipping the ResizeObserver leaves the ribbon built against a stale width after any pane resize.
- The chase animation depends on an inline per-element --gv-perim custom property and a dasharray derived from the node's own perimeter. A CSS-in-JS port that hoists the keyframe but drops the per-node property falls back to the -400 default and the ring visibly stutters on any node that is not ~140x66.
- 'wrote' and 'recorded' are two different measured numbers from two different files, and 'nothing was written' / 'nothing was recorded' / 'no file loaded' / 'policy said off' are four different sentences. Collapsing any of them into one empty box destroys the only reason the state layer exists.
- recordBytes reads the raw on-disk line length captured at parse time (__bytes), not JSON.stringify of the parsed object. Re-serialising produces a different number — key order, whitespace and escape choices all move — and turns a measured claim into a false one.
- The payload section must be built with createElement/textContent. It renders the caller's own corpus; an innerHTML port hands every loaded file an XSS.
- markerKind checks companion fields, not `kind` alone. A port that switches on value.kind will print a fabricated truncation for any user channel that happens to be an object with a `kind` key.
