# spectroscope 0.11.0

> **DRAFT, the cut is not made.** Every section now describes work that is in
> `main` and gated. The date and the merge count are the only blanks left.

Released 2026-__-__, __ merges after 0.10.0.

Most of this release is one surface. The lab, the place a run is watched, was
rebuilt around actually being read. Around that sit two features that needed
the rebuild: a recorded session folder now comes back as the whole run, with
its children and its workflows, and a declared workflow draws itself as the
plan it was.

Then a llama.cpp server became a provider you can pick, and the four defects
0.10.0 shipped with are fixed.

---

## Recorded runs come back whole

Until now you handed the app one `.jsonl` file and got one agent's transcript.
A real Claude Code session is not one file. It is a session stream plus a
`subagents/` folder holding one stream and one metadata file per child, and the
join between them, meaning which child came out of which tool call, was left
open.

Now you hand it the folder. The app finds the session stream, finds the
children, joins each child to the tool call that spawned it, merges everything
onto one clock, and reads the workspace out of the recording. The join key is
the child's own recorded tool call: on the session this was measured against,
it resolved 9 children out of 9. A lone `.jsonl` still behaves exactly as
before.

Workflow runs come along too, and before this they did not come along at all.
A session that had farmed work out to workflows imported nothing: the folder
was refused outright, and every agent a workflow had spawned was dropped by the
join meant to fetch it. A workflow child is simply not attributed the way a
Task child is. A Task child names its parent tool call in its own metadata,
while a workflow child is identified by the directory it sits in. There is one
attribution rule per spawn kind now, instead of one key stretched over both.

And a loaded agent is now listed as an agent. The work panel used to file the
run's own children under external files, next to the documents the run had
happened to open.

One more thing had to be fixed for an import to come back whole: the phases a
workflow declared were being read out of the recording and then dropped on the
way into the app, so an imported workflow drew only what could be reconstructed
afterwards. The declaration arrives now. This was invisible for as long as it
was, because the scenarios in the app take a different path into the lab and
were the only thing anyone had looked at the box with.

## The map got rebuilt around being read

The lab's system map is where a replayed run is watched, and most of this
release is in it.

It seats the fleet the harness actually runs. The harness runs four children in
parallel and more over the length of a run, while the map sliced at three.
Worker cards were also a fixed 408x560 scaled to 0.6, so from the fourth worker
on, the 11px line under each name painted at roughly 2 device pixels: present,
and unreadable. Workers are a grid now, and eight in parallel was the floor the
work had to clear.

Seats say what was concurrent rather than who ever lived. They used to be
indexed by lifetime, so a run whose peak concurrency was five got nine chairs,
a history drawn as a present state. A child now takes a free seat when it
appears, keeps it while it lives, and frees it when it ends. It still never
jumps seats.

The grid also fills the pane it has. The fit zoom used to fall off a cliff at
the fourth worker (0.406 to 0.307) and stay flat all the way to twelve, because
the expanded grid stacked a constant four rows no matter what pane it was
given. Rows come from the seat count and the pane's shape now.

And the seat stopped reserving twice the card. A worker seat held 620 world px
for a card that measures between about 238 and 304. At five children on a
1920x1080 pane that painted roughly 172 device px of card with about 178 device
px of empty room under it: more gap than card, exactly as reported.

**The stations stopped going dark.** The band along the bottom is the half of
the picture that says what the machine is doing, and from the permission prompt
onward it said nothing at all. Not for a gated write, not for a gated command,
not for the main agent and not for any child. There is one derivation of who is
standing on a station now, so the lit node, the name chip and the hot rail
cannot disagree with each other, and a busy station breathes in the colour of
whoever is on it. Children's rails into the band are drawn permanently, the way
the main agent's always were.

Every agent also carries a handle: `main`, then `w1`, `w2` and so on in the
order they first appear, one colour each, folded out of the events so that it
survives scrubbing. No panel derives its own naming any more, and the three
panels that join on the handle today did not have to invent a scheme on the way
in.

The LLM is always outside the machine now. The map used to have two layouts,
chosen once at startup by whether the provider was local, and that distinction
had stopped being true. The model hangs behind the agents either way, and a
local Ollama happily serves cloud models. There is one geometry, and the same
simplification reached the fleet and spectrum surfaces, which had inherited the
same dead bit.

The colour shimmer moved behind the card, so only the rim breathes instead of
the whole panel glowing.

## The workflow draws itself as the plan

A workflow run is a hybrid, and its two halves have different birthdays. Its
phases are declared: they exist in the script before a token flows. Its
occupancy is executed, and knowable only afterwards.

So a workflow is drawn in the solid visual language the state graph uses, and a
recovered spawn tree stays dashed. Solid means declared before the run. Dashed
means reconstructed from what happened. The legend says it once.

The phase is the node. An earlier attempt threw one arc per agent out of the
root, which read as a firework rather than as a plan. The phases are the boxes
now, each leading to the next, with every agent standing inside the phase it
belongs to, so a fan-out of five reads as one phase holding five. A phase
nobody reached is still visibly a phase somebody promised.

It also lives inside the lab rather than in a view of its own. A running
workflow gets a box on the map, where the agents are, holding its own agents
lined up along its flow with the phases visibly separated. Several workflows
means several boxes. A switch decides whether the agents inside a box are drawn
minimal or expanded, and a box may grow large, because you can zoom.

The layout engine underneath had to learn per-node sizes and a real vertical
path to make this possible. The state graph's own face did not move.

A recording of exactly this is in the repository, under `docs/sample-runs/`, so
the picture above is something you can load rather than something you take on
faith. It is generated from the scenario the app already ships, and a test
holds the file byte-identical to what that scenario compiles to today.

## The run explains itself, if you ask it to

An imported run can be handed to a model for a one-shot reading: a summary of
the run, plus a sentence or two per agent.

Nothing runs at import. The affordance opens a consent step that names, before
anything leaves the machine, the provider, the model, and the address it will
talk to, and says that the run's transcript content is what gets sent. A
loopback address adds the line that the content stays here. One click is one
analysis, and asking again costs another click.

What comes back is labelled as the model's reading, not as a measurement. It
lives in app state and is not written to disk in this release.

## Finding the moment in a long run

The scrub bar marks what happened. Under the scrubber there are ticks for
eleven kinds of moment: turns, spawns, compactions, permission gates, refusals,
stalls, interventions, questions, skills, errors and the end. They are read
straight off the stream the scrubber already walks, and each tick is a control
that seeks there. The bar used to carry three different readings of where am I,
which is the question nobody has over the several hundred coarse steps a real
run produces, and nothing that answered where is the interesting part.

The lab also grew a dock on its right edge. Its first panel says how full each
agent's context got, and says what that number is a share of before it says how
big it is. It shares its divisor with the header ring, so the two surfaces can
no longer print two different percentages for one run.

The handovers read as a conversation and the paths read as a receipt. Who
tasked whom is drawn from the run's own spawn frames, and every row on both
panels is one click from the line that recorded it. A handover had reached the
lab twice before this and been readable in neither place: once as a row in the
JSONL strip carrying raw agent ids and a 40-character preview, once as a card
moving on the map. This is also the first per-agent reading of what a replayed
run did to disk. The live workspace browser answers what is in a folder now,
which is a different question, and no question at all for an import.

## The run's self-reports have faces now

0.10.0 gave a run three ways to report on itself and left all three mute in the
app: the loop guard that notices when nothing is moving, the leash, the goal
check and the turn cap. The defect that produced the guard is worth naming: a
local model wrote the same file 31 times in one run. The release notes claimed
the run reports on itself, and in the app it reported roughly a third of
itself.

All of them speak now, in the same place and the same way, in both languages,
and the loop guard's three numbers are settings you can find and change.

## A llama.cpp server is a provider you can pick

If you run `llama-server` directly rather than through Ollama or LM Studio, it
is its own choice in the provider list now, with its own address field.

This is not relabelling. The dialects differ in a way that matters: under the
LM Studio label, turning thinking off sent nothing at all, so the switch was a
no-op against a llama.cpp server. On its own dialect the request carries what
llama.cpp actually reads.

The app also says when it is ignoring an address you typed. Each provider has
its own address field, and that field silently wins over the general one. If
you had typed your server's address into the general field and then picked a
provider that has one of its own, the app quietly talked somewhere else. It
names the field that won, and the field that lost.

## Fixed

- A tool that takes no arguments no longer kills the run on Anthropic. A
  parameterless tool call is an ordinary thing for a model to make, and it was
  fatal.
- A resumed session works in the folder it resumed. It used to keep the
  transcript and swap the tree underneath it, and the run that surfaced this
  was in automatic permission mode, so a file the agent decided to change would
  have been changed in a folder nobody chose.
- A refusal is not a crash. A correct refusal was drawn in the same red box as
  a hard error, offered *Send again*, and left no trace in the transcript
  afterwards. It says what was not allowed and where it belongs now, and the
  reason is still there tomorrow.
- A port that answers is not the process we started. Starting an app whose port
  was already taken handed the agent a stranger's server. It fails honestly
  now, carrying the command's own message.

## Known limits

- The desktop kit is built for the host architecture only. electron-builder,
  the bundled JRE and the llama-server binaries are all OS and arch specific,
  and the pinned llama sha256 is the arm64 asset. Other platforms need their
  own build.
- Notarized only from the release machine. Without a Developer ID and the
  notary profile the build falls back to ad-hoc signing, and macOS then shows
  *unidentified developer*. Right-click, Open, once, or `xattr -cr`.
- The model's reading is not saved. It lives in app state for the session, so
  re-opening the run means asking again. A sidecar file for it is a later
  change.
- The workflow box does not yet move the furniture around it. When a box is
  present the surrounding map keeps its fixed positions instead of deriving
  them from what is running.
- A guide figure still names three of the eight providers as though they were
  the whole picker list. It is a diagram that predates several of them.
- The apt pool is behind. It last published 0.7.0, and neither 0.8.0 nor 0.10.0
  entered it. Whether 0.11.0 does, and whether the gap gets filled, is a
  decision for the cut and not a defect of this build.

## Getting it

The channels are the ones 0.5.0 shipped. Nothing new this cut.

**Homebrew, on macOS.** `brew install --cask spectroscope/tap/spectroscope`
installs the signed and notarized desktop kit.

**The macOS disk image.** `spectroscope-0.11.0-arm64.dmg` on the release page.
Signed, notarized, and carrying its own Java runtime and `llama-server`. Apple
silicon only.

**apt, on Debian and Ubuntu.** The signed repository at
`https://apt.spectroscope.dev` serves the deb. Note that the pool currently
publishes 0.7.0: neither 0.8.0 nor 0.10.0 entered it, so `apt upgrade` does not
carry you here yet. x86_64 only.

If nobody is at the keyboard, use
`sudo DEBIAN_FRONTEND=noninteractive apt install -y spectroscope` instead of the
documented line. The plain line waits for you twice, and in a container neither
question is answered: apt asks you to confirm the download, and on an image
where `tzdata` has never been configured a package further down the chain asks
which timezone you live in. Neither one times out.

**The Linux kit.** `spectroscope-0.11.0-x86_64.AppImage` and
`spectroscope_0.11.0_amd64.deb` on the release page, built and smoke-tested on
Linux by this project's own CI. Both bundle their own Java runtime and
`llama-server`. x86_64 only, not signed.

**The jar and the CLI.** `spectro-server-0.11.0.jar` and `spectro-0.11.0.zip`
run on any machine with Java 21. They are the smallest way in, and the only way
onto a platform that has no kit.

**In your own code.**

```
dev.spectroscope:spectro-core:0.11.0
dev.spectroscope:spectro-orchestrator:0.11.0
```

Maven Central is append-only, and 0.9.0's libraries were never published there,
so on Central this release follows 0.10.0 and the gap where 0.9.0 would sit
stays visible. If the coordinates above answer 404 for you, the publish has not
propagated yet.
