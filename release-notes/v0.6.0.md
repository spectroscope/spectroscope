# spectroscope 0.6.0

Released 2026-08-04. This release is about reading a session that another tool
recorded, all the way down to the bytes it came from; about the browser's back
button finally working; a link from a session to its Langfuse trace; a spectrum
you can zoom into; and an upgrade that can no longer greet you with a blank
window.

## An imported session, down to the file's own bytes

The trace has five faces now: Structured, Insight, Compact, Wire and Source.
The face that used to be called Raw is called Wire, because what it paints is
spectroscope's wire format. The word Raw promised the original file over a pane
showing a reconstruction, and for an imported session that promise was false.
Source is the new fifth face, and it keeps it: every frame that came from a
line of the file carries that line, byte for byte.

- The carried line is proven, not assumed: measured across 140 real Claude Code
  transcripts, 856,486,192 bytes of line content came through with zero
  mismatches, and the identity tests compare buffers against bytes cut on the
  newline rather than reusing the importer's own splitting.
- The line number in the Source pane is the one an editor shows. Blank lines
  count, a trailing newline does not.
- The pane shows at most 65,536 characters and names both numbers when it cuts.
  Copying always takes the whole line.
- Beside the bytes sits a Readable view, and it opens first, an owner call:
  the verbatim form is unreadable at a glance. The strip above the pane names
  which reading is showing, the copy button says what it hands over, and the
  choice lives only in the session, never persisted, so it cannot follow you
  into another file. Readable's only unescape is another JSON parse, because a
  blind string replace was tried against real transcripts and rewrote a shell
  command mid line. What it collapses it never drops: the placeholder names
  the field, counts the characters, opens on a click, and the clipboard still
  carries the whole value.
- Compact wraps and Wire scrolls. Same text, two readings, so the two names
  finally mean two different things.
- A frame the importer built itself says so, and a frame whose line the file
  does not have says that, instead of being passed off as either.

The carried line turned out to hold readings the trace had been ignoring:

- Each imported run now closes on the stop reason the file recorded, main agent
  and every subagent separately. A run that hit `max_tokens` is visible as a
  truncated answer; a file that recorded no reason says `unrecorded` instead of
  inventing an ending.
- A cut-off turn says so on its own row, not only in the `run_end` at the
  bottom.
- Where the file recorded the reasoning effort a turn was told to spend, a chip
  on the row shows it. Absent means absent.
- A user turn that a machine wrote (a task notification, a coordinator
  injection) is labelled with the writer's own name. The chip stays silent for
  a human, deliberately, because half the corpus predates the field and an
  absent chip must never read as a claim that a person typed it.
- A model swapped mid-session by fallback is named on the row with both ends:
  the model that was left and the one that answered.
- An imported todo list reads as a list. The row counts open, running and done;
  opened, it draws the items with their statuses, numbered by the file's own
  ids. An item the renderer cannot draw faithfully sends the whole frame back
  to its JSON.

The import dialog got honest about limits:

- A transcript larger than the server will read is marked in the listing and
  cannot be clicked, instead of answering a bare 413 after the click. The
  ceiling is 128 MiB, raised from 64 because the content read now streams
  instead of holding the whole file in memory.
- A transcript is imported whole or not at all. There is no partial import,
  because a transcript that begins in the middle has lost the part that says
  how the incident started.
- The listing shows at most 300 transcripts and says when older ones were
  hidden, naming the number it shows rather than the number it hid.

And the export sheet stopped claiming completeness it did not have: it counts
the frames that were read around the conversation and the socket-only frames
the app built for its own screen as two separate rows, so "nothing is lost" is
never printed over a file with fewer lines than the screen showed.

One number on screen was plainly wrong: the context ring dropped `claude-fable`
models into a legacy 200k row and read 379 percent, in red, on a healthy
imported session. It now knows the 1M context window that model family actually
has.

## The address bar learns the app

The app used to be one URL. Now a place in the app is an address, and the
browser's back and forward buttons walk your real history.

- `#/{tab}` names each of the six view tabs. `#/session/{id}` opens a session,
  `#/session/{id}@{n}` lands on an event, `#/session/{id}/{tab}` opens a
  session on a specific tab. `#/fleet/{id}` enters a fleet. `#/settings` and
  `#/settings/{section}` open Settings and its eight sections.
- A real gesture pushes one history entry; following a live session or booting
  only ever replaces. Back from `#/session/x/trace` to `#/session/x` is a tab
  flip, measured at zero additional event fetches, and the loaded session
  stays as it was.
- The old receipt links (`#/session/{id}@{n}`) resolve unchanged.
- An unknown route falls through to the default view without a console error.
- A replay is a view, not an address: scenario and import views write `#/` and
  cannot be deep-linked, on purpose.
- Opening a link persists no settings and nothing route-specific. Every route
  was walked against a fresh home and the home byte-compared afterwards:
  `settings.json` was never even created, and the only file that changed was
  `leveling.json`, carrying the same observation marks a hand click writes.

That last rule closed a real defect. Opening the Settings panel used to
auto-pick a model and persist it: a configured model absent from the provider's
fetched list was silently replaced by the list's first entry, by the act of
looking. Settings no longer writes on open. A configured model the provider's
list does not contain stays configured and says so, under the field: not in
this provider's model list, your setting is kept. An empty list writes nothing.
The provider picker's own auto-pick, which is a chooser and may pick, is
unchanged.

One more piece of navigation housekeeping: the trace's agent filter now belongs
to the session it was pinned in. Before, a filter pinned in a fleet-shaped
session rode along into the next session you opened, where the chip row that
clears it hides itself for a single-agent stream; measured on a real store,
that walk showed 2 of 1576 rows with nothing on screen naming the cause. The
pin now clears whenever the shown stream changes.

## A session links to its Langfuse trace

If you export to Langfuse, the trace tab now carries a link straight to the
session's trace there.

- The trace id is computed, never stored: it is a SHA-256 of the session id,
  which is how the exporter names traces, recomputed in the browser. The link
  is derived from the export frame's own endpoint, not from Settings, because
  Settings can be edited after an export.
- The link appears only after an export has landed. Before the first export
  there is nothing; a failed export shows a plain "otlp export failed" instead
  of a link that would 404.
- The link exists only when the endpoint is Langfuse. A Jaeger endpoint gets no
  link rather than a wrong one.
- It opens in your real browser. An inline Langfuse tab was measured and
  refused: Langfuse ships `frame-ancestors 'none'` as a string literal in its
  own build, so framing it is not a setting, and a header-stripping proxy would
  present someone else's app as our own origin, which is the exact claim that
  header exists to deny. The verdict and the measurement are recorded in
  `docs/OBSERVABILITY.md`.
- The link is live-session only in this release. An archived session opened
  from the list shows no link even when its trace exists, because the export
  frame never reaches the session file.

Settings can now tell you where Docker actually stands: not installed,
installed but not answering, ready, or pointed at a remote daemon. A socket
that refuses you reports "not answering" rather than "not installed", whether
or not we found the docker executable, because "not installed" sends someone to
re-download software they already have. The probe is a read of the Docker
socket and starts nothing: the container set was byte-identical before and
after, with zero child processes spawned.

`samples/06-langfuse/` now ships the stack instead of describing it: a
`docker-compose.yml` with all six images pinned by digest, and an `install.sh`
that generates its own secrets, creates the organisation, project and user, and
writes the endpoint and key into `~/.spectro/.env` at mode 0600 so you never
copy a key by hand. Both first-boot traps are closed in the shipped file
itself: the database URL interpolates the Postgres password, and one MinIO
password feeds all three S3 keys. No secret carries a default: every one is a
required interpolation, so a missing secret stops compose loudly instead of
booting a stack that loses every span. A running server now reads
`SPECTRO_OTLP_*` from `~/.spectro/.env` the same way it reads API keys, so the
installer's handover takes effect without exporting anything.

Nothing in the app starts a container. The app tells you the command; you run
it.

## The spectrum under load

On a dense session the spectrum used to say "1003 marks thinned for display"
under a band that had silently deleted whole channels: the thinning budget went
to structural events first, and on a long imported transcript the reasoning and
token marks did not survive at all, while the legend kept promising them.

- Thinning is now a function of the visible window: one mark per pixel column
  per kind, with errors and gates winning their column outright. Zoom in and
  each column covers less time, so more marks appear wherever time can
  separate them, measured monotone across 500 nested window pairs on the real
  transcript; marks tied on a single instant stay collapsed at any zoom, and a
  realigned column grid can occasionally cost one. Channels no longer vanish;
  an error never averages away.
- Zoom has buttons: `+`, `−` and `all` ride the overview strip's rail, pinned
  to the top of the view, because ctrl and a wheel is not a discoverable pair.
  Ctrl or meta plus wheel zooms at the pointer, and a trackpad pinch is the
  same gesture. Keys: `+` `−` `0`, shift plus arrows, Home, End, and `[` `]`
  page across dead air by snapping the next mark to the window's edge. A plain
  wheel still scrolls the page, and bare arrows still scrub.
- The footer sentence now counts what does not fit beside the others in this
  window, so it falls as you zoom and reaches zero when everything fits. When
  it is zero it says nothing.
- Every mark is reachable. The band draws the thinned set but scrubbing and
  hover walk the full list, so a mark that lost its pixel column can still be
  found and opened in the trace.
- The zoom surface appears only on a lane that cannot draw half of what it
  carries. A short session keeps its plain band.
- The overview strip pins to the top of the view and the time axis to the
  bottom, so on a small window you no longer scroll one away to reach the
  other.

## Four read endpoints, fenced

Four read endpoints (`/api/files`, `/api/file`, `/api/claude/transcripts` and
`/api/claude/transcripts/content`) now wear the same local-origin fence the
other local endpoints wear: the caller must be a loopback peer and the `Host`
header must be local, or the answer is 404 with an empty body. This closes the
DNS-rebinding read that a plain cross-origin block does not: a rebound page is
same-origin to itself and reaches loopback exactly like the real UI. `Origin`
is deliberately not consulted, because the desktop shell and inline previews
send none; `Host` is the half a script cannot forge. Measured as requests
against a fresh jar: a rebound host got 404 and zero bytes from all four,
loopback callers kept working.

- The workspace file endpoints also stopped following symlinks out. The path
  check used to be arithmetic on strings while the read below it followed
  links, so a file inside the workspace pointing at a file outside it was
  served. Both sides resolve real paths now, the tree listing drops a link that
  points out, and the ordinary macOS case, where the workspace root itself sits
  behind a symlink like `/tmp`, still works.
- The shell and the settings write now resolve the same folder the run
  resolved, the record written when the session's workspace was decided,
  instead of recomputing it from live configuration. Changing the configured
  workspace under a running session can no longer point the Files tree and the
  terminal at two different directories.
- The transcript size cap is pinned to one constant with drift guards on both
  ends, and the content read streams, so one import no longer holds the whole
  file in memory twice. Streaming decoupled the server's heap floor from the
  cap: the 128 MiB ceiling is now a budget for the browser that must render
  the file, not for the server's heap. Every launch path this project ships
  starts the JVM with a third of the machine's memory instead of the JVM's
  default quarter, a drift test holds the four scripts together, and the
  server logs its heap share at boot so a launcher that stopped passing the
  flag shows itself.

## An upgrade cannot land on a blank window

The asset files are content-hashed and the entry page is not, and until now
both were served with no cache policy at all. The desktop shell was measured
serving a previous build out of its own HTTP cache while Chrome, against the
same server in the same minute, had the current one, and the old asset hash
answers 404 on the new jar. A stale entry page whose assets are gone would
show a blank window after an upgrade: the mechanism is measured, the
end-to-end upgrade replay is not.

- `/` and `/index.html` now answer `Cache-Control: no-cache`, so the shell is
  revalidated on every load. A 304 is a header exchange, so this costs almost
  nothing.
- `/assets/*` answers `Cache-Control: max-age=31536000, public, immutable`. A
  name that changes with the content never needs revalidating.
- The desktop shell clears its HTTP cache once whenever its version changes,
  before any window loads, because new headers cannot fix a cache that was
  poisoned before they shipped. A missing version marker counts as a change,
  which is exactly the upgrade-from-an-older-build case.

Both header answers were measured with curl against a running jar rather than
read out of configuration.

## Also new

- The built-in model's one-time notice now remembers every way of closing it:
  the button, the ×, the backdrop and Escape all mean understood, go away.
  Before, only the button persisted and the notice returned forever for anyone
  who dismissed it the way people dismiss modals. Because it can now be gone
  for good, Settings keeps a deliberate way back: built-in model, show the
  notice again.
- The version travels with the build. A 0.5.0 build's About dialog answered
  0.4.1, and the starter bundle you copied out of the app named
  `dev.spectroscope:spectro-core:0.4.1`, a line that resolves on Maven Central
  and is wrong, because one hand-maintained constant stood outside the release
  pipeline's reach. The constant is gone: the build stamps its own version into
  a resource the server reads, a drift test went red on the exact drift the
  release shipped, and the tag pipeline now greps shipped Java for stray
  version literals.
- The export and translate buttons moved out of a floating cluster over the
  chat and into the composer bar, where the disclosure menu already lives. The
  archive view got the disclosure menu back too, and its raw download link now
  says what it is: download .jsonl, the server's stored file verbatim, as
  opposed to the export sheet, which writes the view you are looking at.
- One primary button style, the quiet one: a surface with an accent hairline.
  The solid accent fill with a gradient and a drop shadow is gone from all
  eleven buttons that carried it, because the brand rules put colour on the
  lines and allow no shadows.
- The Files tab says there is no folder yet instead of listing the server's
  own working directory before a session has resolved one.

## How you get it

The channels are the ones 0.5.0 shipped. Nothing new this cut, and nothing
dropped.

**Homebrew, macOS on Apple silicon.**
`brew install --cask spectroscope/tap/spectroscope` installs the signed and
notarized desktop kit.

**The macOS disk image.** `spectroscope-0.6.0-arm64.dmg` on the release page.
Signed, notarized, and carrying its own Java runtime and `llama-server`. Apple
silicon only.

**apt, on Debian and Ubuntu.** The signed repository at
`https://apt.spectroscope.dev` serves the deb; if you added it for 0.5.0,
`apt upgrade` carries you here. x86_64 only.

**The Linux kit.** `spectroscope-0.6.0-x86_64.AppImage` and
`spectroscope_0.6.0_amd64.deb`, built and smoke-tested on Linux by this
project's own CI. Both bundle their own Java runtime and `llama-server`.
x86_64 only, not signed.

**The jar and the CLI.** `spectro-server-0.6.0.jar` and `spectro-0.6.0.zip`
run on any machine with Java 21. They are the smallest way in, and the only
way onto a platform that has no kit.

**In your own code.**

```
dev.spectroscope:spectro-core:0.6.0
dev.spectroscope:spectro-orchestrator:0.6.0
```

Both are on Maven Central, which is append-only: 0.6.0 stands beside 0.5.0
rather than replacing it.

## Fixed

- Three socket-only frame kinds could be written into an exported session
  file, where the store reads the line as torn and drops it without a word.
  The export gate now names all six socket-only kinds and is derived from one
  list instead of two hand-kept copies, with a drift test that reads the
  server source so the next socket frame goes red in the suite rather than
  into somebody's file.
- The note chips on a trace row shrink before they clip, and the import bar
  leaves with its file instead of describing a session that is no longer
  shown.
- A frame with no timestamp landed off the left edge of the spectrum band at a
  negative position. It is clamped into the band now.
- The spectrum's time axis no longer drifts after a daylight-saving boundary.
  Swept over ten time zones across a full year: zero misaligned labels, and
  the one interval that really is thirteen hours long says so.
- The Readable pane stops at a structure depth of 64 and hands the rest to
  plain JSON printing, instead of crashing the tab on a pathologically deep
  but valid line.

## The gate

Measured on 2026-08-04 on the release tree, with the build cache and the
up-to-date checks disabled: 1275 Java tests and 2387 web tests across 161
files, no failures. One Java test is skipped when no live API key is present.
Both suites run the same way in CI.

## Not in this release

- No arm64 Linux build, no Windows desktop kit, and no arm64 package in the
  apt repository. Unchanged from 0.5.0.
- No inline Langfuse tab. Measured and refused; the reasoning is in
  `docs/OBSERVABILITY.md`.
- No Langfuse link on archived sessions. The link needs the export frame,
  which only a live session carries.
- Translation is unchanged from 0.4.1; only its button moved.

## Requirements

Java 21 or newer. The macOS desktop kit is arm64, signed and notarized, and
includes its own Java runtime. The Linux kit is x86_64, includes its own Java
runtime, and is not signed. The server jar and the CLI need a `llama-server`
on the PATH (`brew install llama.cpp`) to run a local model; both desktop kits
bundle one. The terminal in the Files tab needs the `spectro-pty` helper,
which only the desktop kits carry.
