# spectroscope 0.4.1

Released 2026-07-27. `dev.spectroscope:spectro-core:0.4.1` and
`dev.spectroscope:spectro-orchestrator:0.4.1` are on Maven Central; the CLI,
the server, the MCP notes server and the macOS desktop kit are attached below.

## A third session format

You can load VS Code and GitHub Copilot agent-mode exports alongside
spectroscope's own JSONL and Claude Code transcripts. That format does not
carry tool output, so the tool bodies in those sessions are empty. The import
says so once.

If a file is in none of the three formats, the import now names the record
types the file contains. If a file cannot be read, the import reports the
reason.

## Search

Press Cmd+F (Ctrl+F on Windows and Linux) to search the chat, the text feed or
the trace. Enter and Shift+Enter step through the matches, and a checkbox reads
the query as a regular expression.

Each view counts in its own units: occurrences in the text feed, turns in the
chat, rows in the trace. In the chat, search covers your messages, the answers,
the reasoning and the tool calls, including their commands and results.

## Translation

You can translate a session into German or English, with the built-in local
model or with your configured cloud provider. The translation applies to the
session itself, so the chat, the trace, the text feed, the graph, the spectrum
and the lab all show it at once. One click switches back to the original, and
the stored file stays unchanged.

Translation covers the agent's reasoning as well as the answers. A checkbox
leaves the reasoning in its original language, and the panel shows how many
extra passages including it costs before you start.

If a passage cannot be translated, the panel names it and leaves it in its
original language. A run that ends early reports how many passages stayed in
their original language.

Translation leaves tool calls and tool output untouched, so commands, paths and
results stay as they were recorded. You can save a translated session as JSONL
and load it again later.

## Export

The chat and the text feed export their view as a single HTML file that opens
without a network, and the event stream as JSONL. An export of a translated
session marks the translation in its file name and its label.

## Imported sessions

- Each answer names the model that produced it, including where a session
  switched models part-way through.
- For Claude Code transcripts, each answer also reports prompt caching: how
  much came from the cache and how much went into it. VS Code exports carry no
  token counts.
- A session's duration is the time between its first and its last event.
  Durations over an hour appear in hours.
- An imported session has one turn per exchange, so the graph draws every
  exchange instead of a single row.
- Playback starts at the beginning of an imported session, and the chat has a
  control to jump to either end.

## Reading a session

- Fenced code blocks in an answer are syntax-coloured: shell, SQL, Java, Python
  and JSON. On tool cards, a command is coloured as shell, and a file body by
  its extension.
- Tool calls from Claude Code, VS Code and MCP servers are rendered by type: a
  command as a command, an edit as a diff, a generated image as the image.
- The trace's event detail has a structured view beside the raw event, and the
  lab has the same choice.
- You can switch off the host and model columns in the trace. A column with no
  data for the session you are reading stays hidden.
- The timeline lens is now off by default.

## Fixed

- Browser-side errors appear in the log pane next to the server's.
- The context gauge measures against the compaction threshold the run reports,
  or the model's context window when it reports none. It previously divided by
  a fixed number and could report over 100%.
- Scrolling over the read-only bar of an archived session no longer moves the
  whole page.
- Settings section headings are bigger and higher in contrast, and each one
  sits closer to the fields it names than to the section above it.

## Requirements

Java 21 or newer. The desktop kit is macOS arm64, signed and notarized, and
includes its own Java runtime. The server jar and the CLI need a `llama-server`
on the PATH (`brew install llama.cpp`) to run a local model; the desktop kit
bundles one.
