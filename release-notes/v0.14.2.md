# spectroscope 0.14.2

Most of this release is about sessions. The list on the left has one row per
session, and the "Live session" row is gone. Click a row and keep typing in it.
Several sessions can run at the same time, and each one uses its own provider
and model. The first start now asks whether you want the full app (learn) or
only the chat (light). The images move into the side panel, and the side panel
can show one panel at a time. `read_file` reads a whole file when it fits the
model's context window, instead of stopping at 50 kB. The desktop app on macOS
now asks for the microphone.

---

## Sessions

**One row per session.** The session list no longer has a "Live session" row at
the top, and a session no longer shows up twice. A new chat gets its own row
once it has started.

**Click a session and keep typing.** A saved session opens with its history and
an empty message box. The next message continues that session in the same file.
There is no Resume button any more. The trace still marks the point where the
session was continued, and the context jumps there because the whole history
goes to the model again. Imported sessions and scenarios still open read-only
and say so.

**Several sessions run at once.** You can start a long run in one session,
open another and send a message there. The first one keeps running, and its row
pulses until it is done. A new chat adds a session and does not replace the
one you had.

**Each session has its own provider and model.** One session can run on a
local model in LM Studio, another on an ollama cloud model and a third on the
Anthropic API, all at the same time. The provider and model menu always
applies to the session you are looking at. Switching providers in one session
does not change the model of another one that is already open. A saved session
continues on the provider and model of its last run, also after a reload. If
that provider can no longer be used, for example because its key is gone, the
session starts on the provider a new chat would get, and the header shows
which one.

**A session that needs you says so.** If a session in the background asks a
question or waits for a permission, its row reads "waiting for you" and a
banner with "open it" appears, whatever you are looking at.

**A session waiting for the model says so.** When a run has no output yet
because another session is using the same provider, its row reads "waiting
for the model".

**Deleting a running session asks first.** The row menu asks "This session is
still running. Stop it and delete?". The delete button on the archive bar is
gone; delete from the row menu.

**The desktop app asks before quitting running sessions.** Quitting while
sessions are working asks "... still working. Quit anyway?". Quitting stops
them, and their history stays saved.

## First start

**The first start asks for a mode.** Before the tutorial question, a new
screen asks "How much of spectroscope do you want to see?". It shows learn and
light side by side, with the same weight. Each choice says what it shows and
has a small picture of the window in that mode. Learn goes on to the tutorial
question. Light skips it and turns the tutorial off, because light keeps the
parts closed that the tutorial would open. If you switch to learn later, you
can turn the tutorial on in the settings.

**Existing installations see the question once.** Your current mode stays
until you choose. If you already answered the tutorial question, you are not
asked again. The choice is kept per window type: the desktop app and a browser
tab each ask once.

## Side panel

**The images are a panel of the side panel.** The images no longer have their
own area next to the side panel. They open as the Images panel, from the
header button, from View > Images or from the side panel's tab strip, and they stay
open after a reload.

**The side panel can show one panel at a time.** A "Tabs" checkbox at the top
of the side panel switches it from side by side to tabs. With tabs, a click on
Files shows only Files and a click on Plan shows only Plan, and the side panel
keeps its width. A terminal or a browser keeps its state when you switch to
another tab and back. Side by side stays the default.

**In a narrow window the side panel lies over the chat.** When there is not
enough room for both, the side panel opens on top of the chat instead of
squeezing both.

## Tools

**`read_file` reads whole files that fit.** The old limit of 50 kB is gone. A
file is read in one call when it fits a quarter of the context window of the
running model. With a window of 250,368 tokens, that is up to 187 kB. There is also a
fixed limit of 2 MiB for very large logs and binary files. When a file is too
large, the answer names its size, the estimated tokens and the window, and
still offers reading it in pages with `offset` and `limit`.

**`grep` searches larger files and names the ones it skipped.** Files up to
2 MiB are searched. A file it skips is named at the end of the answer instead
of being left out silently.

**Skill files follow the same rule.** `read_skill_file` reads under the same
limit as `read_file`.

## Desktop

**The macOS app asks for the microphone.** The signed app was missing the
microphone entitlement, so macOS refused voice input without asking and
spectroscope did not appear under Privacy and Security, Microphone. The app
now asks once on first use, and the prompt says what the microphone is for.

---

## Known limits

- The text you are typing is shared between sessions. Switching sessions keeps
  the draft.
- The image backend and the thinking switch still apply to the whole window,
  not to one session.
- A provider's server address (base URL) changed in your user settings is
  not yet kept per session; provider and model are.
- Quitting the desktop app from the terminal (a signal) does not ask.
- "waiting for the model" is a guess from the app: a run with no output while
  another session streams on the same provider.
