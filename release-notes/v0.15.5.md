# spectroscope 0.15.5

The main agent is now told that an explore helper can use the code graph. When
the model ends its turn with a question to you, the app no longer continues the
run on its own, so your answer comes first. `grep` searches a file when it is
given one. The chat line about a continuation has a sentence for every reason.

***

## Helpers

**The explore helper's code graph.** The descriptions of `spawn_agent` and
`spawn_agents` list the tools an explore helper gets. The list now includes
`code_graph`, with the note "when the folder has a code graph". Before, it
stopped at `grep`, and the main agent ran graph questions itself instead of
handing them to the helper. The app reads the list from the same set the
helper's tools come from, and the System context panel shows the same text.

## Continuation

**A question waits for you.** When a run's plan still has open steps, the app
writes a message of its own and starts another turn. If the model ended its
turn with a question to you, the app now ends the run there, and the chat
says "Not carried on: the turn ended with a question to you, so your answer
comes first." A turn counts as a question when the last line of its answer ends
with a question mark. Closing quotes, brackets and bold or italic marks after
the question mark do not change that.

**The message says who wrote it.** When the app does continue a run, its
message now says that it comes from the app and is not your answer to anything
the model asked.

**A sentence for every reason.** The chat line about a continuation has its own
sentence, in English and German, for each reason the app writes: carried on,
nothing moved since the last continuation, all continuations spent, and the new
question case. A spent budget used to show a generic line with an internal
name.

## Tools

**grep takes a file.** When the model gives `grep` a file as its `path`, it
searches that file and answers in the same form as for a folder. Before, it
answered "no such directory" for a file that was there. A path that does not
exist now answers "no such file or directory", for `grep` and for `glob`.
`glob` still needs a folder and says so when it gets a file.

## Library API

`ContinuationLeash.Decision` has a new value, `QUESTION_TO_PERSON`, written as
`question_to_person` in the `continuation` event. `ContinuationLeash.consider`
takes the turn's final text as an optional third argument; the form with two
arguments still works. A `switch` over `Decision` without a default branch
needs a case for the new value.

## Known limits

- The deprecated settings file in the folder the app was started from can
  still set `toolResultElision`.
- A settings file changed by hand outside the app reaches an empty chat only
  after a reload.
- The agent's file tools refuse to write under a playbook folder, but a shell
  command run with `run_command` can still write there.
- The hooks of a picked playbook do not run in the session.
- Refusals from the server, such as the reason a run may not start, show in
  English in the German interface.
- The context tab still lists the skills of the folder the app was started
  from, not the skills of the session.
- The run panel lists the files that the agent's file tools wrote. It does not
  list files written by shell commands, MCP tools or git. It counts the shell
  commands of a step.
