# spectroscope 0.8.0

Released 2026-08-12, 26 merges after 0.7.0. Three changes carry it. A state
graph joins sessions and fleets as the app's third surface, drawn before the
first token flows and lit up by the run. The conversation between the backend
and the model, the one exchange that costs money, is recorded verbatim as a
second file beside the session. And the microphone types while you speak.
Behind those, this release answers two sentences from 0.7.0's own "not in
this release" list: you can message a fleet node now, and a trace row and a
spectrum window produce a link.

## The state graph

Everything this app showed before was reconstruction: a run happened, events
arrived, views were built from what they said. A graph is the first thing on
these screens that exists before the run. Its topology is fixed at
`compile()`, so the picture is drawn first and the event stream only lights
it up: nodes as they enter and leave, edges as they are taken, values as
they are written. Observing without touching, which is the working principle
of the instrument this product is named after.

The runtime lives in `spectro-core`, in the published library, not in the
app. You build a `StateGraph` in your own code, compile it, run it, and two
files land beside your run. `<stem>.graph.jsonl` carries the structure:
topology, node lifecycle, taken edges. `<stem>.state.jsonl` carries what
nodes wrote, in four tiers (`off`, `summary`, `sample`, `full`), and the
default is `off`, because a library update must never start writing your
documents to disk. Recording is one line in your own source, where you will
find it again.

The runtime holds the pieces a real application reaches for. A checkpointer
seam (`CheckpointSaver`, an in-memory saver, `getState` and
`getStateHistory`) gives a graph thread memory, so a second turn on the same
thread continues where the first ended, through the reducers. Streaming
delivers values, updates, and custom writer output while the run is still
going. A multi-sink fans records out to more than one consumer, and an
artifact reader loads the two files back in. One thing the runtime refuses
to do quietly: two sibling nodes writing the same non-folding channel in the
same superstep is an error that names the channel, both writers, the
superstep and the remedy. Silent last-writer-wins is exactly the kind of lie
the graph exists to end.

The view is the third entry in the sidebar, beside sessions and fleets. It
loads the file pair through a picker, or one of five bundled scenarios: a
linear RAG pipeline, a corrective loop, a two-turn tool conversation on one
thread, a run with a real node error, and a reference run with recorded
values. All five were written by the engine itself in real runs, never by
hand. A transport plays the run over the drawing (play, pause, five speeds,
arrow keys, Home and End), rank rulers cross the field, a revisited node
counts itself (`×2`), a loop says so (`↺`), and the panel joins the values a
node wrote at the visit the cursor is on, with a documents strip that says
how much of a list was kept rather than presenting the sample as the whole.
A failed node carries its error class and message. Export produces an SVG
that speaks the same visual language, or a Markdown summary.

Two decisions in the drawing are worth naming. The layout is not dagre:
dagre breaks cycles by reversing edges, which drew a correction loop
backwards, and a graph view that shows the opposite of what ran is worse
than none. The rank layout with gutter routing is this project's own. And
the untaken edge stays on the canvas. It does not disappear; it steps back.
Reading a graph means seeing the branches that were available, not only the
ones that fired, and that is what separates this view from a trace.

One more, from the same week: the view's quiet text ("not recorded", "never
entered", the step numbers) now meets the 4.5:1 accessibility floor in every
design, derived from each design's own ink and ground. Absence stays quieter
than value; it no longer becomes unreadable.

**What this does not do.** The view reads files; a live session does not
feed it yet. A loaded run deliberately does not survive a reload, since the
browser cannot re-open your file without you. When one file pair carries
several runs, the footer still describes the first while the transport walks
them all; the two-turn scenario shows it. Value recording stays off
until your code turns it on, and no policy flag makes redaction a promise:
the policy field says `patterns`, never `true`, because patterns catch
credential shapes and cannot catch confidential prose. The session tab named
`graph` is a different thing, the event replay of one run, and keeps both
its name and its job.

## The llm wire

The trace has a face called wire, and until now it did not show the wire.
The request the backend builds for a model (system prompt, the entire
replayed history, tool schemas, images) was assembled, sent, parsed and
thrown away. What the interface showed was a paraphrase.

Now every session records the real exchange in a second file beside its own:
`llm-wire/<session>.llm.jsonl`. An `llm_request` line is written at send
time, so a crash cannot erase what was sent; an `llm_response` line at close
carries the status, the raw stream lines, and an honest word when the call
aborted. Four kinds ride the same record: chat, compaction, image
generation, speech. Credential header values are redacted while the header
names stay. Fidelity is part of the record, never implied: `bytes` means the
string is what went over the socket, `sdk-json` means the SDK owned the
socket and this is its own serialization. A hard byte ceiling ends recording
with one marker line; past it the ledger stays complete while bodies carry
an omitted marker instead of vanishing.

The trace reads these rows like any other traffic. An exchange is three
rows, request up, response down, and a summary, with the full body a click
away and base64 rendered as measured gaps rather than noise. A finished
exchange also becomes a line of the session file itself, so an archived
session re-opened next month still knows every model call it made. And
spectrum draws a second line under every agent: the app-protocol marks
above, the wire marks below, joined by exchange id, so a call sits under the
moment that caused it. A mark is coloured only by what is measured: it came
back, or it never answered.

The record earned its keep within minutes of existing. The first live test
caught a bug where a failed audio conversion's help text was returned as a
200 "transcript", visible only because the wire file held what the server
actually received and answered. That is the argument for verbatim recording
in one sentence.

**What this does not do.** The session-less endpoints (explain, translate)
and the orchestrator's panel lanes are declared, not captured; the interface
says so instead of pretending. Spectrum's wire marks carry a native tooltip
but no hover card and no click-through yet. Header redaction still prints
the credential's exact length, which is a small oracle; the graph layer
already reports a coarse bucket instead, and the wire will follow.

## Voice, while you speak

0.7.0 could transcribe a finished clip. 0.8.0 gives the microphone a face
and a live mode.

The face first. Failures name their cause: permission denied, no
microphone, a server that is not ready, and a network failure are four
different sentences, none of which is a vanished button. A popover lists the
input devices by name, remembers your choice, and says honestly why it
cannot show names before permission has been granted once. A level meter
moves beside the glyph while you speak, a short click confirms arming, a
small LED marks start and stop, and both respect reduced motion. A first-run
sheet says what speech needs on this machine before the first failure, not
after it.

Under the hood, ffmpeg left the recording path. The browser already holds
the audio, so it decodes and resamples to what the model wants and posts a
plain WAV, measured at 21.9 ms to decode and a size factor of 2.8 for
speech, with a 300-second ceiling. The server stopped spawning a converter
per recording, and the wire records the exact bytes the model was handed.

Speech has two routes now. The hosted route transcribes remotely, so a
desktop install has voice on day one with an OpenAI key and no binaries. The
local route stays what it is: keyless, offline, private, one binary. And on
the hosted route there is live transcription. Hold the button and the words
appear as you speak, faded while they are provisional. The page talks to
this server only; the socket keeps the API key server side, refuses foreign
origins by name, and holds audio spoken before the upstream is ready instead
of dropping it. Measured through this server: first words on screen 1.2
seconds in, 59 of 64 partial results delivered before the audio had
finished. When the final transcript lands it replaces the provisional text,
because the model corrects itself once it has heard the end; concatenated
guesses are never committed. The whole live session rides the llm wire
verbatim, every frame recorded before it is interpreted and the provider's
own frame types kept, so a reader can tell a guess from an answer without
trusting this code's opinion.

**What this does not do.** The live toggle is greyed out, never hidden and
never silently rerouted, when the active route cannot stream (today, the
local route). A live session has no duration ceiling yet; the batch route
stops at 300 seconds, the socket does not. And the live record is complete
about what the model said but not about what it heard: the spoken bytes ride
the socket in pieces and are not on the request line, which the record names
rather than hides.

## You can talk to a fleet node now

0.7.0 said it plainly: no way to send a message to a fleet node, the wire
verb is the open leg. The leg is built. The composer on a fleet card and in
the agent feed comes off disabled, and the words travel the fleet wire as a
message form of the control frame, through the hub, to the node's own run
loop. The node actually runs again. Typed into a live fleet: "count to
three, nothing else". The node answered "1, 2, 3".

The wire version moved from 3 to 4 for it, because a version-3 node would
have parsed the new form as a no-op and dropped the words with no log line.
The bump makes the mismatch loud instead. Messages merge in order when they
arrive faster than the node fires. A node with no run loop at all answers
409 with the reason, while there is still somebody to tell.

Two more sentences from 0.7.0's open list close with it. A trace row and a
spectrum window now say where they are: the address carries the open row,
the active filters, and the spectrum's zoom window, so the link you paste is
the reading you had, and back and forward walk your readings. And typing `/`
in the composer completes across the installed skills.

**What this does not do.** A fleet is still not an object anyone creates:
the only path is spawning into a hub already running behind two variables
that both default to off, unchanged from 0.7.0. The message verb makes an
existing fleet talkable; it does not make fleets easier to have. A message
to a node needs the node to have a run loop; the 409 says so. The lab tab
still publishes no reading, fleet addresses carry no tab, and a scenario, a
pasted body or a file picked from disk still has no address at all,
unchanged from 0.7.0 and named there.

## The redaction patterns are reviewed

The state file's redaction rules were shapes somebody wrote down; now they
are shapes the issuers document. Each of the twelve patterns was reviewed
against the published formats: AWS access key prefixes, GitHub's token
formats including the fine-grained `github_pat_`, Slack's token families,
the OpenAI and Anthropic key anatomies, and the PEM private-key headers
including PGP's. A table of near-misses pins the other half of the contract.
A whole string is replaced when a rule fires, so prose that merely resembles
a credential must survive: "task-management-ui", a slug after "sk-", a
sentence about bearer authentication, an AWS resource identifier, and a
friendly "xoxo-" all stay untouched. Two limits are pinned as limits, on
purpose. Prose is never caught, which is why the policy says `patterns` and
not `true`. An IBAN written in spaced groups of four is a recorded gap.

## Sharper edges

The trace stopped rebuilding the world. It renders a window rather than
nine thousand rows, is mounted once and hidden rather than rebuilt on every
visit, and when the window must drop rows it says so instead of trimming
silently. The OTLP export stops calling a flat list a tree. The lab map no
longer claims a named tool is "planning". The desktop shell's window-open
seatbelt is actually worn, and its Electron pin now provably reaches the
shipped binary. The README installs the current release instead of one from
two releases ago. And spectrum's frame got its borders back: its stylesheet
named 37 design tokens that did not exist, every declaration silently
resolved to nothing, and nobody saw a missing border for months. The tokens
are real now, and a test keeps them real.

Dependency housekeeping: Electron 39.8.10, js-yaml 4.3.1.

## Getting it

**Homebrew, on macOS.** `brew install --cask spectroscope/tap/spectroscope`
installs the signed and notarized desktop kit.

**The macOS disk image.** `spectroscope-0.8.0-arm64.dmg` on the release
page. Signed, notarized, and carrying its own Java runtime and
`llama-server`. Apple silicon only.

**apt, on Debian and Ubuntu.** The signed repository at
`https://apt.spectroscope.dev` serves the deb; if you added it for an
earlier release, `apt upgrade` carries you here. x86_64 only.

**The Linux kit.** `spectroscope-0.8.0-x86_64.AppImage` and
`spectroscope_0.8.0_amd64.deb`, built and smoke-tested on Linux by this
project's own CI. Both bundle their own Java runtime and `llama-server`.
x86_64 only, not signed.

**The jar and the CLI.** `spectro-server-0.8.0.jar` and `spectro-0.8.0.zip`
run on any machine with Java 21. They are the smallest way in, and the only
way onto a platform that has no kit.

**In your own code.**

```
dev.spectroscope:spectro-core:0.8.0
dev.spectroscope:spectro-orchestrator:0.8.0
```

Both are on Maven Central, which is append-only: 0.8.0 stands beside 0.7.0
rather than replacing it. New in this release, `spectro-core` carries the
graph runtime (`StateGraph`, the checkpointer seam, streaming, the sinks and
the artifact reader), so the two files the app's state graph view reads can
come from your own program.

## The gate

Measured on 2026-08-12 on main, with the build cache and the up-to-date
checks disabled: 1,901 Java tests across 241 result files and 3,431 web
tests across 224 files, no failures and no errors. Three Java tests skip by
design: one needs a live API key, two are the on-demand writers that produce
the demo scenarios and the end-to-end artifact proof. The release day
re-measures both suites on the release tree, and the numbers here get
replaced by what it says.

## Not in this release

- No arm64 Linux build, no Windows desktop kit, and no arm64 package in the
  apt repository. Unchanged from 0.5.0.
- No live feed into the state graph view: it reads the file pair, it does
  not watch a running session yet.
- No hover card and no click-through on spectrum's wire marks; the exchange
  id is on the mark, the gesture is not.
- No duration ceiling on a live voice session; the batch route has one.
- No address for the lab tab, a scenario, a pasted body, or a file picked
  from disk. Unchanged from 0.7.0.
- No install from a live git remote, and no skill update check.
- Translation is unchanged from 0.4.1.

## Requirements

Java 21 or newer. The macOS desktop kit is arm64, signed and notarized, and
includes its own Java runtime. The Linux kit is x86_64, includes its own
Java runtime, and is not signed. The server jar and the CLI need a
`llama-server` on the PATH (`brew install llama.cpp`) to run a local model;
both desktop kits bundle one. The terminal in the Files tab needs the
`spectro-pty` helper, which only the desktop kits carry.
