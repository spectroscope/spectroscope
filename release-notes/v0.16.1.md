# spectroscope 0.16.1

The files tab now writes a report for a session: which files the run read,
changed or created, which credentials it saw and used, and which models got
its content. You save it as PDF, HTML or CSV. Imported GitHub Copilot sessions
now carry what their tools returned, their helpers' work on their own lanes
and the model that answered, and a Copilot session folder loads as a whole.

***

## Files report

**One line at the top.** The Report button in the files tab opens a sheet.
Its first line gives the session's level: critical, sensitive, unknown or
project. Below it the report names every model the session called and where
it ran: on this machine, on the local network, on a local server that relays
to a cloud service, in the cloud, or at an address the session did not record.

**What it lists.** Every file the session touched, with its level, what
happened to it (read, changed, created, deleted, sent) and where that comes
from (recorded, probable or model). Then the findings:

- a file with a secret-shaped name that was read or sent, such as `.env` or a
  private key
- a credential shape in a tool result, a tool input or a prompt
- a credential the session saw and then used again in a later call
- a dump of the environment, and the output of a secret getter such as
  `gh auth token`
- a network command, as a finding of its own; one that only talks to this
  machine stays at project level
- a file outside the working folder, and a script whose effect the report
  cannot tell
- the number of email-shaped strings and IBANs in what the session read

Listings that return names only, such as a glob pattern, `ls`, `find` or
`rg --files`, appear in a section of their own and do not count as files the
session read. A `grep` or `rg` reads the files it searches, so a search over
`~/.ssh` counts as a read of secret files.

**No credential is printed.** The report shows a credential as a label and a
size band, never its value, a part of it, its exact length or a hash of it.
It finds credentials by their shape and by their place in a command: the
password in `curl -u`, an `Authorization` header, a query parameter named like
a key or token, and similar positions. On top of that, printed commands and
titles hide every word part that mixes letters and digits, or upper case,
lower case and symbols, unless it is a path, an address, an option, a program
or a version. A secret made only of letters, in a position the report does not
know, can still appear in a printed command; the method section says so.

**It does not call a session safe.** When it finds nothing, it says which
shapes and names it checked and that none of them was found.

**Three formats.** PDF through the print dialog, a self-contained HTML file,
and a CSV with one row per file and finding. A CSV cell that starts with `=`,
`+`, `-`, `@`, a tab or a carriage return gets an apostrophe in front, so a
spreadsheet does not run it as a formula.

## Copilot import

**Tool output.** An imported Copilot session now shows what its tools
returned. Before, every tool card was empty and a note said the export held no
output, which was wrong for this format. The note now appears only when a file
has results without output, and it says how many.

**More tools are read.** The files tab and the report read the Copilot CLI's
`view`, `create`, `edit`, `bash` and `powershell`, and the IDE's `rg`,
`apply_patch` and `glob` with a list of paths. A patch names its files, so a
change made through `apply_patch` shows as recorded.

**Helpers on their own lanes.** A helper's work now runs on the helper's own
lane, under its name. Before, it counted as the main agent's work, and each
helper's task showed as a message you had typed.

**The real model.** A run names the model that answered, such as the model
behind `auto`, and the provider `copilot`. An imported Claude Code transcript
names the provider `anthropic` beside its model. The report uses both to say
where the content went.

**Token counts and errors.** Copilot's usage records become token counts, and
a session error shows in the chat. A session that only started and stopped
now imports instead of being refused.

**A session folder loads as a whole.** Pick the folder of a Copilot session
and the import reads `events.jsonl` together with `workspace.yaml` and the
file snapshots Copilot keeps beside it. The session gets its name, its working
folder and the client that recorded it. The snapshots show in the files tab
and the report as recorded changes, also for files a shell command changed.
The import does not read the stored file contents of the snapshots. A folder
that holds several sessions opens a list to choose from. When you pick
`events.jsonl` alone, the import says that it belongs to a folder and offers
to load the folder. A side file picked alone gets a hint instead of an error.
When a lock file marked the session as in use, the import says so, and a last
line that was still being written is left out.

## Files tab

**Patterns are not folders.** A glob pattern used to show as a chain of
folders. It now shows as one row with the pattern, under the folder it starts
from, marked as a pattern.

## Known limits

- The report reads what the session recorded. A command's effect beyond its
  command line, such as the files a script or a build tool changed, stays
  unknown unless a tool or a snapshot recorded it.
- A password with several symbols in a position the report does not know can
  still show a short part of four or five characters in a printed command or
  title. Printed commands also hide some harmless words, such as file names
  with capitals or digits.
- In prompts and tool results, the report counts credentials by the same
  shapes the app uses to redact them. A password those shapes do not match
  there is not counted.
- PowerShell is read for a few cmdlets only: the web requests, the
  environment drive and `$env:`. The report says so when a session ran
  PowerShell.
- The app reads only the files and folders you pick. It does not open the
  Copilot session store on its own.
- An imported session is shown and not saved. Exporting it writes the events,
  not the folder's file snapshots.
- A Copilot session's permission requests, hooks, system prompt, images and
  encrypted reasoning are not shown yet.
- After a switch to `auto`, a run names no model unless the session recorded
  which model answered.
- Sessions imported with an earlier version keep their earlier reading until
  you import them again.
