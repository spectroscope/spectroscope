# spectroscope 0.15.1

This release follows up on the playbook work of 0.15.0. Every folder field in
the Playbook segment has a button that opens the system's folder dialog.
Developer mode opens on the chat alone and hides the row of tabs the way light
does. Back and forward now sit in the header, left of the mode switch, in every
mode and on every screen. Spectrolyzr is one page with a switch between a new
project and a new playbook. A new playbook is a copy of the spectro playbook
with the models you pick.

***

## Playbooks

**Choose a folder instead of pasting a path.** A Choose button stands beside
the folder field of the Playbook tab and beside the playbook folder in
Spectrolyzr. It opens the system's folder dialog and puts the path into the
field. A pick does nothing else: Add and the copy button act on the field, and
a picked folder is checked exactly like a typed one. You can still type or
paste a path. Where the system has no folder dialog, a line beside the field
asks you to paste an absolute path. If a folder dialog is already open, the
line says so.

**Spectrolyzr is one page.** The tab is now called New. Every choice stands on
one page: archetype, language, name, add-ons and folders. The file tree and the
reason for each file stand beside them, and Generate is at the bottom. On a
narrow window the files move under the choices. A switch at the top, "What to
make", offers Project or Playbook.

**A playbook without a project.** With Playbook, the page asks for a folder and
a model for each of the four roles of the spectro playbook: fast, standard,
strong and judge. Each role offers the spectro playbook's own model first and
then the models your providers list. Generate writes a copy of the spectro
playbook into the folder, sets the models you chose and adds the folder to the
Playbook tab. No project is written, and the playbook is not pinned to a
workspace.

## Modes

**Developer opens on the chat alone.** In developer, the row of tabs above the
chat now follows the tutorial, as it does in light. A fresh developer window
shows the chat with no row above it. Turn the tutorial on in the settings to
bring the row back. A tab chosen earlier, by an address or a reload, shows the
chat until the row is back. The Playbook segment keeps its own tabs. Learn is
unchanged.

**Back and forward in the header.** The two buttons now stand left of the mode
switch in learn, light and developer. They are there on every screen,
including the Playbook segment, the state graph, the skills page and an open
fleet. They work as before, and so do ⌘← and ⌘→. In a window narrower than 480
pixels the header uses less spacing, so the side panel button and the menu stay
in view.

## Known limits

- The project folder button in Spectrolyzr still reads Pick, the playbook
  folder button reads Choose. Both open the same dialog.
- Before any provider has listed its models, each role offers only the spectro
  playbook's model. A check in the provider settings fills the list.
- The spectro playbook declares no workflows, so a playbook made from it lists
  none. Spectrolyzr does not yet preview the workflows a playbook will carry.
