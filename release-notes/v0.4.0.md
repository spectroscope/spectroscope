# spectroscope 0.4.0

**Released 2026-07-27.** `dev.spectroscope:spectro-core:0.4.0` +
`spectro-orchestrator:0.4.0` on Maven Central; one download per app module on
the GitHub release, and the desktop run kit is signed **and notarized** —
container and app. Full gate at release: **JUnit 929 · vitest 593**, all
green (1 skipped = the live-Opus test), measured with
`--rerun-tasks --no-build-cache`.

Two things headline this release, and they answer the same complaint from
opposite ends. A fresh install used to open on a wall of seven tabs with a
paid model selected: too much surface, and none of it reachable without a
key. 0.4.0 gives the surface a path and the model a free alternative.

## The ladder: the product opens as you use it

Seven states, from **dark frame** to **deep field**, and you leave each one by
using the thing it opened. It is not a tutorial and there is no checkbox: the
product already watches agents through an event stream, so it watches you
through the same instrument. You read a trace, and the engine sees it in the
events the interface was rendering anyway.

- a once-per-home question with a real choice — grow into it, or open
  everything now. No silent default either way, and a home that already has
  sessions is never asked and never locked.
- a closed surface shows a **teaser**, never a hidden tab: what the surface is,
  the one criterion still outstanding, and a button that ends the arrangement
  permanently. The settings and the permission gate are never locked at any
  level.
- **receipts**: a met criterion carries the session and the event index it was
  earned in, and the link opens that frame. The address is a plain hash
  (`#/session/<id>@<n>`), so it pastes into a bug report. A criterion ticked by
  hand says `manual` forever — a progress display that cannot tell what it saw
  from what it was told is decoration.
- the header pill carries a spectrum strip that gains one line per state, in
  the logo's own order. No new colour was invented: they are the app's existing
  event tokens.
- three modes in the settings — ladder, checklist, off — and a way back to the
  dark frame.
- `spectro level` prints the same ladder with no server running, and
  `spectro doctor` carries one line of it. All three faces read one
  `levels.json`, so they cannot drift.
- **every criterion is reachable without a paid key**, and the walkthrough from
  dark frame to deep field was done that way.

## The local line: choose a model, own your machine

The built-in provider grows from one fixed demo model into a **catalogue**.
Pick from five open models in the app — what each is good for, whether it can
drive the agent's tools, and whether your machine has the memory and disk for
it, measured before the download starts. Downloads come from each model's
publisher, sha256-verified, and land in `~/.spectro/models`. The default is
Qwen3 4B: the one entry that both shows its thinking and calls tools, at a
download and a memory bar most machines clear.

**What ships in the DMG, and what deliberately does not.** The desktop run kit
now bundles its own signed `llama-server` (llama.cpp `b10107`, 11 Mach-O files,
~22 MB), so the built-in path needs nothing installed: download the app, pick a
model, done. The model **weights themselves are not bundled**: VibeThinker-3B
descends from `Qwen2.5-Coder-3B`, whose licence (Qwen RESEARCH LICENSE
AGREEMENT) limits use to research and evaluation, so redistributing those
weights inside a signed artifact is not ours to do. Every catalogue entry
instead links its licence and its source, and the download is the operator's
own act. The four Qwen entries are apache-2.0; VibeThinker's row carries its
caveat in the dialog.

- five models: Qwen3 1.7B / 4B (default) / 8B, Qwen2.5 Coder 7B, VibeThinker 3B
- native tool support is a per-model fact now — the Qwen entries drive the file
  tools, shell and subagents; VibeThinker stays honestly tool-free
- a RAM/disk preflight per row: fits / tight / names what is missing
- per-model context budgets; switching models restarts the runtime
- the first-run sheet leads with the zero-install path
- the runtime we spawn is **fenced**: a 192-bit key is minted per launch and
  required on every call. Loopback alone is not a fence when llama.cpp answers
  every origin with `Access-Control-Allow-Origin: *` — the port is not a secret,
  and any page the operator has open can sweep it. The key never touches disk
  and dies with the process.

## The chat lost its boxes

A user turn is a flat bubble on the right. An answer is bare text on the left,
with no card at all. Thinking and tool calls are hairlines with a two-pixel
rule rather than panels. What is left on screen is the conversation and the
record of what the agent did.

- tool cards open on **three faces** — structured, json, raw — with a copy
  button, and a closed card now measures exactly zero pixels of body
- a disclosure menu with two sections: how much is expanded (normal, extended,
  thinking only) and the reading width (normal, or 30% wider)
- an **extended text feed**: the whole record, not only the readable part
- every answer names its model and its wall-clock window; the trace grows a
  model column
- the timeline lens breathes, and `context_info` parts carry their real content

## The command line grows groups

`./spectro web` used to start a server the moment you typed it. A bare face
invocation that fires a process is a face you cannot ask questions of, so it
now reports where the server would live, whether one is running, and the eight
things you can do to it — and starts no server.

- `dev` is the old foreground Gradle run, now named; `start` backgrounds the
  packaged jar, health-waits and opens the browser
- every verb but `dev` execs `./spectro-serve`, which owns the pid file, the
  port file and the log. One lifecycle, one implementation.
- `spectro level` became reachable at all — it had shipped with the ladder, in
  Java, with tests, and the bash launcher had no arm for the word
- one `.env` contract for both launchers: values stop being cut at an inline
  hash, and an inherited variable stops being blanked

## Also in this release

- **session export** — JSONL out, the mirror of the import (card 95)
- **skills ride in the belly**: the repo skills travel inside the jar and seed
  `~/.spectro/skills` on first boot, absent-only, so your edits survive and
  your deletions stay deleted. Plus a settings manager for skills and MCP
  servers (card 90)
- the **Files tab follows the run** — auto-refresh on tool results, run end and
  workspace switches (card 89)
- **security**: the `/ws` handshake is fenced to local origins, closing
  cross-site WebSocket hijacking (card 92)

live-model frozen-facade check, which needs a paid key). tsc, eslint and

release check that trusts the fast green is checking nothing.
