# spectroscope 0.4.0

Released 2026-07-27. `dev.spectroscope:spectro-core:0.4.0` and
`dev.spectroscope:spectro-orchestrator:0.4.0` are on Maven Central; the CLI,
the server, the MCP notes server and the macOS desktop kit are attached below.

## Run a model locally, without a key

The built-in provider now offers a catalogue of five open models: Qwen3 1.7B,
4B and 8B, Qwen2.5 Coder 7B, and VibeThinker 3B. Qwen3 4B is the default.

- Each entry shows what the model is for, whether it can drive the agent's
  tools, and whether your machine has the memory and disk for it, checked
  before the download starts.
- Downloads come from each model's publisher and are verified by sha256 into
  `~/.spectro/models`.
- The four Qwen models call the file tools, the shell and subagents. Each
  model runs with its own context size, and switching models restarts the
  runtime.
- The desktop app bundles its own signed `llama-server`, so the local path
  needs nothing else installed: open the app, pick a model, run.
- Model weights are not bundled. Each catalogue entry links its licence and
  its source.

## Levels

A new install opens with the chat and adds surfaces as you use the ones you
already have, across seven levels from dark frame to deep field.

- You are asked once per install whether to grow into the product or open
  everything immediately. An install that already has sessions is never asked
  and never restricted.
- A closed surface shows what it is and what remains to open it, with a button
  that opens everything for good. Settings and the permission gate are always
  available.
- Each completed criterion links the session and event where it happened.
  Event links are plain addresses (`#/session/<id>@<n>`) that can be pasted
  and shared.
- The header carries a spectrum strip that gains a line per level.
- Settings offer three modes — levels, checklist, off — and a reset.
- `spectro level` prints the same information without a running server, and
  `spectro doctor` shows one line of it.
- Every criterion can be reached without a paid API key.

## Chat

- Your message is a flat bubble on the right; the answer is plain text on the
  left. Thinking and tool calls are single lines you can expand.
- Tool calls open on three views: structured, JSON and raw, each with a copy
  button.
- A disclosure menu sets how much is expanded (normal, extended, thinking
  only) and the reading width.
- An extended text feed shows the complete record.
- Every answer names the model that produced it and its start and end time.
  The trace has a model column.

## Command line

`./spectro web` is now a command group. Typed on its own it reports where the
server would run, whether one is running, and the available verbs, without
starting anything.

- `dev` runs the foreground Gradle server; `start` runs the packaged jar in
  the background, waits for health and opens the browser.
- Every verb except `dev` runs through `./spectro-serve`, which owns the pid
  file, the port file and the log.
- `spectro level` is available from the launcher.
- Both launchers read `.env` the same way: values are no longer cut at an
  inline `#`, and an inherited variable is no longer blanked.

## Also new

- Sessions can be exported as JSONL.
- The bundled skills install into `~/.spectro/skills` on first start; your
  edits and deletions are kept. Skills and MCP servers can be managed in
  settings.
- The Files tab refreshes itself on tool results, run end and workspace
  changes.
- The local runtime requires a key that is generated per launch.
- The WebSocket handshake accepts local origins only.

includes its own Java runtime.
