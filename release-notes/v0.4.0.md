# spectroscope 0.4.0

Released 2026-07-27. `dev.spectroscope:spectro-core:0.4.0` and
`dev.spectroscope:spectro-orchestrator:0.4.0` are on Maven Central; the CLI,
the server, the MCP notes server and the macOS desktop kit are attached below.

## Run a model locally without a key

The built-in provider now has a catalogue of five open models. Qwen3 4B is the
default.

| model | download | memory | licence |
|---|---|---|---|
| Qwen3 1.7B | 1.8 GB | 6 GB | apache-2.0 |
| Qwen3 4B (default) | 2.5 GB | 8 GB | apache-2.0 |
| Qwen2.5 Coder 7B | 4.7 GB | 12 GB | apache-2.0 |
| Qwen3 8B | 5.0 GB | 12 GB | apache-2.0 |
| VibeThinker 3B | 1.9 GB | 6 GB | see below |

- Each entry says what the model is for and whether it speaks the tool-call
  protocol. It also shows whether your machine has the memory and the disk for
  it, before you start the download.
- The four Qwen models speak the tool-call protocol, so the file tools, the
  shell and subagents are offered to them. VibeThinker does not, and is
  offered none.
- Four of the five download straight from the publisher. VibeThinker's GGUF is
  a community requantization by mradermacher, which the chooser states. All
  five are sha256-verified into `~/.spectro/models`.
- Each model runs with the context size the catalogue gives it, and switching
  models restarts the runtime.
- **VibeThinker 3B licence:** the GGUF is tagged MIT, but the model it
  descends from, Qwen2.5-Coder-3B, carries the Qwen Research License, which
  permits research and evaluation only. Check it yourself before commercial
  use.
- spectroscope does not bundle model weights.

The desktop app bundles its own signed `llama-server`, so it needs no other
software to run a model locally. The server jar and the CLI do not bundle it:
they need a `llama-server` on the PATH (`brew install llama.cpp`), and they
say so instead of failing at the end of a download.

## Levels

A new install opens with the chat and adds surfaces as you use the ones you
already have, across seven levels from dark frame to deep field.

- spectroscope asks once per install whether to unlock surfaces as you go or
  to open everything immediately. An install that already has sessions skips
  the question and stays unrestricted.
- A closed surface shows what it is and what remains to open it, with a button
  that opens everything for good. Settings and the permission gate are always
  available.
- Each completed criterion links the session and event where it happened.
  Event links are plain addresses (`#/session/<id>@<n>`) that you can paste
  and share.
- The header has a spectrum strip that gains a line per level.
- Settings have three modes (ladder, checklist, off) and a reset.
- `spectro level` prints the same information without a running server, and
  `spectro doctor` shows one line of it.
- You can reach every criterion that gates a level without a paid API key.

## Chat

- Your message is a flat bubble on the right; the answer is plain text on the
  left. Thinking and tool calls are single lines you can expand.
- Tool calls open on three views: structured, JSON and raw, with a button that
  copies the raw output.
- A disclosure menu sets how much is expanded (normal, extended, thinking
  only) and the reading width.
- An extended text feed shows the complete record.
- Answers from 0.4.0 onward name the model that produced them and their start
  and end time, and the trace has a model column. Sessions recorded earlier
  leave both blank.

## Command line

`./spectro web` is now a command group. Typed on its own it reports where the
server would run, whether one is running, and the available verbs, without
starting anything.

- `dev` runs the server in the foreground and holds the terminal; `start` runs
  the packaged jar in the background, waits for health and opens the browser.
  `stop`, `restart`, `status`, `logs`, `doctor` and `open` do what they say.
- `spectro level` now works from the `./spectro` script.
- A key containing a `#` is no longer cut short when read from `.env`, and a
  variable you already exported is no longer blanked by an empty entry there.

## Also new

- You can export a session as JSONL.
- The bundled skills install into `~/.spectro/skills` on first start. Later
  starts leave your edits and your deletions alone. You can manage skills and
  MCP servers in settings.
- The Files tab keeps up with the run on its own.
- The local model runtime is reachable only by spectroscope: it is started
  with a key generated for that launch, so another page open in your browser
  cannot talk to it.
- A page on another site can no longer open a WebSocket to your local
  spectroscope and drive it.

## Fixed

- Stop now ends a run in milliseconds rather than seconds, including in the
  middle of a long reasoning stream.
- The composer no longer locks while the agent works. What you type is queued
  and sent when the run ends.
- The local model process is shut down with the server instead of being left
  running.

Java 21 or newer. The desktop kit is macOS arm64, signed and notarized, and
includes its own Java runtime.
