# spectroscope 0.9.0

Released 2026-08-14, 42 merges after 0.8.0 — the largest cut so far, and the
first one that deliberately suspended the release cadence to carry two halves
of one line together: the agent can reach the web now, and you can watch it do
it. A real browser lives in the app, driven by the agent or by you, fenced,
recorded, and replayable. Research is taught now: a
shipped skill carries the method, and a role carries the skill. And the workspace turned into
panels you arrange instead of tabs you visit.

## A real browser you can watch

The agent gets seven browser tools, and every one of them acts on a browser
you can see. In the desktop app it is a native pane; in the web app it is the
same engine running beside the server, streamed into the page — picture, URL
bar, back and forward, a screenshot control. One browser per session, with its
own cookies and its own profile, gone when the session closes. What the agent
does in it, you watch live. What you do in it, the agent's record keeps apart
from its own actions — a replay never attributes your click to the model.

The browser respects the same network fence as every other tool: private
addresses, the tailnet and file:// are refused on every redirect hop, and the
refusal lands in the run as a sentence that names the rule. The fence holds no
matter who typed the address. While an agent call is driving the page, your
input waits — one sentence says so — instead of silently fighting the run.

Every browser run writes a replay file beside the session. Open an old run and
step through what the browser did, screenshots included. A browser change and
its replay path ship together in this house; a surface you could witness only
once would be against the point of the product.

The empty browser is not empty anymore either: it lists your launch
configurations with a play button each. Press one, the app under test starts,
and the browser opens on it.

## Research, taught rather than permitted

`web_search` now says which engine answers and why: a SearXNG instance you
run, a Tavily or Brave key, or — labeled plainly as best effort and last
resort — the keyless scrape. Exactly one tier answers, the settings page, the
doctor and the tool description all name the same one, and changing the
configuration reaches an open session's next call, not just the next restart.

On top of the tools sits a research skill in the shipped catalog and a
research role that carries it: query strategy, source triage, verify before
citing, when to escalate from a snippet to the full page. A worker child
cannot reach the web by construction; the research role can, through the same
permission gate as everything else.

## Panels instead of tabs

Terminal, files, agents, plan, context and the browser are separate panels
now. One panel takes the full height; a second splits the column; a third
opens a new column. Width belongs to the column, height to the pair, every
divider drags and answers to the keyboard, and the arrangement survives both a
reload and a window resize without reshuffling. Header icons toggle each panel
and a menu shows what is open. The terminal survives you looking elsewhere.

## MCP, honest end to end

A configured MCP server that starts and never answers used to hang `doctor`
forever. Now it is written off inside a bound the docs actually state, its
whole process tree is cleaned up — twice counted, so a launcher's child does
not escape during the goodbye — and a healthy server still gets a polite
shutdown: stdin closes first, signals come after. Every server row shows the
command it runs before you switch it on, entries can be disabled without
deleting them, and a screenshot returned by an MCP tool reaches the model as
an image instead of a wall of base64.

Headless runs mount MCP servers only when asked: a settings switch covers
`spectro run`, cron fires and fleet nodes; `--mcp` / `--no-mcp` overrides per
invocation. The flag's help text says what an unattended `auto` approves,
because a permission-shaped decision should not wear a convenience-shaped
name.

## The app stops hiding its own state

Hooks get a settings page that answers for the run in front of you: which
layer is in force, which it replaced, and what actually runs — and headless
runs now execute hooks at all, which they silently did not before. The
calibration panel names the web-search tier and the instance address. Settings
say which run a change reaches — immediately, next session, or headless only —
and the sentence is derived from the code, not written beside it. Skills moved
out of settings into their own place in the rail, where you can also install
them. A plus menu in the composer switches skills and MCP servers where your
hand already is.

The trace stopped lying in three places: a windowed live trace says "last
5000 of N · how many fell out", an import keeps every row, and the fleet room
no longer borrows another session's losses. Subagent exchanges land in the
session's LLM wire file, so the record of what the run cost is complete.

## Smaller, and worth having

- The sidebar is a quiet nav list: sessions scroll where the rows start, an
  options switch chooses a denser list, and the browser lives in the session,
  not in the rail.
- The trace builds after the chat has painted instead of beside it, and the
  list no longer jumps under a resting reader.
- Paste an image straight into the chat box.
- Desktop menus carry the product's real actions.
- Level-up notices dismiss on click and leave on their own.
- The empty states across the app now say what to do next, in both languages,
  in fewer words.

## Known limits

- The desktop kit is built and notarized per platform; the macOS dmg in this
  release is arm64. Linux gets an AppImage and a deb.
- The visible browser's subresource requests follow the page's own redirects;
  the fence judges navigations and top-level hops, and the docs say exactly
  where its writ ends.
- The web-face browser streams the server's own Chrome; a desktop pane, when
  attached, takes precedence — one browser per session means exactly one.
