# spectroscope 0.14.1

This release adds a fourth permission mode, extended. It works like auto and
also lets the agent read and write files outside the working folder. The rest
are fixes: the microphone menu stays inside the window, a model that cannot
think no longer fails when thinking is switched on, web search through a stock
SearXNG instance answers instead of failing, and the app finds `whisper-cli`
from Homebrew however it was started.

---

## First run

**Extended is a new permission mode.** The mode list under the composer now
reads ask, auto, readonly and extended. Extended approves every tool call
without asking, as auto does. The file tools view_file, read_file, list_dir,
write_file, edit_file, glob and grep may also reach paths outside the working
folder, given as an absolute path or as a relative path with `..`. It is meant
for a session opened on an inner folder of a larger project that sometimes has
to change a file one level up.

**A project folder cannot switch itself into extended.** Only the switch in the
app, your user settings (`~/.spectro/settings.json`) and the command line can
set it. A `.spectro/settings.json` or `settings.local.json` inside a project
that says `extended` loses that one key, and the app tells you it ignored it.
The same holds for the settings file in the folder the server was started from.
The other modes can still come from a project file, as before.

**Picked in the app, extended holds until the window reconnects.** A reload or
a reopened session starts again in the mode from your settings. To keep
extended, set it in your user settings.

**The command line knows extended too.** `spectro run --permissions extended`,
`spectro node --permissions extended` and a scheduled job with
`"permissions": "extended"` run with the same reach. A node started from the
web still runs in readonly, as before.

**The microphone menu opens to the left.** The device list under the
microphone's caret now hangs from the caret's right edge and grows to the left,
so it stays inside the window at every width, also beside docked panels. The
gear's menu at phone width is fixed the same way.

**A model that cannot think runs anyway.** With thinking switched on, ollama
used to refuse a model that cannot think, and the run ended with an error. The
app now asks ollama once which models think and sends no thinking request to one
that does not. If ollama still refuses, the request is sent once more without
it. On Anthropic, the older models that have no thinking control get no
thinking request either.

**A stock SearXNG instance answers the search.** SearXNG ships with its JSON
output switched off, so `web_search` through a fresh instance failed. The search
now reads the same instance's ordinary results page instead. The first time
this happens in a session in the app, the transcript says once how to switch on JSON in
the instance's `settings.yml`, which is faster and more exact. The search still
never hands your question to another provider.

**The app finds whisper-cli from Homebrew.** Started from the Dock or the
Finder, the app did not see programs in the Homebrew folders, so voice input
reported `whisper-cli` missing after `brew install whisper-cpp`. It now looks in
the same folders as its other tools, runs the binary it found, and names the
folders it searched when it finds nothing.

## Extended mode

Paths in extended still resolve through the file system's real path, so a link
is followed to where it points, and a link that points nowhere is refused. A
relative path still starts at the working folder.

What stays fenced in every mode: the file browser in the app, the host guard
that protects the app's own process, and `view_image`. In extended, the agent
also may not write a `.spectro/launch.json` or `.claude/launch.json` in any
folder, not only in the working folder.

The shell tool had no path fence before this release and has none now.

---

## Library API

No public member of the 0.14.0 API was removed, and no constant changed its
value. Code compiled against 0.14.0 still runs. `spectro-orchestrator` has no
change to its public API.

`PermissionBroker` gained `reachesOutsideTheWorkingDirectory()`, a default
method that returns false. A broker of your own needs no change, and its tools
stay inside the working folder.

`Tool.ToolContext` gained `reachOutside` as its ninth component. Its
eight-argument constructor from 0.14.0 is still there and sets it to false. A
record pattern that takes `ToolContext` apart must name nine components now,
and two contexts that differ only in `reachOutside` are no longer equal.

New: `SpectroConfig.PERMISSION_MODE_EXTENDED`, `SpectroConfig.knownPermissionModes()`,
`HeadlessRunner.withOutsideReach(boolean)`, `Job.EXTENDED` and `Job.PERMISSIONS`.
`ToolPath.locate(...)` returns the new record `ToolPath.Lookup`, which carries the
path it found and the folders it searched.

## Fixed

- **The microphone's device list left the window** to the right at every width.
- **The gear's menu left the window** by a few pixels at phone width.
- **A model without thinking failed** when thinking was on, with ollama's
  refusal as the error.
- **`web_search` failed on a stock SearXNG instance.**
- **Voice input did not find `whisper-cli`** when the app was started from the
  Dock or the Finder.

---

## Known limits

- **Extended reaches anything your user account can.** There is no list of
  folders it may not touch.
- **A search over the whole disk is not capped, and Stop does not end it.** In
  extended, `glob` or `grep` with a path of `/` walks every folder it can read.
  In a test with a pattern that matched nothing, both were still walking after
  120 seconds, and `grep` held 750 MB of memory by then. Point them at a
  folder.
- **The plus menu's side panel still leaves the window at phone width** and
  moves the page sideways when it opens.
- **The transcript does not say that a model cannot think.** The run answers
  without thinking and gives no sign of it.
- **`spectro run` does not print the SearXNG hint.** In the terminal, only the
  result header says that the results came from the HTML page.

## Getting it

The channels are the ones 0.14.0 shipped.

**Homebrew, on macOS.** `brew install --cask spectroscope/tap/spectroscope`
installs the signed and notarized desktop kit.

**The macOS disk image.** `spectroscope-0.14.1-arm64.dmg` on the release page,
also under the stable name `spectroscope-arm64.dmg`. Signed, notarized, and
carrying its own Java runtime and `llama-server`. Apple silicon only.

**apt, on Debian and Ubuntu.** The signed repository at
`https://apt.spectroscope.dev` serves the deb once this version enters the pool.
Check `apt policy spectroscope` before assuming `apt upgrade` carries you here.
x86_64 only. Without a keyboard, use `sudo DEBIAN_FRONTEND=noninteractive apt
install -y spectroscope`.

**The Linux kit.** `spectroscope-0.14.1-x86_64.AppImage` and
`spectroscope_0.14.1_amd64.deb` on the release page, built and smoke-tested on
Linux by this project's own CI. x86_64 only, not signed.

**The jar and the CLI.** `spectro-server-0.14.1.jar` and `spectro-0.14.1.zip`
run on any machine with Java 21.

**In your own code.**

```
dev.spectroscope:spectro-core:0.14.1
dev.spectroscope:spectro-orchestrator:0.14.1
```

If the coordinates answer 404 for you, the publish has not propagated yet.
